# Phase 18.2: jiib Rebrand - Context

**Gathered:** 2026-06-07
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the **user-facing** "Dinghy Display" brand with **"jiib"** across exactly four
surfaces, and nothing more:

1. **Launcher icon** — swap the Benchy line-art adaptive icon for the jiib sail mark.
2. **App label** — both `android:label="Dinghy Display"` occurrences in `AndroidManifest.xml`
   (application + activity) → `jiib`.
3. **Splash screen** — the centered `Text("Dinghy Display")` → the stacked icon+wordmark lockup.
4. **About screen** — the `SectionLabel("Dinghy Display")` → the jiib wordmark, plus a reworded
   tagline.

**Out of scope (hard boundary, locked by ROADMAP.md):** the repo name, the Java/Kotlin
package `works.mees.dinghy`, the `applicationId`, and every `Dinghy*` class/symbol name
(`DinghyApp`, `DinghyTheme`, `DinghyIcon`, `Theme.DinghyDisplay`, etc.) all stay UNCHANGED.
This is a brand swap on what the user sees, not a rename of the codebase. No new capabilities.

"jiib" is a play on **jib** (a triangular headsail) — the nautical lineage of "dinghy."
</domain>

<decisions>
## Implementation Decisions

### Launcher icon
- **D-01:** Keep the existing dark-navy `#141A24` static adaptive-icon **background** (same as
  today's Benchy icon and the app `bg` token). Swap only the foreground: Benchy line-art →
  the jiib sail mark (`img/jiib_icon.svg`), rendered **white** on the navy, identical treatment.
- **D-02:** Ship the **monochrome / themed-icon layer = the jiib mark itself** (mirrors today's
  Benchy-as-monochrome setup). This is the Material You hook: on Android 13+ with a supporting
  launcher and "Themed icons" enabled, the system ignores the navy background and tints this
  monochrome mark to the wallpaper palette. Everyone else (Android <13, Fire OS / Kindle,
  themed-icons off) gets the fixed navy+white static icon. No extra work beyond shipping the
  monochrome layer — the navy default protects the brand; Material You is automatic where present.
- **D-03:** The launcher mark stays **fixed white** (outside the theme system) — it is NOT
  theme-tinted like the in-app marks. Retain the **pre-API-26 vector fallback**
  (`mipmap-anydpi/ic_launcher.xml`) because `minSdk 23` (adaptive icons need API 26+); update it
  to the jiib mark too (navy box + white mark, no adaptive layering), parallel to the current
  Benchy fallback.

### In-app branding placement
- **D-04:** **Splash screen** → the **stacked icon+wordmark lockup** (`img/jiib_name_icon_stack.svg`):
  sail mark above the "jiib" wordmark, replacing the centered "Dinghy Display" text. Reason text
  and the recovery/status buttons stay exactly where they are below it. Splash is the app's front
  door / first-run trap screen — the full lockup is the strongest brand moment.
- **D-05:** **About screen** → the **wordmark only** (`img/jiib_name.svg`) in place of the
  `SectionLabel("Dinghy Display")` above the version row. The `SectionHeader("About")` stays;
  the stacked lockup would be redundant here (user just saw the launcher mark).

### Theme-tinting & asset conversion
- **D-06:** In-app marks (splash lockup + about wordmark) **tint to the accent/brand token
  (`t.accent`)** — NOT fixed white. This keeps them THEME-01 compliant (legible on dark, light,
  and custom themes) and gives the brand an accent-colored pop.
  - **⚠ Watch-item for planner/researcher:** `t.accent` on a **user-custom** theme could wash
    out or clash against `bg`. Consider a minimum-contrast floor or a graceful fallback
    (e.g. fall back to `t.text` when accent↔bg contrast is too low). Also note: on the splash
    the accent-tinted lockup will visually rhyme with the accent-intent recovery buttons
    (`Intent.Accent`) — cohesive, but the logo is less "set apart." Acceptable per owner; flag
    if it reads poorly on-device.
- **D-07:** **Flatten each in-app SVG to a single fill** when converting to VectorDrawable. The
  source SVGs use slightly different off-whites (`#F9F9F9`/`#F8F8F8`/`#F7F7F7`) across paths plus
  `<circle>` elements — collapse all to one tintable fill (a tint applies one color over the whole
  drawable). Visually identical (all ~white already). `<circle>` elements convert to path data.
- **D-08:** **SVG→VectorDrawable conversion is required for all three assets** — Android cannot
  render raw SVG. `jiib_icon.svg` (launcher, fixed white), `jiib_name.svg` (about wordmark,
  tintable), `jiib_name_icon_stack.svg` (splash lockup, tintable). Use Android Studio's vector
  asset import or `svg2vectordrawable`; verify path/circle fidelity after conversion.

### Label & copy
- **D-09:** App label string = **`jiib`** (all-lowercase, matches the wordmark). Replaces both
  `android:label` occurrences in `AndroidManifest.xml`. Route through `stringResource` per the
  preview-first / tokenized convention (`docs/ui_design/PREVIEW_AND_TOKENS.md`) — i.e. an
  `app_name`/label string resource, not a hardcoded manifest literal where avoidable.
- **D-10:** About **functional tagline kept**: "A direct Moonraker touchscreen for Klipper."
- **D-11:** Add an About **jib-explainer note** beneath it (the reason the app is named jiib).
  Locked exact copy (attribute the quote to Wikipedia in the string):
  > *jiib — "a triangular sail that sets ahead of the foremast … a jib's most crucial function
  > is increasing performance and overall stability."* So is this.

  Leads with the part of the definition that establishes "it's a sail" (so the name explains
  itself), then lands the parallel. Render via `stringResource`.

### Claude's Discretion
- Exact VectorDrawable sizing/scaling of the lockup on splash and the wordmark on About (respect
  the FFG grammar and `fsSp` scale conventions; don't hardcode px — `docs/ui_design/LAYOUT.md`).
- The tagline note's typography (font/size/secondary color) — follow About's existing
  `Text(... t.text3, fsSp(15f) ...)` description treatment.
- Whether the contrast-floor fallback for D-06 is implemented now or left as a documented
  known-limitation — planner's call based on effort, but the watch-item must be addressed or
  explicitly deferred, not silently dropped.
</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **Current launcher icon set** (`mipmap-anydpi-v26` + `mipmap-anydpi` + `drawable/ic_launcher_foreground.xml`):
  pure-vector, no PNG densities — exact template to mirror for jiib (background/foreground/monochrome
  layering already wired, including the pre-26 vector fallback for minSdk 23). Swap the mark, keep the structure.
- **`LocalTokens.current` + `t.accent`/`t.text`/`t.bg`**: the in-app theme token surface every screen
  already uses; the tinted VectorDrawables consume `t.accent` the same way text colors are pulled.
- **`fsSp(baseSp, t.fs)`** scale (see [[dinghy-font-sizes-too-small]]) + `Geist`/`GeistMono` families —
  for the About tagline note typography.

### Established Patterns
- **Splash** (`SplashScreen.kt`) renders brand as a centered `Text` inside `ScreenScaffold { field = ... }`
  with `gutter` omitted (hard-override surface). The lockup `Image`/`Icon` drops into that same Column,
  above the existing reason `Text` + recovery `Row`.
- **About** (`AboutScreen.kt`) uses `SectionHeader`/`SectionLabel`/`InfoRow` helpers in a scrollable
  Field column; the wordmark replaces the `SectionLabel("Dinghy Display")` call, tagline note slots
  under the existing description `Text`.
- Icon background is a color resource (`@color/ic_launcher_background = #141A24`) — reuse as-is.

### Integration Points
- VectorDrawables tinted via `t.accent` need to be Compose-consumable — render with
  `painterResource(...)` + `colorFilter`/`tint`, or as a tinted `Image`. Match how existing
  `DinghyIcon`/Compose icon rendering applies token color so the brand mark tints identically.
- Themed-icon (`<monochrome>`) layer only consulted by API 33+ launchers with themed-icons on —
  verify the static navy icon renders correctly on the floor device (LineageOS 18.1 / API 30, `flox`)
  where the monochrome path is NOT exercised.
</code_context>

<specifics>
## Specific Ideas

- Brand name **"jiib"** is intentionally all-lowercase and is a pun on **jib** (a headsail) — the
  About note must make this legible to users via the Wikipedia-sourced definition (D-11). Keep the
  pun tasteful/explanatory, not jokey.
- The sail-mark identity is the through-line: it appears as the launcher icon, the Material You
  monochrome layer, and the top of the splash lockup — one silhouette everywhere.
- Owner explicitly fine with navy "for now" as the brand background but values that capable phones
  pick up Material You via the monochrome layer (D-02) — the rebrand should not foreclose that.
</specifics>

<deferred>
## Deferred Ideas

- **Brand-background recolor** (replacing navy `#141A24` with a dedicated jiib brand color on the
  launcher) — owner is "fine with navy for now." Revisit only if a deliberate brand-color pass is
  wanted later; not this phase.
- **Reworking the in-app accent contrast system** for custom themes beyond the D-06 watch-item — if
  the accent-tint contrast problem proves systemic, it's a theming-system concern, not a rebrand one.

None of these block the phase.
</deferred>
