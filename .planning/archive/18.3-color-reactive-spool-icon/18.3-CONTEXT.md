# Phase 18.3: Color-Reactive Spool Icon - Context

**Gathered:** 2026-06-07
**Status:** Ready for planning

<domain>
## Phase Boundary

Author a genuinely-custom **spool glyph** (Material Symbols has no filament-spool icon) to replace the
`database` ligature placeholder used for `DinghyIcons.LauncherSpool`, and make it **color-reactive** —
the wound-filament portion is tinted by the **loaded filament's actual color**, a documented exception
to the tokens-only theming law. Ships a sensible empty/no-color fallback and stays legible across
dark + light + custom themes.

**In scope:** the custom vector glyph; filament-only color reactivity on the existing spool-icon
surfaces (+ the App Drawer Spool tile + SpoolScreen); color sourcing/precedence; keyline legibility;
documenting the THEME-01/token carve-out.

**Out of scope:** any NEW spool/status surface that doesn't exist today (e.g. a dedicated "print-status
spool line" — the glyph only goes where a spool icon/tile already lives, plus the SpoolScreen additions
agreed below); per-tool multi-extruder color rendering (index `[0]` only for v1); reacting to the
printer's Mainsail/Fluidd *web-UI* theme color (that's a different concept — see canonical refs note).

</domain>

<decisions>
## Implementation Decisions

### Glyph Design
- **D-01:** Author a **custom side-view spool** VectorDrawable following the existing printer-domain
  convention (`res/drawable/nozzle.xml`, `heat_bed.xml`: stroke-led white paths, ~96×96 viewBox,
  Compose tints at runtime). It has **two distinct regions**: (a) the spool **body/flanges** and
  (b) the **wound-filament band** between the flanges. Replaces `LauncherSpool`'s `database` ligature —
  flip `DinghyIcons.kt:57` from `IconRef.Ligature("database")` → `IconRef.Drawable(R.drawable.<spool>)`.
- **D-02 (filament-only tint):** ONLY the filament band takes the filament color. The spool body/flanges
  stay a **neutral role token** (`--text`/`--text2` per surface). The body is *not* color-reactive.
- **D-03 (no-color fallback = empty spool):** When no filament/color is known, the spool body draws
  (neutral token) but the **band is omitted entirely** — an *empty spool*. This is the universal
  fallback on EVERY surface (replaces "tint the whole glyph with a dead token"). Owner's framing:
  *"empty, spool is drawn, filament is not."*
- **D-04 (multi-color = two-stop gradient):** Multi-color filament (Spoolman `multi_color_hexes` /
  `colorSwatches`) renders as a **two-stop linear gradient** across the first two swatches, painted on
  the band. ⚠ This must be a **runtime gradient brush** (filament colors are dynamic data) — NOT a
  static `<gradient>` baked into the VectorDrawable XML. **Key research question:** the rendering seam
  for a runtime gradient on a vector band (Compose `Canvas` + `Brush.linearGradient` over a `Path`, vs.
  a token-tinted body drawable composited with a Compose-drawn gradient band). A solid single color is
  just a flat fill of the same band region.
- **D-05 (true color + neutral keyline):** Render the **exact filament hex** — never clamp/distort it.
  Give the band a **thin neutral (token) keyline** so its edge reads against any background even when
  the fill ≈ surface (white PLA on light theme, black on dark). Honors the "filament color is DATA, not
  chrome" carve-out. The `brandTint` WCAG-clamp was explicitly **considered and rejected** for the band
  (it would lie about the color); it remains correct only for brand chrome.

### Surfaces (all color-reactive; empty-spool when no color)
- **D-06:** Five surfaces use the new glyph:
  1. **Standby launcher tile** — `PrintStatusScreen.kt` (~:1118), currently `LauncherSpool`/`--text2`.
  2. **App Drawer Spool tile** — `AppDrawer.kt` `DRAWER_TILES`. ⚠ Integration wrinkle: drawer tiles
     render from a `symbol: String` (`DrawerTileSpec`), NOT a `DinghyIcon` — a custom reactive glyph
     needs a different render path than the ligature-string tiles. Capability-gated by `spoolEnabled`
     (`AppContainer.spoolmanPresent`).
  3. **Mid-print shortcut row** — `PrintStatusScreen.kt` (~:1212).
  4. **SpoolScreen empty-state** — **SWAP** the generic `Inventory` (`inventory_2`) box at
     `SpoolScreen.kt:323` → the new (empty) spool glyph.
  5. **SpoolScreen detail pane** — add a reactive spool glyph tinted by the **selected** spool's color.

### Color Source & Precedence
- **D-07 (loaded-context surfaces — launcher tile, drawer tile, mid-print shortcut):**
  **Spoolman active-spool `colorHex` FIRST → gcode `filament_colors[0]` FALLBACK → empty spool.**
  Spoolman wins on disagreement (it's the user-tracked physical truth; gcode is sliced intent and
  covers no-Spoolman users mid-print). Seam already present: `PrintStatusScreen` collects
  `container.activeSpool` and resolves `spoolDetail` (`SpoolmanSpool`, carries `filament.colorHex`)
  for the active-spool card (`:155-157`).
- **D-08 (SpoolScreen detail):** uses the **tapped spool's own** `colorHex` directly (not the active
  spool). The detail pane already has `spool.filament` in hand.
- **D-09 (multi-tool):** use index `[0]` / the first loaded spool for v1 (both target printers are
  single-extruder; a small icon can't show N colors). Per-tool color = deferred future enhancement.

### Documentation (SC3 — THEME-01 exception)
- **D-10:** Extend the **existing** token carve-out rather than inventing a new one. Update
  `docs/ui_design/THEMING.md` ("Carve-out: macro-authored PromptMarkup author-hex (D-03)") and the
  `docs/ui_design/CLAUDE.md` "Token carve-out" bullet to **explicitly sanction the color-reactive spool
  glyph** as a second instance of the same "filament color is DATA, not chrome" exception. (The
  CLAUDE.md bullet ALREADY names "a Spoolman spool's filament color" as the precedent — this phase makes
  that precedent literal.) Scope the carve-out to the filament BAND only; the spool body, keyline, and
  all surrounding chrome stay token-routed.

### Claude's Discretion
- Multi-tool index `[0]` (D-09).
- Exact spool silhouette proportions, viewBox, keyline stroke weight, and gradient direction — author to
  taste within the agreed grammar (side-view, flanges neutral, band reactive).
- **Watch-item:** if the two-stop gradient (D-04) doesn't read at launcher-tile size, fall back to the
  dominant/first swatch as a flat fill for the small surfaces and keep the gradient only on the larger
  SpoolScreen icon. Not a hard decision — verify on-device.

</decisions>

## Existing Code Insights

### Reusable Assets
- **Tint override seam:** `DinghyIconView(tint = …)` already accepts any `Color` (defaults to a token).
  Solid-color band reactivity needs no API change; a runtime *gradient* band does (D-04).
- **Filament color, already resolved:** `PrintStatusScreen` already collects `container.activeSpool` and
  resolves the full `SpoolmanSpool`/`spoolDetail` (with `filament.colorHex`) for the active-spool card —
  reuse it for the launcher tile + shortcut, no new fetch.
- **Normalization:** `SpoolmanModels.normalizeColorHex()` + `colorSwatches`/`multiColorHexes` cover
  parsing, casing, and multi-color splitting (D-04/D-08).
- **gcode fallback:** `FilePreviewMetadata.filamentColors` already parsed from `server.files.metadata`.
- **Drawable convention:** `nozzle.xml`/`heat_bed.xml` are the template for the new vector.

### Established Patterns
- **Icon-source policy:** custom drawables only for printer-domain glyphs Material Symbols lacks — spool
  is explicitly sanctioned (`docs/ui_design/CLAUDE.md`). `DinghyIcons.all` + the uniqueness/drift tests
  must be kept in sync when the entry flips to `Drawable`.
- **Token carve-out precedent:** `PromptMarkupText` author-hex is the existing "raw color = content
  data" exception; this phase is the second instance (D-10).

### Integration Points
- `DinghyIcons.LauncherSpool` (registry) — the single flip point.
- `AppDrawer.DRAWER_TILES` — drawer Spool tile renders via `symbol: String`, NOT `DinghyIcon`; needs a
  reactive render path (the one real structural wrinkle of the phase).
- `SpoolScreen` empty-state swap + detail-pane addition.
- The `brandTint`/keyline + DinghyIcons drift tests are the regression surface (SC6).

</code_context>

<specifics>
## Specific Ideas

- Owner picked the **richer illustration** over the simple options: filament-ONLY tint (not whole-glyph)
  and a two-stop GRADIENT for multi-color (not a flat dominant swatch). Author for that fidelity.
- The fallback should read as an honest *empty spool*, not a recolored placeholder — the appearance of
  the band IS the "filament loaded" signal.
- Legibility is solved by **framing, not distortion** — keep the true hex, add a keyline.

</specifics>

<deferred>
## Deferred Ideas

- **Per-tool / multi-extruder color** (band reflecting tools `[1..n]`, not just `[0]`) — future
  enhancement; both target printers are single-extruder.
- **Dimmed last-known color** on idle (instead of empty spool) — considered and rejected (risks showing
  a stale color after an unload); empty spool is the chosen fallback.

None of the above is in scope for 18.3. Discussion otherwise stayed within phase scope.
