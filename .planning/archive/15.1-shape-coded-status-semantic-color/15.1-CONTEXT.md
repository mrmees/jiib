<domain>
## Phase Boundary

**Make color *safe and semantic*.** Phase 15 shipped the generative ENGINE (seed → palette →
cached `pool[]`/`directional`/status tokens). This phase decides **what the colors MEAN** and adds
the non-color safety layer on top — built before Home (Phase 16) so every later surface inherits it.

**IN scope:**
1. **Shape-coded status** — a consistent shape-icon vocabulary (octagon = stop / triangle =
   caution / circle = go) so color is never the *only* safety cue (COLOR-SYSTEM.md §7, §D).
2. **Status color behavior** — make the 3 status slots user-editable; confirm the three palette-mode
   renderings (Colorful pool-by-warmth / Simple mono / High-Contrast forced RYG).
3. **The N-series color rule** — the canonical, mode-aware "distinguishable sequence" that any
   multi-line graph / colored list draws from, wrapping infinitely (no cap).
4. **App-wide pool→role semantic assignment** — which generated color means what, everywhere
   (folds the `pool-color-semantic-assignment` todo).
5. **Color-doctrine pick-ones** — D-5 (back-button), D-6 (bed-mesh ramp), D-8 (force-move).
6. **Reconcile `docs/ui_design/THEMING.md`** against the COLOR-SYSTEM.md model (rewrite in-repo).

**OUT of scope → Phase 15.2 (Theme Conformance Sweep & Settings IA):**
- The heavy token-purity / button-intent / FFG / ≥64px / `fsSp` / dark-light-custom audit of every
  existing surface.
- The Settings-vs-Devices boundary / "printer settings page" reframe.
- (Light final re-sweep of late surfaces 16–20 still folds into Ship / Phase 21.)

<decisions>
## Implementation Decisions

### Shape-coded status (Area A)
- **D-01:** **Minimal shape-icon set — NOT shaped containers.** Keep every element's current form
  (rect buttons, round dots, plain letters); add a consistent **octagon-✕ / triangle-! / circle-✓**
  glyph next to the status signal. Avoids awkward octagonal touch targets and is Adreno-320-cheap
  (static, no animation). **Load-bearing requirement:** the three glyphs MUST read as genuinely
  distinct *silhouettes* (octagon vs triangle vs circle) so the SHAPE — not just the inner mark —
  carries meaning at a glance and in grayscale. Shape is the safety mechanism; this is not garnish.
- **D-02:** **Coverage = safety-critical only (stop + caution).** Only `stop` (octagon-✕) and
  `caution` (triangle-!) carry a shape-icon, everywhere status appears (Print-Status dot, Move
  homed/unhomed axis letters + force-move, Stop/e-stop/power buttons, console severity). Benign
  `go`/ok/homed states stay **color-only** (no circle glyph) to keep a normal print quiet — the
  fill/shape salience ladder: calm state quiet, attention states pop. *(This adjusts the spec's
  "go = circle" — go has no glyph in dinghy; only stop/caution do.)*

### Status color behavior & palette modes (Area B)
- **D-03:** **Status colors are FULLY user-editable, no guard** (resolves Phase-15 D-09 open item).
  Same per-slot override mechanism as data-pool slots — extend `poolOverrides` to the 3 status slots;
  the Theme Editor exposes them. A user *can* make `stop` green; that's acceptable because shape +
  icon + position carry 100% of safety meaning (Area A). Consistent with Phase-15 "no arbitrary
  limits." The editor swatch-strip preview shows the status colors **with their shapes**.
- **D-04:** **Three palette-mode renderings (spec-locked, confirmed):** Colorful = status from pool
  slots ordered by warmth (not fixed RYG); **High-Contrast force-overrides status to stoplight RYG**
  regardless of user overrides (the accessibility / CVD escape hatch); Simple = status collapses to
  text color (shape + position still carry it).

### The N-series color rule (Area D — the load-bearing concept)
- **D-05:** **Accent always LEADS the distinguishable color sequence — in every mode AND for
  canonical named sets.** Series fill an ordered sequence then **wrap infinitely (no cap)**:
  | Mode | Sequence (then wrap) |
  |---|---|
  | **Colorful** | `accent, pool[0], pool[1], pool[2], … pool[N]` |
  | **Simple** | `accent, text` (alternating; beyond 2, identity rides on label/dash/marker) |
  | **High-Contrast** | `accent, stop, caution, go, text` |
  - **Line-1 = accent in all three modes** → the first/lead series keeps identity across mode switch.
  - **Colorful never uses status colors for data** (data wraps within `accent + pool`; a normal trace
    is never stop-red — cleaner than the spec's overflow-into-status-slots).
  - **High-Contrast deliberately presses RYG status colors into data duty** (pool has collapsed; safe
    because actual status signals carry shape-icons + fixed position, so a red *line* ≠ the octagon
    e-stop).
- **D-06:** **Accent leads canonical sets too** (chosen over pinning them to the pool). For the temp
  graph: **nozzle = accent, bed = `pool[0]`, chamber = `pool[1]`; the nozzle readout matches (= accent).**
  Rationale (owner): in a whitespace-heavy minimal UI the personalization (accent) is easy to lose, so
  the most-watched live channel should wear it — keep the user's accent **prominent on every screen.**
  Owner explicitly accepts the trade (the nozzle trace/readout now moves on reseed and shares the
  accent hue with the primary action).
  > ⚠ **SUPERSEDES Phase-15 D-2 / D-13** (which set nozzle = `pool[0]` / `temperature`). The planner
  > MUST update the locked Phase-15 wiring, not just add to it.
- **D-07:** **Directional reconception** (consequence of D-06): `directional.temperature → accent`,
  `directional.xy → pool[0]`, `directional.z → pool[1]`. Dual-tag preserved, shifted down one: **bed
  shares xy's `pool[0]`, chamber shares z's `pool[1]`** (they never co-occur on screen, so identity
  never collides in view — owner accepted dual-tagging).
- **D-08:** **Move screen unchanged in spirit** (accent-leads is for *data displays*, not control
  screens): Home stays **accent** (the primary action, Part II §A gate 3); jog-pad = `directional.xy`
  = `pool[0]`; Z-row = `directional.z` = `pool[1]`.
- **D-09:** **No user-facing item cap — wrap and repeat** (carries Phase-15 D-14). `maxItems` is an
  internal generator boundary only; the N-series rule (D-05) defines what happens past the pool.

### Color-doctrine pick-ones (Area C)
- **D-10:** **D-5 → Back button = NEUTRAL / outline, app-wide.** By the spec's own earns-color
  grammar (Part II §A gate 4) plain navigation carries no role-meaning → neutral. Resolves the
  green-vs-red inconsistency by spending *no* safety color on nav. **PLUS:** the Back button's
  **gutter LOCATION must be consistent app-wide** — right-aligned (centered also acceptable), never
  varying screen to screen. *(The position-consistency rule is a layout requirement for the planner.)*
- **D-11:** **D-6 → Bed-mesh = dedicated perceptually-uniform OKLCH sequential ramp**, kept OFF pure
  red/green (spec §11; sequential data is its own sub-system). Fixes "red-for-high implies this spot
  FAILED" when it's only a tall spot. Replaces the current `accent→neutral→red` sRGB lerp in
  `render/BedMeshHeatmapView.kt`.
- **D-12:** **D-8 → Force-move = green-lock (safe) / red-open (armed)** per the README, with the lock
  **open/closed shape** as the redundant non-color signal (fits the shape doctrine). Resolves the
  prose-vs-amber-prototype mismatch.

### THEMING.md reconciliation (Area D)

  source-of-truth. Downstream agents read `docs/ui_design/` reliably; they won't read a sibling repo.

<specifics>
## Specific Ideas

- **"Keep the user's accent prominent on every screen."** (Owner.) The driving principle behind D-06
  — the minimal/whitespace motif risks washing out personalization, so the lead data channel wears
  the accent. This overrides the spec's "data ≠ accent" rule on purpose.
- **The N-series collapse model** (Owner, verbatim intent): three color sources — accent, text, pool —
  combine and "collapse onto duplicate colors" in Simple/High-Contrast; accent + pool carry
  arbitrarily large data sets in Colorful. Captured as D-05.
- **Shape glyphs must be distinct silhouettes**, not just distinct icons — the shape is what survives
  CVD/grayscale/a-glance (D-01).
- **Back-button position consistency** (Owner) — same gutter slot app-wide (D-10).

</specifics>
