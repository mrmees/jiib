## Design-System Mode: C6-Exempt Settings Cluster

This phase is governed by **C6** (THEMING.md / LAYOUT.md), the documented exemption for
settings-class surfaces:

- **C6 exemption applies to all 6 rebuilt screens + the new System page.** The ≥64dp touch-floor
  and the U-based minimum row height are **suspended** for these screens. Dense rows (≈10dp
  vertical padding each side) are the target.
- **Print-control surfaces (WaterfallHome, PrintStatus) keep the ≥64dp floor.** C6 does not
  relax them. The new System-page rows on WaterfallHome's idle list are also **not** C6 — they
  are normal U-sized rows that happen to link to C6 screens.
- **The Phase-23 component kit is still used** — `ListRow`, `FootButtonBar`, `DetailCard` — but
  with `dense = true` (sub-1U height, tighter padding). One visual family; config screens just
  run denser.
- **UAT-1..UAT-5 apply to WaterfallHome changes** (the new idle-list rows, the System shortcut
  in the printing grid) because those surfaces are NOT C6-exempt.

## Spacing Scale

This is an Android/Compose project. Spacing is expressed in `dp`, not CSS `px`, but both map
to the same 8-point scale at standard density (mdpi). The unit `U` governs all non-C6 rows.

| Token | Value (dp) | Usage in this phase |
|-------|------------|---------------------|
| xs | 4 dp | Inline icon-to-label gaps; dense row intra-content gaps |
| sm | 8 dp | Dense C6 row vertical padding (each side ≈ 10dp — see Dense Row section) |
| md | 16 dp | Standard horizontal content padding inside rows |
| lg | 24 dp | Section gaps in About/Settings one-page layouts |
| xl | 32 dp | System page Focus vertical padding |
| 2xl | 48 dp | Page-level top/bottom padding on SysInfo when scrolling freely |
| 3xl | 64 dp | Not used this phase |

**C6 dense row target:** `10.dp` vertical padding top+bottom (≈ 20dp total per row vs standard
1U ≈ 44–72dp). Implemented as `dense = true` flag on `ListRow` or equivalent overload.

**Exceptions:**
- System page Focus strip: capped at **20% of screen HEIGHT in portrait / 40% of WIDTH in
  landscape** (D-02) — ratio-only, not a fixed dp value.
- FootButtonBar on Printers screen = 1U (standard), not dense — it is a primary action row.
- Floating e-stop = 1U × 1U square (same as all other screens, UAT-5).
- WaterfallHome idle-list new rows (Temperature/Console/Fine-Tune) = 1U (standard U rows, not C6).

## Typography

All sizes expressed in **sp before `fsSp` scaling**. Every size goes through `fsSp(baseSp, t.fs)`
at render time — never a bare `.sp` value.

| Role | Base Size (sp) | Weight | Line Height | Font | Notes |
|------|---------------|--------|-------------|------|-------|
| Dense row label | 17 sp | 400 (regular) | 1.3 | Geist | Primary text in C6 dense rows |
| Dense row sublabel | 15 sp | 400 (regular) | 1.3 | Geist | Secondary / subtitle in dense rows (floor at 15sp, D-10) |
| Section title / Focus header | 20 sp | 600 (semibold) | 1.2 | Geist | System page brand lockup label, Printers section headings |
| App version / tabular data | 15 sp | 400 (regular) | 1.0 | Geist Mono | Version string, host:port, IP addresses, numeric fields |
| Focus identity headline | 22 sp | 600 (semibold) | 1.2 | Geist | "jiib" wordmark in System page Focus strip |
| Foot button label | 17 sp | 600 (semibold) | 1.0 | Geist | FootButtonBar button labels (standard rows) |

**Hard floor: 15sp** — no text in any surface rebuilt this phase may drop below 15sp at base
size (D-10). The old EX(set) 13sp Material-label exemption is dead; the dense restyle replaces
those labels.

**fsSp scale:** `S ≈ 1.0 × base`, `M ≈ 1.15 × base`, `L ≈ 1.32 × base`. M is the default
(larger default, per THEMING.md). OS `fontScale` is pinned to `1f` at the Compose root; `--fs`
is the sole authority.

**Source:** CLAUDE.md recurring lesson "fonts get picked too small" + D-10 + THEMING.md `--fs`.

## Color

All colors reference **semantic role tokens from `ThemeTokens`** — never raw `Color(0xFF…)` in

| Role | Token | 60/30/10 Slot | Usage in this phase |

| Stop (destructive) | `t.stop` / `t.stopSoft` | semantic | Delete printer foot button; Delete mode armed state; Power stub row label+icon; ConfirmGuard destructive button; FloatingEStop |
| Caution | `t.heat` / `t.heatSoft` | semantic | Caution state on theme editor status-slot; Reset-to-default actions |
| Neutral | `t.text` on `t.outline` | semantic | Back foot button; plain navigation; inactive dense rows |
| Outline | `t.outline` (1.5dp) | structural | All dense ListRow borders; dense TokenTextField border |
| Text primary | `t.text` | text | All labels at full weight |
| Text secondary | `t.text2` | text | Sublabels, captions, muted helper text |

**Accent reserved for (explicit):**
1. The "Add Printer" foot button (`Intent.Accent`)
2. Selected idle-list row on WaterfallHome (accentSoft fill, accentLine border)
3. Active filter/sort option tile background (`t.accentSoft`) in SortFilterControlRow
4. Color picker: active slot's ring/border in ThemeEditorScreen (`t.accentLine`)
5. System page row tap ripple (brief touch feedback)

**Button intent map for this phase (by safety of action):**

| Action | Intent | Token | Rationale |
|--------|--------|-------|-----------|
| Add Printer | Accent | `t.accent` | Expected physical command — ordinary connection add |
| Edit Printer (mode toggle) | Neutral | `t.text` on `t.outline` | Mode arm, no immediate printer state change |
| Delete Printer (mode toggle armed) | Stop (filled) | `t.stop` fill | Armed dangerous mode — C4 rule (filled when armed) |

| Back | Neutral | `t.text` on `t.outline` | Plain navigation, D-10 |

| Theme "Apply" / Save | Go | `t.go` | Safe commit |
| Reset to default in Theme editor | Caution | `t.heat` | Undo/unexpected revert — "reset" earns caution per sketch-findings |

### Printers Screen (D-13, D-15)

**Grammar:** Focus | Field | FootButtonBar (no gutter). `ScreenScaffold(gutter = null)`.

**Focus:** Active printer `DetailCard` — filled `t.surface`, corner `t.rCard` (22dp).
  - Name (Geist, 20sp semibold)
  - `host:port` (Geist Mono, 15sp)
  - Color-coded connection state chip (accent = connected, heat = connecting, stop = error)
  - Klippy state label (Geist, 15sp, `t.text2`)
  - UAT-4: FloatingEStop top-left reserved when printing

**Field (portrait below Focus, landscape right):**
  - Dense `ListBlock` of printer profile `ListRow` items
  - Active printer row: `accentSoft` fill, `accentLine` border (selected state)
  - Inactive rows: transparent fill, `t.outline` (1.5dp) — content convention
  - Row anatomy: `[colored-dot]` · `[printer name]` · `[host:port Geist Mono]` + `Spacer(weight)` + `[Edit/Delete mode indicator if armed]`
  - Tap in normal mode: switch active printer
  - Tap in Edit mode: open inline densified connection editor form
  - Tap in Delete mode: show `ConfirmGuard` (destructive)

**Mode-toggle states (D-13):**
  - **Normal:** all rows switch on tap; Edit+Delete foot buttons show normal intent
  - **Edit armed:** Edit foot button filled/highlighted (no safety color — neutral mode); row tap opens editor
  - **Delete armed:** Delete foot button filled with `t.stop` (C4 rule — armed dangerous mode = filled stop)
    Row tap triggers `ConfirmGuard` (destructive red)
  - **Disarm:** tap the armed toggle again, or press Back

**Inline connection editor (Edit mode):**
  - Densified `TokenTextField` fields: Host (text), Port (numeric keyboard), API key (text, masked)
  - Save = Go intent (`t.go`); Cancel = Neutral

**FootButtonBar (D-15):** 4 buttons, equal `weight(1f)`:

| Button | Intent | Icon | Notes |
|--------|--------|------|-------|
| Add | Accent | `DinghyIcons.AddPrinter` (owner to confirm glyph if not yet registered — check DinghyIcons) | Always present |
| Edit | Neutral | `DinghyIcons.Edit` (existing, `edit` ligature if registered) | Mode toggle; armed = filled neutral |
| Delete | Stop | `DinghyIcons.Delete` (existing, `delete` ligature if registered) | Mode toggle; armed = filled stop |
| Back | Neutral | none (text only) | Disarms if a mode is active |

**Note:** Confirm glyph assignments for Add/Edit/Delete footer icons against DinghyIcons registry.
Any unregistered glyph = STOP AND ASK before building.

**Empty state (no printers):** Field shows a centered message:
"No printers configured. Tap Add to set up your first printer."
(Geist 17sp, `t.text2`). Foot: Add (Accent) + Back (Neutral).

## Interaction Contract

### Dense jiib ListRow variant (D-09)

Reusable kit extension. One visual family:

```
Content (browsable):   transparent fill, t.outline (1.5dp border)
Controls:              t.surface fill, t.outline border (or intent-line when active)
C6 dense modifier:     vertical padding 10dp top + 10dp bottom (instead of U-derived min)
```

The `dense = true` flag on `ListRow` suspends `heightIn(min = uDp)`. All other ListRow
conventions (leading icon, name start-aligned, value end-aligned with `Spacer(weight(1f))`) hold.

### Printers mode-toggle state machine

```
Normal mode
  └── Tap Edit → Edit mode armed (Edit button filled neutral)
  │     └── Tap a row → inline editor opens; tap Save/Cancel → back to Edit mode
  │     └── Tap Edit again / Back → Normal mode
  └── Tap Delete → Delete mode armed (Delete button filled stop, C4)
        └── Tap a row → ConfirmGuard (destructive); confirm → profile deleted; back to Normal
        └── Tap Delete again / Back → Normal mode

Normal mode: row tap → switch active printer (immediate; no confirmation)
```

### System page — direct tap nav (D-02)

No select-then-open. Each dense row navigates immediately on tap to its destination screen.
No selection state on System page rows (not a picker — tap = navigate).

### floatingEStop on System cluster screens (D-06)

Shell-level `FloatingEStop` appears on System page and all cluster sub-screens when printing
(D-06 makes the whole cluster print-reachable). Do NOT add `NavDest.System` or cluster screens
to `screenOwnsEstop`. The shell-level overlay fires on all destinations. UAT-4 applies: top-left
corner of the Focus/field reserved.

### TokenTextField dense variant (D-12)

Densified inline keyboard fields. System keyboard for text; numeric keyboard for port / numeric
fields. `dense = true` reduces internal vertical padding. Default behavior (non-dense) unchanged
for existing call sites.

### seedTheme reactive fix (D-19)

`ThemeEditorScreen.kt` line 117: replace `container.themePrefs.tupleFlow.firstOrNull()` in the
`LaunchedEffect` with a reactive collect (`collectAsStateWithLifecycle` or restructured effect).
The fix is in the editor's local seed effect, NOT in `AppContainer.seedTheme` (which is already
reactive — confirmed by RESEARCH.md).

### Dev cycler overlay drag (D-20)

`DevThemeCyclerOverlay.kt`: add a bare-surface `pointerInput` drag region on the outer container
so the panel relocates on drag. Chip tap events continue consuming their events (no bleed to
parent drag). Dev-only tool; no user-visible change.
