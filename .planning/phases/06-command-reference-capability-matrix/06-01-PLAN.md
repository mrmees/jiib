<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| docs JSON -> tests | Repository JSON sidecars are parsed by host tests and must fail closed on malformed data. |
| registry -> gcode builders | Registry-generated params eventually become printer commands; tests must prove builder wrapping, not template reinvention. |
| live capture evidence -> predicates | E5/E3 matrix evidence informs future gates but must not become shipped per-printer runtime data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-T | Tampering | docs/commands/catalog.json, printer-matrix.json | mitigate | Parse JSON in host tests and require registry IDs/predicates to match machine-readable sidecars per D-10. |
| T-06-01-S | Spoofing | CommandRegistry gcode wrappers | mitigate | Add byte-identical tests against `PrinterCommands.*`; registry must wrap proven builders per D-06/D-11. |
| T-06-01-D | Denial of Service | CommandDispatcher registry overload tests | mitigate | Preserve existing finite timeout tests, including 120s `printer.gcode.script` path and key removal in finally. |
| T-06-01-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs are planned in this phase. |
