<objective>
Stand up the Phase-2 Wave-0 foundation that every later plan in this phase depends on: the JVM unit-test
source set, the one new (test-only) catalog dependency, the static dev-config wiring (D-05), the public
data contracts (JSON-RPC envelopes, a typed connection/RPC error model, `PrinterState`, `Capabilities`),
and the golden+adversarial fixture corpus (plus a committed redacted fallback corpus) with a
`FakeWebSocket` harness.

Purpose: This is the testability bedrock. Without the `app/src/test/` source set, virtual-time coroutine
test lib, golden Ender-5-Plus frames, and the injectable fake socket, none of the behavioral plans
(reducers, JSON-RPC correlation, reconnect supervisor, auth) can be proven off-hardware. It also defines
the interface-first contracts (envelope types, typed errors, toolkit-agnostic immutable state/capabilities
models) the Wave-2/3 plans implement against, so executors receive the contracts rather than rediscovering
them. The error model and the `Syncing` connection state added in this pass close two review HIGH/MEDIUM
findings at the contract layer (typed errors instead of "any identify error → AuthRequired"; `Connected`
meaning "resynced + subscribed," not socket-open).

Output: A compiling `:app:testDebugUnitTest` source set; `kotlinx-coroutines-test` in the catalog and
wired as `testImplementation`; `BuildConfig` host/port/apiKey fields fed from gitignored `local.properties`
with placeholder defaults; `net/JsonRpc.kt`, `net/RpcError.kt`, `state/PrinterState.kt`, `state/Capabilities.kt`
contracts; the golden + adversarial fixture files AND a committed redacted fallback corpus; `FakeWebSocket`
+ `GoldenFixtures` loader; and a `FixtureSanityTest` that proves the harness and fixtures load.
</objective>
