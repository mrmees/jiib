<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Moonraker gcode stream → Dinghy parser | Untrusted macro-AUTHORED content (prompt lines) crosses here; the parser is the first hostile-input handler |
| Macro-authored image path → file load (downstream) | `prompt_image` path is attacker-controllable; must be allow-listed BEFORE any HTTP load (this phase enforces in the pure layer) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering/DoS | `parseAction` + sub-parsers | mitigate | Total functions: malformed/unknown/partial input → null or a degraded event, NEVER an exception (proven by PromptParseTest fuzz cases + the 26 fixtures). A garbage stream cannot wedge the parser. |
| T-12-02 | Information Disclosure | `isValidImagePath` | mitigate | Verbatim allow-list (`config/` prefix, forward slashes, no leading `/`/`~`, no empty/`.`/`..` segments, no `:` in a segment, no `\`) ported from image.ts and enforced in the PURE layer before any load (12-04 only ever receives a vetted `config/...` path; rejected → alt-text upstream). |
| T-12-03 | Tampering/Elevation | PromptMarkup parser | mitigate | Markup is parsed to a neutral AST only — never HTML/Pango/WebView; entities decoded exactly once and the output is never re-scanned as markup (so `&amp;lt;` → literal `&lt;`). No script/link/CSS surface exists in the AST. |
| T-12-04 | (no high threats) | — | accept | No crypto, no auth, no network in this plan (pure host-testable layer). |
</threat_model>
