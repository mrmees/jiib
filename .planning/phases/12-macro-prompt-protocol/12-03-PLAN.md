## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Live Moonraker gcode stream -> PromptEngine | Untrusted macro content arrives continuously; the engine must remain a non-starved independent subscriber and never wedge |
| Local lifecycle event (disconnect/process-death) -> other connected clients | A local teardown must NOT produce a cross-client side effect (prompt_end broadcast) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-09 | DoS (cross-client) | disconnect handling | mitigate | Disconnect/process-death runs the reducer's LOCAL disconnect path ONLY — never dispatches `prompt_end` (D-10). Unit-pinned with a recording dispatcher (zero dispatches on the disconnect edge); on-device-gated in 12-05. This prevents a local Dinghy event from closing the prompt on KlipperScreen/Mainsail/Fluidd. |
| T-12-10 | DoS (starvation) | gcode-stream subscription | mitigate | The engine subscribes the SAME un-throttled `store.gcodeResponses` SharedFlow as the Console as an INDEPENDENT collector (D-13); console filters never starve it. The parser is total (12-01) so a garbage stream cannot wedge the collect loop. |
| T-12-11 | Tampering (key collision) | dispatch key bookkeeping | mitigate | Stable `prompt:<epoch>:<index>` / `prompt:close` keys (Pitfall 4) keep the dispatcher busy/debounce guard correct across recomposition; epoch isolates a replaced prompt's keys from the prior one. |
| T-12-12 | Secrets in logs | dispatcher-Failure fold | accept (inherited) | The fold surfaces `DispatchEvent.Failure.message`, which `CommandDispatcher` already redacts (`?token=` removed, T-05-11-01). The engine never builds an error from raw exception text. |
