# Phase 9 — UI Design Contract

> Visual and interaction contract for the Calibration & Maintenance phase. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **THIS DOCUMENT IS SUBORDINATE TO `docs/ui_design/` (the canonical UI LAW).** It does NOT invent a new
> visual system — it applies the existing one (`CLAUDE.md`, `LAYOUT.md`, `THEMING.md`, `reference/hifi.css`)
> to the five new Calibration surfaces and records the per-screen Focus/Field/Gutter composition, intent-color
> assignments, copy, and reused primitives. The screws-tilt page is LOCKED by `docs/ui_design/images/05-screws-tilt.png`
> and reconciled by CONTEXT D-03/D-05; do NOT re-litigate it. All sizing is ratio-only (no hardcoded px) per
> LAYOUT.md ⚠ NON-NEGOTIABLE 3; all color routes through role tokens per THEMING.md.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** (native Android / Jetpack Compose + classic Views hybrid, ADR 0001 — shadcn is a web-only tool and is **not applicable**) |
| Preset | not applicable |
| Component library | Material 3 (Compose) skinned through `LocalTokens`; the project's own `designsystem/` primitives are the real component library |
| Icon library | **Material Symbols** (via `designsystem/MaterialSymbol.kt`, ligature names) — Outlined style. NEVER repeat a glyph on one screen (CLAUDE.md "never the same glyph twice"). |
| Font | **Geist** (`--ui`) for all UI text; **Geist Mono** (`--mono`) for ALL live numeric/tabular data (screw turns, Z position, mesh values, profile names). Bundled static TTFs (Phase 3). |

**Design-system state:** fully established in Phases 3–8. This phase adds ZERO new tokens, ZERO new fonts, and
ZERO new primitive types — it composes existing primitives (`ScreenScaffold`, `OutlinedControl`, `ConfirmGuard`,
`ScrubberPage`, `SeverityToast`, `MaterialSymbol`, `GraphView`/`GraphViewHost` discipline) into five new screens
plus one new sibling Canvas View (`BedMeshHeatmapView`). The shadcn gate does not apply.

## Spacing Scale

The project does **not** use an 8-point px scale — LAYOUT.md ⚠ NON-NEGOTIABLE 3 forbids hardcoded px for any
structural dimension. Spacing is **ratio-only**: `%`, `fr`, `aspect-ratio`, or container-relative units derived
from the Focus/Field/Gutter grid. The ONLY permitted fixed values (from `hifi.css` / LAYOUT.md) are:

| Fixed value | Token | Where it is allowed (and ONLY here) |
|-------------|-------|--------------------------------------|
| 2px | control outline border | the 2px outline on every `OutlinedControl` (UI-02) |
| ≥64dp | touch-target floor | minimum height of every interactive control (`heightIn(min = 64.dp)`) |
| `--fs` (1.0 / 1.15 / 1.32) | S/M/L text multiplier | the user text-size step; every font size is `fsSp(base, fs)`, never bare px |
| `--r-card` 22 / `--r-ctrl` 16 / `--r-pill` 999 | corner radii | card / control / pill rounding (visual, not structural) |
| hairline | `--hair` divider | 1.5px grid dividers between Field cells (as `statgrid` already does) |

Every region split, cell gap, and dot/heatmap dimension this phase introduces MUST derive from the grid
(weights / `fillMax*` / `aspectRatio`), exactly as `ScreenScaffold`, `MoveScreen`, and `ExtrudeScreen` already do.

Exceptions: none beyond the LAW-permitted fixed values above. The bed-mesh heatmap and probe-dot sizes are
**ratio-derived** (dot radius scales with cell size / grid density per D-08), not fixed px.

## Typography

Sizes are the `--fs`-scaled steps already in production (`fsSp(base, fs)` from Phase 3); `base` values below are
the M-default reference. Two weights only (Regular 400 + SemiBold 600), per the established panels.

| Role | Size (base, ×`--fs`) | Weight | Line Height | Family | Phase-9 usage |
|------|----------------------|--------|-------------|--------|----------------|
| Display | ~40sp | SemiBold 600 | 1.1 | Geist Mono | Focus headline live value: the per-screw turn (`CW 00:25`), the live `manual_probe.z_position`, the "X of N in tolerance" count |
| Heading | ~24sp | SemiBold 600 | 1.2 | Geist | screen/section titles, the hub routine-tile labels, "Adjust the highlighted screw, then re-probe" sub-headline |
| Body | ~16sp | Regular 400 | 1.5 | Geist | helper/empty/error copy, gutter button labels |
| Label / dense value | ~13–14sp | Regular 400 (Mono for values) | 1.3 | Geist Mono for data | per-screw `CCW 0:10` / `in tol.` markers, mesh min/max readout, profile-list names, dense Field cells |

Rules carried from LAW: tabular numerals come from Geist Mono by construction (no `fontFeatureSettings`); live
data is ALWAYS Mono so digits don't jitter; dense cells (≥3 cols portrait / ≥6 landscape) drop text labels and
show a single glyph or ≤3-char value at ~75% of the constraining dimension (CLAUDE.md "Dense cells drop labels").

## Color

The 60/30/10 framing maps onto the project's token roles. Values shown are the **dark** theme (the dark-first
baseline); every value has a light + user-custom variant resolved through `LocalTokens` — components reference
the ROLE, never the literal.

| Role | Token (value, dark) | Usage |
|------|---------------------|-------|
| Dominant (60%) | `--bg` `oklch(0.17 0.012 255)` / `--surface` `oklch(0.225 0.015 255)` | app background + raised screen/card surfaces (Focus/Field panes) |
| Secondary (30%) | `--surface-2` `oklch(0.265 0.017 255)` / `--surface-3` / `--outline` `oklch(0.44 0.02 255)` | inset wells, control bounds (the 2px outline), grid dividers, the heatmap track |
| Accent (10%) | `--accent` `oklch(0.66 0.15 255)` (signature blue) | **reserved — see list below** |
| Destructive | `--stop` `oklch(0.66 0.2 25)` (red) | destructive/dangerous actions only — see list below |

**Accent (blue) reserved for — exhaustive list this phase:**
- `Initiate` / `Run` / `Re-probe` / `Adjust` gutter buttons (an ordinary **physical command** that probes/moves
  the toolhead but is the routine's normal action — per THEMING.md "blue = ordinary physical command, no special hazard").
- `TESTZ` nudge controls and the `Home` pre-flight offer on the Probe-Calibrate page.
- The active-screw highlight outline + glow on the screws-tilt bed/indicator and the active routine tile in the hub.
- The bed-mesh `Load` / `Calibrate` (re-probe) actions and `Z_TILT`/`QGL` `Run`.
- `bed_mesh` profile **load** action; the heatmap's neutral chrome (axes/dots) uses `--text-3`/`--outline`, NOT accent.

> NOTE on the heatmap color ramp (D-07): the red↔blue mesh gradient is a **data visualization ramp**, not the
> accent/stop semantic tokens. It uses `--stop` (high) ↔ `--accent` (low) as its endpoints so it still routes
> through theme tokens and recolors on theme flip, but it is a continuous heat-map scale, exempt from the "10%
> accent budget" the way a chart's data ink is exempt. Probe dots are `--text-3` at low opacity (D-08, "faint").

**Amber (`--heat`, "proceed at peril") reserved for:** the optional **bed pre-heat** offer on BED_MESH (drives
heat — caution, D-13). Any motion-with-mistake-risk affordance if a planner surfaces one. NOT used for ordinary run.

**Green (`--go`) reserved for:** `Accept` (Probe-Calibrate), the per-screw `in tol.` check marker (locked mockup),
`Save` confirmation success, and every **`Back`** gutter button (backing out changes no printer state → green, NOT red).

**Red (`--stop`) reserved for — exhaustive destructive list this phase:** the global `Stop` → `emergency_stop`
(the ONLY hard interrupt for automatic routines, D-11); `ABORT` on the Probe-Calibrate manual-probe session (D-01,
terminates the session — destructive-ish, red per the mockup's Cancel); `Remove` on a bed-mesh profile (D-10);
the `SAVE_CONFIG` **confirm** button inside its `ConfirmGuard` (rewrites printer.cfg + restarts the host, D-12 — a
host interruption). The Files-delete fix (D-15) keeps Delete red inside its existing `ConfirmGuard`.

## Copywriting Contract

Copy is verb-first, terse, and arm's-length-legible. Live data uses Geist Mono. Per-screen below; the table is the
checker's quick reference.

| Element | Copy |
|---------|------|
| Primary CTA (per routine) | screws-tilt: **`Initiate`** (first probe) / **`Adjust`** (re-probe) · Z-tilt/QGL: **`Run`** · bed-mesh: **`Calibrate`** · probe-calibrate: **`Start`** (then `Accept`) |
| Hub heading | **`Calibration`** |
| Hub empty state (heading) | **`No calibration routines available`** |
| Hub empty state (body) | **`This printer reports no leveling, mesh, or probe-calibrate capability. Calibration runs from the printer's own config — add a [screws_tilt_adjust], [z_tilt], [bed_mesh], or [probe] section to enable it here.`** |
| Bed-mesh empty (no mesh) | heading **`No active mesh`** · body **`Run a bed-mesh calibration, or load a saved profile below.`** |
| Screws-tilt headline (live) | **`{n} of {N} in tolerance`** · sub: **`Adjust the highlighted screw, then re-probe`** (verbatim from locked mockup) |
| Screws-tilt all-in-tol | headline **`{N} of {N} in tolerance`** · sub: **`Bed is level.`** |
| Probe-calibrate prompt | **`Jog Z until the nozzle just grips a sheet of paper, then Accept.`** (live value `Z {z_position}` in Mono) |
| Error state (routine rejected) | `SeverityToast` (Severity.Error): **`{printer's rejection text}`** — surfaced verbatim from the `RpcError` (e.g. `Too many retries`, `bed level exceeds configured limits (0.42mm)!`), NEVER a fabricated message and NEVER the transport `e.message` (T-05-11-01 redaction holds) |
| Error state (must home) | pre-flight gate copy: **`Home required before calibration`** with an inline blue **`Home`** offer (D-13) |
| Missing-section degrade | routine simply absent from the hub (capability-gated, D-14) — NO dead/disabled button, NO error |
| Destructive confirm — SAVE_CONFIG | `ConfirmGuard`: title **`Save & restart?`** body **`This saves the printer config and restarts the printer. The connection will briefly drop and reconnect.`** confirm **`Save & restart`** (red) / dismiss **`Cancel`** (neutral) |
| Destructive confirm — Profile remove | `ConfirmGuard`: title **`Remove profile?`** body **`Delete saved mesh profile "{name}". This cannot be undone.`** confirm **`Remove`** (red) / dismiss **`Cancel`** (neutral) |
| Destructive confirm — Abort probe | `ConfirmGuard` NOT required (it's a live session control); `ABORT` is the red gutter button directly. Body label: **`Abort`** |
| In-progress feed (D-11) | compact live feed of `notify_gcode_response` lines (reused Phase-8 console parse), e.g. `Retries: 1/5 Probed points range: 0.043` — RAW, severity-colored, tapped independent of the console filter |
| Save-success | `SeverityToast` (Severity.Success): **`Profile {name} saved`** (timestamp name `YY.MM.DD_HH.MM`, D-10 — no keyboard) |

## Per-Screen Layout Contract (Focus / Field / Gutter)

> All five screens are built on `designsystem/layout/ScreenScaffold.kt` (the Focus/Field/Gutter primitive) and
> render correctly in BOTH portrait (stacked ~40/40/20) and landscape (Focus|Field 50/50 + full-width gutter on
> the shared grid). Square content uses `aspectRatio(1f)` centered in its cell. No hardcoded px.

### 1. Calibration Hub (`CalibrationHubScreen`) — CALIB-01 / D-14
- **Region usage:** Field-only (Focus omitted). The Field is a grid of square outline tiles — one per SUPPORTED
  routine (gated live by `Capabilities.hasObject`). Mirrors the `AppDrawer` tile grammar (`OutlinedControl` square
  tiles, MaterialSymbol + label, blue accent outline).
- **Gutter:** single green **`Back`** (the hub is reached from the drawer; it needs an explicit exit — LAYOUT.md
  "a monitor screen keeps a Back so there's always an exit"). Drawer-swipe NOT suppressed (tiles aren't a scroll list).
- **Tiles + glyphs (no glyph repeats):** Screws-tilt `architecture`/`pivot_table_chart` · Z-tilt `vertical_align_center` ·
  QGL `crop_square` (only when present) · Bed-mesh `grid_on` · Probe-calibrate `straighten`. (Planner picks final
  ligatures; constraint = each unique on the hub.)
- **Empty state:** if `hasObject` returns nothing, show the hub empty-state copy (above) centered, with the Back gutter.

### 2. Screws-Tilt (`ScrewsTiltScreen`) — CALIB-02 — **LOCKED by `05-screws-tilt.png`**
- **This layout is UI LAW. Reproduce the mockup; do not redesign.** Focus = the guided one-screw-at-a-time card:
  `base` marker (top-left), the active screw's exact turn `CW 00:25` (top-right, Mono, blue-glow active indicator),
  the **`{n} of {N} in tolerance`** headline + "adjust the highlighted screw, then re-probe" sub (center), and the
  next/other screw markers (`CCW 0:10`, `in tol.` green check) along the bottom.
- **D-06 enhancement (desired, planner sizes cost):** draw the bed to scale from `[screws_tilt_adjust]` coords +
  bed extents, highlight the active screw. **Graceful fallback:** labeled list / abstract-corner layout if coords
  unavailable. The guided loop (D-03) is the must-have; the to-scale drawing is the slick-if-affordable layer.
- **Gutter (reconciled by D-05):** the mockup's `Initiate` (blue) · `Adjust` (blue, re-probe) · `Accept` (green) ·
  `Cancel` (red) → **Accept/Cancel collapse to a single green `Back`** because screws-tilt is one-shot/stateless and
  changes no config (nothing to accept, no session to abort). Final gutter: **`Initiate` (blue) · `Adjust` (blue) ·
  `Back` (green)**. (Both Initiate and Adjust re-run `SCREWS_TILT_CALCULATE`; Initiate = first probe, Adjust = re-probe.)
- **Generic N-screw (D-04):** screw count/coords/names come from config; do NOT hardcode 4. `results` is keyed
  `screw1..screwN` (1-based) joined to config by index (research Pitfall 1).

### 3. Z-Tilt / QGL (`TiltScreen`) — CALIB-03 — shared automatic flow
- **Region usage:** Focus = a convergence display (state-adaptive): Idle prompt → Running (the D-11 live feed of
  `Retries: N/M Probed points range: …` lines, `ProgressRing` indeterminate-style spinner is NOT used — static per
  D-13; show the running feed instead) → Done (`applied == true` → green "Leveled" + the applied adjustments) /
  Failed (`RpcError` → red result + the rejection text). Field = the per-Z-stepper adjustment readout when present.
- **Gutter:** **`Run` (blue)** · **`Back` (green)**. **NO `Abort`** for automatic routines (Klipper has no clean
  cancel — D-11); `Run`/`Back` are **disabled while running**; the only hard interrupt is the global Stop→ConfirmGuard
  →`emergency_stop`. Pre-flight: `Run` is gated on homed state, offering inline `Home` (D-13).
- **QGL** is the same screen/code path, gated on `quad_gantry_level` (built blind, D-02). Done-detection is
  `applied == true`, failure is the dispatcher `Failure` event — never `applied == false` alone (Pitfall 2).

### 4. Bed-Mesh (`BedMeshScreen`) — CALIB-04 — heatmap + profiles
- **Region usage (landscape):** Focus = the **overhead 2D heatmap** (`BedMeshHeatmapView`, a NEW classic-Views
  Canvas sibling modeled on GraphView discipline — allocation-free `onDraw`, `ThemeableView` token-push, sparse
  redraw; NOT a GraphView fork). Square content (`aspectRatio(1f)`) centered. Red(high)↔blue(low) interpolated
  `mesh_matrix` fill (D-07); faint density-scaled `probed_matrix` dots (D-08, 3×3→50×50, dots shrink with density).
  Field = the profile list (load/remove from `bed_mesh.profiles` keys) + the mesh min/max readout (Mono) + the
  color-scale re-clamp control. Portrait stacks Focus over Field.
- **Color-scale control (D-09):** reuse **`ScrubberPage`** to re-clamp the red/blue min/max — pure view-layer, no
  re-probe. (Two scrubber invocations: min, max.)
- **Empty state (D-07 / Pitfall 4):** `mesh_matrix` empty OR `profile_name == ""` → show "No active mesh" copy +
  the Calibrate/Load actions; profile-list availability is the SEPARATE `profiles`-non-empty condition.
- **Gutter:** **`Calibrate` (blue, re-probe)** · **`Save` (blue → ConfirmGuard SAVE_CONFIG, green on success)** ·
  **`Back` (green)**. Optional **bed pre-heat** offered as an amber pre-flight before Calibrate (D-13). `Remove`
  profile lives in the Field list rows (red, ConfirmGuard). Save auto-names `YY.MM.DD_HH.MM` (D-10, no keyboard).
- **`SAVE` flow (D-10/D-12):** `BED_MESH_PROFILE SAVE={timestamp}` → `ConfirmGuard` ("Save & restart") →
  `SAVE_CONFIG` → reuse the Phase-5 G2 firmware-restart re-handshake (klippy shutdown→ready → resubscribe).

### 5. Probe-Calibrate (`ProbeCalibrateScreen`) — CALIB-05 / D-01 — **the only interactive/stateful page**
- **Region usage:** designed FRESH in the grammar (no mockup). Focus = the live `manual_probe.z_position` (big
  Mono Display value) with the `Z {lower} --> {current} <-- {upper}` bracket parse + the "jog Z until the nozzle
  grips paper" prompt. Field = the **TESTZ step presets** (fine steps `1 / 0.1 / 0.05 / 0.025 mm` — consistent with
  Move's scrubber grammar, D-01 discretion) + `+`/`−` nudge controls. Behaves like a specialized fine-Z move page.
- **Page enable/disable** is driven by `manual_probe.is_active` (Pattern 3). Idle → only `Start` enabled; active →
  TESTZ + Accept + Abort enabled.
- **Gutter:** **`Start` (blue, `PROBE_CALIBRATE`)** → once active → **`Accept` (green, `ACCEPT` then `SAVE_CONFIG`
  via ConfirmGuard)** · **`Abort` (red, `ABORT` — the sole real abort, D-01)** · **`Back` (green)**. Probe-less
  printers surface `Z_ENDSTOP_CALIBRATE` via the same page, gated by probe-present (A3, research-confirmed).

### Cross-cutting (all screens)
- **In-progress feed (D-11):** every routine streams its `notify_gcode_response` lines into a compact feed reusing
  the Phase-8 console parse, tapped RAW (independent of the console display filter). Done = the live object signal;
  failed = the dispatcher `Failure` toast — never a bare gcode ack (Pattern 2).
- **Files-delete fix (D-15) — no new UI, behavioral:** `FilesScreen.deleteEnabled` gates on
  `selected.path == print_stats.filename` (only the currently-printing file is undeletable) instead of the global
  `printingActive`. **Record the relaxed rule** ("Delete is scoped to the active file, not idle-only") in
  `docs/ui_design/` and add the delete-during-print-scoping check to `09-UAT.md`.
