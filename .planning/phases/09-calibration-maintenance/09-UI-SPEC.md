# Phase 9 — UI Design Contract

> verified by gsd-ui-checker, then revised in a design session with the project owner (2026-06-02).

## Design System

| Property | Value |
|----------|-------|

## Spacing Scale

The project does **not** use an 8-point px scale — LAYOUT.md ⚠ NON-NEGOTIABLE 3 forbids hardcoded px for any
structural dimension. Spacing is **ratio-only**: `%`, `fr`, `aspect-ratio`, or container-relative units derived
from the Focus/Field/Gutter grid. The ONLY permitted fixed values (from `hifi.css` / LAYOUT.md) are:

| Fixed value | Token | Where it is allowed (and ONLY here) |
|-------------|-------|--------------------------------------|
| 2px | control outline border | the 2px outline on every `OutlinedControl` (UI-02) |
| ≥64dp | touch-target floor | minimum height of every interactive control (`heightIn(min = 64.dp)`) |
| `--fs` (1.0 / 1.15 / 1.32) | S/M/L text multiplier | the user text-size step; every font size is `fsSp(base, fs)`, never bare px |
| `--r-card` 22 / `--r-ctrl` 16 / `--r-pill` 999 | corner radii | card / control / pill rounding (visual, not structural) |
| hairline | `--hair` divider | 1.5px grid dividers between Field cells (as `statgrid` already does) |

Every region split, cell gap, point-row column width (the 20/40/40 screws-tilt row, the 50/25/25 bed-mesh button
row), and dot/heatmap/icon dimension this phase introduces MUST derive from the grid (weights / `fillMax*` /
`aspectRatio` / percentage), exactly as `ScreenScaffold`, `MoveScreen`, and `ExtrudeScreen` already do.

Exceptions: none beyond the LAW-permitted fixed values above. The bed-mesh heatmap, probe dots, the `bed_tilt`
icon (90%H of cell), the `clock_loader_10` indicator (≤80%H / ≤20%W of its row) are all **ratio-derived**, not
fixed px.

## Typography

Sizes are the `--fs`-scaled steps already in production (`fsSp(base, fs)` from Phase 3); `base` values below are
the M-default reference. Two weights only (Regular 400 + SemiBold 600), per the established panels.

| Role | Size (base, ×`--fs`) | Weight | Line Height | Family | Phase-9 usage |
|------|----------------------|--------|-------------|--------|----------------|
| Display | ~40sp | SemiBold 600 | 1.1 | Geist Mono | Focus headline live value: the live `manual_probe.z_position`, the screws-tilt per-screw turn, the "X of N in tolerance" count |
| Heading | ~24sp | SemiBold 600 | 1.2 | Geist | screen/section titles, the hub routine-tile labels, sub-headlines |
| Body | ~16sp | Regular 400 | 1.5 | Geist | helper/empty/error/prompt copy, gutter button labels |
| Label / dense value | ~13–14sp | Regular 400 (Mono for values) | 1.3 | Geist Mono for data | screws-tilt row `hh:mm` / `°` values + `in tol.` markers, mesh min/max readout, profile-list names, dense Field cells |

Rules carried from LAW: tabular numerals come from Geist Mono by construction (no `fontFeatureSettings`); live
data is ALWAYS Mono so digits don't jitter; dense cells (≥3 cols portrait / ≥6 landscape) drop text labels and
show a single glyph or ≤3-char value at ~75% of the constraining dimension (CLAUDE.md "Dense cells drop labels").

## Color

The 60/30/10 framing maps onto the project's token roles. Values shown are the **dark** theme (the dark-first
baseline); every value has a light + user-custom variant resolved through `LocalTokens` — components reference
the ROLE, never the literal.

| Role | Token (value, dark) | Usage |
|------|---------------------|-------|
| Dominant (60%) | `--bg` `oklch(0.17 0.012 255)` / `--surface` `oklch(0.225 0.015 255)` | app background + raised screen/card surfaces (Focus/Field panes) |
| Secondary (30%) | `--surface-2` `oklch(0.265 0.017 255)` / `--surface-3` / `--outline` `oklch(0.44 0.02 255)` | inset wells, control bounds (the 2px outline), grid dividers, the heatmap track, greyed-out (unsupported) hub tiles |
| Accent (10%) | `--accent` `oklch(0.66 0.15 255)` (signature blue) | **reserved — see list below** |
| Destructive | `--stop` `oklch(0.66 0.2 25)` (red) | destructive/dangerous actions only — see list below |

**Accent (blue) reserved for — exhaustive list this phase:**
- `Run` gutter buttons (screws-tilt, Z-tilt/QGL — an ordinary **physical command** that probes/moves the
  toolhead but is the routine's normal action — per THEMING.md "blue = ordinary physical command, no special hazard").
- The bed-mesh **Activate** (`blur_on`) button and the `Z▲`/`Z▼` `TESTZ` nudge controls on Probe-Calibrate.
- `Start` (`PROBE_CALIBRATE`) on the Probe-Calibrate page; the `Home` pre-flight offer.
- The active routine tile outline + glow in the hub; the not-yet-run `question_exchange` overlay on Z-tilt/QGL.
- The heatmap's neutral chrome (axes/dots) uses `--text-3`/`--outline`, NOT accent.

> NOTE on the heatmap color ramp (D-07): the red↔blue mesh gradient is a **data visualization ramp**, not the
> accent/stop semantic tokens. It uses `--stop` (high) ↔ `--accent` (low) as its endpoints so it still routes
> through theme tokens and recolors on theme flip, but it is a continuous heat-map scale, exempt from the "10%
> accent budget" the way a chart's data ink is exempt. Probe dots are `--text-3` at low opacity (D-08, "faint").

**Amber (`--heat`, "proceed at peril") reserved for:** the **reusable SAVE_CONFIG restart gate** (`ConfirmGuard`
amber variant — confirms a config-save that restarts the host; used by bed-mesh **Save** and Probe-Calibrate
**Save**, D-12). A config-save+restart is the *expected, intended* result of calibration, so it is amber
proceed-at-peril, **NOT** red destructive. Also: the optional **bed pre-heat** offer on BED_MESH (drives heat —
caution, D-13). NOT used for ordinary run.

**White (`--text`, "setting") reserved for:** the Probe-Calibrate **TESTZ step-preset pills** (`1 / 0.1 / 0.05 /
0.025 mm`) and the bed-mesh **scale-mode toggle** (`RELATIVE`/`PLATE`/`±n`) — both change a display/parameter
setting, not printer state (THEMING.md "white = setting").

**Green (`--go`) reserved for:** `Accept` (Probe-Calibrate `ACCEPT`), the screws-tilt `commit` / `in tol.` marker,
save-success toast, and every **`Back`** gutter button (backing out changes no printer state → green, NOT red).

**Red (`--stop`) reserved for — exhaustive destructive list this phase:** the global `Stop` → `emergency_stop`
(app-wide, not phase-specific); `Abort` on the Probe-Calibrate manual-probe session (D-01, terminates the live
session); `Remove` on a bed-mesh profile (D-10); the Files Delete guard (D-15). **SAVE_CONFIG is NOT red** — it
routes through the amber `ConfirmGuard` variant (config-save+restart is the intended result, not a destructive stop).

## Per-Screen Layout Contract (Focus / Field / Gutter)

> All five screens are built on `designsystem/layout/ScreenScaffold.kt` (the Focus/Field/Gutter primitive) and
> render correctly in BOTH portrait (stacked ~40/40/20) and landscape (Focus|Field 50/50 + full-width gutter on
> the shared grid). Square content uses `aspectRatio(1f)` centered in its cell. No hardcoded px.

### 1. Calibration Hub (`CalibrationHubScreen`) — CALIB-01 / D-14
> **OWNER OVERRIDE (2026-06-02):** supersedes CONTEXT.md D-14's "list ONLY routines this printer supports" — ALL
> routines are shown (unsupported ones greyed-but-tappable, sorted last). See spec-intro revision context.
- **Region usage:** Field-only (Focus omitted). The Field is a grid of square outline tiles (mirrors the
  `AppDrawer` tile grammar — `OutlinedControl` square tiles, MaterialSymbol + label).
- **ALL routines are shown** (not just live-supported ones, D-14 revised): **supported routines first** (full
  accent-capable outline), **unsupported routines greyed (`--outline` on `--surface-2`) and sorted to the
  bottom**, but **still tappable** so the owner can open and visually inspect each page even when the printer
  can't exercise it. This also tells users which routines the app supports but didn't detect on their config.
- **Gutter:** single green **`Back`** (the hub is reached from the drawer; it needs an explicit exit — LAYOUT.md
  "a monitor screen keeps a Back so there's always an exit"). Drawer-swipe NOT suppressed (tiles aren't a scroll list).
- **Tiles + glyphs (no glyph repeats):** Screws-tilt `architecture` · Z-tilt `vertical_align_center` · QGL
  `crop_square` · Bed-mesh `grid_on` · Probe-calibrate `straighten`. (Planner finalizes ligatures; constraint =
  each unique on the hub. These are tile glyphs and may differ from the in-screen state glyphs.)
- The hub is **never empty** (all routines render); the prior "no routines" empty-state is removed.

### 2. Screws-Tilt (`ScrewsTiltScreen`) — CALIB-02 — **OWNER-AUTHORED spatial layout (supersedes the mockup card)**
- **Focus = a to-scale representation of the printer bed**, derived from `[screws_tilt_adjust]` screw coords +
  bed extents, with **location-accurate adjustment points** drawn where the screws physically sit. Each point is
  a state icon:
  - `point_scan` — not yet measured
  - `rotate_left` — needs a CCW turn · `rotate_right` — needs a CW turn
  - `commit` (green) — in tolerance
  Under each point: the **direction indicator + turn value**, OR (if unmeasured) the point's **Moonraker name**.
- **Direction indicator (`clock_loader_10`):** the icon's filled wedge is rotated to **point from bed-center
  toward the screw's real location**. The rotation is computed at runtime: bearing(center→screw) adjusted for
  (a) the icon's native wedge-center offset (~30° from 12-o'clock) and (b) the printer-Y-up vs screen-Y-down
  flip. (Owner reference: a screw due-south of center ≈ 175° — calibrate the exact constant against the rendered
  asset; do NOT hardcode per-screw angles, derive them.)
- **Field = the point list** (3 or 4 rows only — beyond that is out of project coverage). Each row, ratio-split:
  - **`[≤20%W]`** the `clock_loader_10` direction indicator, ≤80% row height, centered H/V
  - **`[40%W]`** the required adjustment in **`hh:mm`** clock format (Mono)
  - **`[40%W]`** the same adjustment in **degrees** (Mono)
- **Generic N-screw (D-04):** screw count/coords/names come from config; do NOT hardcode 4. `results` is keyed
  `screw1..screwN` (1-based) joined to config by index (research Pitfall 1). Supports 3 and 4 generically.
- **Gutter:** **`Run` (blue, `SCREWS_TILT_CALCULATE`)** · **`Back` (green)**. **Nothing is applied** — the routine
  is one-shot/stateless (D-05); `Run` = (re-)probe, `Back` = leave. No Accept/Cancel.

### 3. Z-Tilt / QGL (`TiltScreen`) — CALIB-03 — shared automatic flow (no abort needed)
- **Region usage:** Focus = **`img/bed_tilt.svg`**, kept square, **90%H** of the cell, theme-tinted. State overlay:
  - **Not yet run** → overlay **`question_exchange`** in **accent**, ~30% cell-height, centered on the icon.
  - **Run + results returned** → swap the Focus icon to **`data_table`**; the per-Z-stepper adjustment results
    populate the **Field**.
  Field = the adjustment readout (per-stepper Z corrections / "applied" summary) once results exist.
- **Gutter:** **`Run` (blue)** · **`Back` (green)**. This is a pure run-it function with no mid-run user action —
  **no `Abort`, no e-stop framing** (D-11: Klipper has no clean cancel; the routine is short and hands-off).
  `Run` is disabled while running and gated on homed state (offers inline `Home`, D-13).
- **QGL** is the same screen/code path, gated on `quad_gantry_level` (built blind, D-02). Done-detection is
  `applied == true`, failure is the dispatcher `Failure` event — never `applied == false` alone (Pitfall 2).

### 4. Bed-Mesh (`BedMeshScreen`) — CALIB-04 — heatmap + scale toggle + three-button field
- **Focus = the overhead 2D heatmap** (`BedMeshHeatmapView`, a NEW classic-Views Canvas sibling modeled on
  GraphView discipline — allocation-free `onDraw`, `ThemeableView` token-push, sparse redraw; NOT a GraphView
  fork). Square (`aspectRatio(1f)`) centered. Red(high)↔blue(low) interpolated `mesh_matrix` fill (D-07), the
  saturation endpoints set by the **active scale mode** (below); faint density-scaled `probed_matrix` dots (D-08,
  3×3→50×50, dots shrink with density). The active/just-run mesh loads here.
- **Scale-mode toggle (D-09 — owner-authored, 2026-06-02):** an overlay control inset top-left of the Focus
  heatmap — `expand` glyph + the current mode as text (Mono for the numeric modes), **white/setting intent**
  (changing the scale is a display setting, not a physical command), ≥64dp target. Tap **cycles** through a fixed
  list; it re-colors the existing mesh only (pure view-layer, no re-probe). Modes in order:
  - **`RELATIVE`** — endpoints = the measured min/max; there is ALWAYS a 100%-blue (min) and a 100%-red (max)
    point (normalizes the ramp to the data range).
  - **`PLATE`** — referenced to **z = 0** and symmetric: the larger-magnitude extreme (|max| vs |min|) sets full
    saturation for BOTH directions, so typically only one side reaches 100% (both only when |max| == |min|).
  - **`±0.10` · `±0.25` · `±0.50` · `±1.00` mm** — four fixed bounds; the chosen value is the full red/blue
    saturation deviation from z = 0.
  - Cycle wraps `RELATIVE → PLATE → ±0.10 → ±0.25 → ±0.50 → ±1.00 → RELATIVE`. Default = `RELATIVE`.
- **Field = three buttons (ratio-split 50/25/25):**
  1. **`[50%]` Activate** (`blur_on`, blue) — runs `BED_MESH_CALIBRATE`, loads the result into the Focus heatmap.
     **Does NOT save.** (Optional amber bed-preheat pre-flight before probing, D-13.)
  2. **`[25%]` Save** (`save`, blue) — opens the **full-screen Save dialog**: name pre-filled `YY.MM.DD_HH.MM`,
     **system-keyboard-editable** (carve-out note above), gutter `Save`/`Cancel`. Save runs
     `BED_MESH_PROFILE SAVE={name}` → **amber `ConfirmGuard` restart gate** → `SAVE_CONFIG`.
  3. **`[25%]` Load** — opens the **full-screen scrollable profile selector** (`bed_mesh.profiles` keys), gutter
     `Apply`/`Cancel`. Apply loads the selected profile into the Focus heatmap. `Remove` (red `ConfirmGuard`)
     lives on each selector row (D-10).
- **Gutter (main screen):** single green **`Back`**. (The routine actions are the three Field buttons; the gutter
  only needs an exit.)
- **Empty state (D-07 / Pitfall 4):** `mesh_matrix` empty OR `profile_name == ""` → "No active mesh" copy in the
  Focus; the Activate/Load buttons remain. Profile-list availability is the SEPARATE `profiles`-non-empty condition.
- **`SAVE` flow (D-10/D-12):** dialog → `BED_MESH_PROFILE SAVE={name}` → amber restart gate → `SAVE_CONFIG` →
  reuse the Phase-5 G2 firmware-restart re-handshake (klippy shutdown→ready → resubscribe).

### 5. Probe-Calibrate (`ProbeCalibrateScreen`) — CALIB-05 / D-01 — **the only interactive/stateful page**
- **Region usage:** designed FRESH in the grammar (no mockup). Three states driven by `manual_probe.is_active`:
  - **Focus — idle:** `img/nozzle.svg` square ~90%H + prompt "Start, then lower the nozzle to the bed."
  - **Focus — active:** the live **`manual_probe.z_position`** as the hero (big Geist Mono Display ~40sp,
    updating as you nudge) + the active prompt; if the `// Z position: {lower} --> {current} <-- {upper}`
    response is parseable, render that bracket under the hero in Mono.
  - **Focus — accepted (pending save):** the captured offset + "Offset set. Save to keep it (restarts printer)."
- **Field = the jog pad** (mirrors Move's grammar, disabled until `is_active`):
  - **Step preset** row — outline pills `1 / 0.1 / 0.05 / 0.025 mm`, intent **white** (selecting a step is a *setting*).
  - **`Z▲` / `Z▼` nudge** — two large **blue** (physical-command) buttons firing `TESTZ Z=±{step}`.
- **Gutter (state-adaptive):**
  - *Idle* → **`Start` (blue, `PROBE_CALIBRATE`)** · **`Back` (green)**
  - *Active* → **`Accept` (green, `ACCEPT`)** · **`Abort` (red, `ABORT`)** — **`Back` is suppressed while a
    session is live** (leaving mid-probe = dangling-session bug; you must Accept or Abort).
  - *Accepted* → **`Save` (amber → reusable `ConfirmGuard` restart gate → `SAVE_CONFIG`)** · **`Back` (green,
    discards the in-memory offset)**
- **Page enable/disable** is driven by `manual_probe.is_active` (Pattern 3). Probe-less printers surface
  `Z_ENDSTOP_CALIBRATE` via the same page, gated by probe-present (A3, research-confirmed).

### Cross-cutting (all screens)
- **In-progress feed (D-11):** every routine streams its `notify_gcode_response` lines into a compact feed reusing
  the Phase-8 console parse, RAW (independent of the console display filter). Done = the live object signal;
  failed = the dispatcher `Failure` toast — never a bare gcode ack (Pattern 2).
- **Files-delete fix (D-15) — no new UI, behavioral:** `FilesScreen.deleteEnabled` gates on
  `selected.path == print_stats.filename` (only the currently-printing file is undeletable) instead of the global
  `printingActive`. **Record the relaxed rule** ("Delete is scoped to the active file, not idle-only") in
  `docs/ui_design/` and add the delete-during-print-scoping check to `09-UAT.md`.
