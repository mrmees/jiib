# Phase 15.1 Plan 03: OKLCH Bed-Mesh Ramp Summary

**Replaced the bed-mesh heatmap's `accent→surface2→stop` sRGB red/green lerp with a host-pure, golden-locked 32-stop OKLCH viridis ramp (blue→teal→yellow, off red/green, D-11) baked once and read cheaply per cell — a tall spot now reads as "tall," not "FAILED."**

## Accomplishments

- **`theme/OklchRamp.kt`** — a host-pure (zero Android/Compose imports) baker for the LOCKED 32-stop
  viridis bed-mesh ramp. Three LOCKED control points (`low oklch(0.45 0.12 255)` → `mid oklch(0.65
  0.13 150)` → `high oklch(0.85 0.15 95)`), interpolated PIECEWISE-LINEARLY across two segments split
  at stop index 15 (segment A = 0..15 low→mid, segment B = 15..31 mid→high), endpoints inclusive, hue
  along the SHORTER arc. Every stop is converted to opaque sRGB ARGB via `Palette.oklchToHex` — the
  OKLab matrices are reused from `Palette` (golden-tested once), NEVER re-ported. Public API:
  `bedMeshRampStops(): List<Int>` + `stopCount`.
- **`OklchRampTest` turned GREEN** against the committed `oklch-ramp-golden.json` `ramp[]` — every baked
  stop matches the reference hex bit-for-bit (quantized lowercase `#rrggbb`, no epsilon), exactly as
  `PaletteGoldenTest` asserts against the sibling `color.js` oracle. Fixture was NOT regenerated from
  the Kotlin (that would collapse the test into a tautology).
- **`BedMeshHeatmapView` rewired** — `applyTokens` now bakes the OKLCH ramp ONCE into a
  `private val rampStops: IntArray`; `onDraw` is a pure baked-array index + `lerpArgb` between the two
  adjacent stops (NO OKLCH math per cell per frame — Adreno-320 fill-rate floor, RESEARCH Pitfall 5).
  The `t.stop`/`t.surface2`/`t.accent` ramp endpoints are GONE (negative grep clean). The
  `deviationToRamp`/`endpoints` scale-mode math and the probe-dot overlay are untouched — only the
  color source changed.
- **On-device flox UAT PASSED** (LineageOS API 30, genuine Adreno 320): the bed-mesh ramp reads as a
  height scale (viridis blue→teal→yellow, off pure red/green) with acceptable performance — confirmed
  by Matthew. The `autonomous:false` manual gate is satisfied.

## Decisions Made

- **Zero-arg `bedMeshRampStops()` API** chosen over the inconsistent two-endpoint
  `bakeRamp(low, high, stops)` — the locked three-control-point spec made a single dedicated bed-mesh
  helper read cleanest at the call site (control points / stop count / `MID_INDEX` baked in as private
  vals named to match `_meta`).
- **OKLab matrices reused from `Palette`**, never re-derived in `OklchRamp` — re-porting would risk
  golden drift on the Nexus-7 floor; the matrices are golden-tested once in `Palette`.
- **Golden fixture is the source of truth** — if the locked endpoints ever change, edit + re-run the
  independent oracle `tools/oklch-ramp-oracle.mjs` and re-bake from THAT, never from `OklchRamp.kt`.
