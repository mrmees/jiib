# Phase 15.1 Plan 02: Semantic Core (PaletteMode + seriesColor + D-07 Directional) Summary

Built the semantic core of the token model: the `PaletteMode` enum carried as a resolved field on
`ThemeTokens`, the D-05 `seriesColor(i)` N-series helper (accent-led, D-09 infinite wrap, empty-pool
guard, explicit negative-index reject), and the D-07 accent-led re-derivation of `Directional`
(`temperature=accent`, `xy=pool[0]`, `z=pool[1]`) centralized in one place so Move/PrintStatus
consumers shift values without any shape change.

## What Was Built

### Task 1 — PaletteMode + the seriesColor N-series helper (D-05 / D-09) — commit `a1f2896`
- **`PaletteMode` enum** (`Colorful` / `Simple` / `HighContrast`) added to `ThemeTokens.kt` with a
  `companion fromFlags(simple, highContrast)` that maps the generator's two boolean mode flags to the
  enum in ONE place (high-contrast wins if both set — defensive; the resolver never sets both).
- **`ThemeTokens.mode: PaletteMode`** field added with a default of `PaletteMode.Colorful` so every
  existing constructor site (`TokensDark`, `TokensLight` baked fallbacks) compiles unchanged — no
  spread-string churn (Item 8 resolved via the default-value path).
- **`SeriesColor.kt`** — `fun ThemeTokens.seriesColor(i: Int): Color`, a top-level extension reading
  ONLY `ThemeTokens` fields (no Android view imports, host-testable):
  - `seriesColor(0) == accent` in ALL three modes (lead series keeps identity across a mode switch).
  - Colorful: `pool[(i-1) % pool.size]` past 0 — wraps INFINITELY (D-09), NO status colors in data.
  - Simple: alternates accent (even `i`) / text (odd `i`).
  - HighContrast: cycles `[accent, stop, caution(=heat), go, text][i % 5]`.
  - Empty-pool guard: Colorful falls back to `accent` rather than `% 0` (mirrors GraphView CR-02).
  - Negative index: `require(i >= 0)` reject — documented as the public contract in KDoc.
- **`TokenBridge.build`** threads `mode = PaletteMode.fromFlags(gen.simple, gen.highContrast)` onto the
  built tokens (the resolver already derives those flags from its `MODE_*` string — no resolver change
  needed, the mode flows through the existing `gen`).
- **`SeriesColorTest` GREEN**: accent-leads-in-all-modes, each mode's sequence, the D-09 wrap well past
  pool length (index 1000), Colorful-never-emits-status, the empty-pool guard, the negative-index
  reject, and a fallback-token case (`TokensDark.seriesColor(0) == accent`, mode default == Colorful).

### Task 2 — D-07 accent-led Directional re-derivation — commit `ea0a095`
- **`TokenBridge.build`** re-derives `directional` from the RESOLVED (post-override) pool in ONE place:
  `temperature = accent`, `xy = pool.getOrElse(0){accent}`, `z = pool.getOrElse(1){accent}`. This
  supersedes the Phase-15 `bake(gen.directional.*)` warmth-tagged derivation. Because it reads the
  post-override pool, a `pool[0]`/`pool[1]` override shifts `directional.xy`/`.z` with it (same-identity);
  `temperature` is accent and override-immune.
- **Empty-pool guard** via `getOrElse(accent)` so `pool[0]`/`pool[1]` reads can't index-crash.
- **accent survives all palette modes** (D-05), so `directional.temperature` never collapses to text in
  Simple/HighContrast — pinned by a test.
- **KDoc** on both `Directional` and `ThemeTokens.directional` updated to document the D-07 accent-leads
  reconception (supersedes Phase-15 D-2/D-13).
- **`TokenBridgeTest` extended**: fixed the now-superseded `directional.xy == bake(gen.directional.xy)`
  assertion to the D-07 `pool[0]` value; added accent-led directional assertions, the
  Simple/HighContrast temperature-stays-accent test, and a pool-override-follows-directional test.
