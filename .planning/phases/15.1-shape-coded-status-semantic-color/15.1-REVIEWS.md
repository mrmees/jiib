## Codex Review

**Overall Summary**

The plans are well sequenced and mostly extend the existing Phase 15 substrate instead of rebuilding it. The wave ordering is sound and the major semantic goals are covered. The main risks are a few correctness traps: status overrides must not defeat Simple/High-Contrast mode semantics, the OKLCH fixture must be reproducible and valid JSON, TextView compound drawables need explicit bounds, and D-10 Back behavior is not truly app-wide yet.

**Cross-Cutting Concerns**

- **HIGH:** Plan 04 conflicts with D-04 if status overrides are applied unconditionally. High-Contrast must force status to RYG regardless of user overrides, and Simple should collapse status to text. Status overrides should likely apply only in Colorful/effective editable mode.
- **HIGH:** D-10 says Back is neutral/outline app-wide with consistent gutter position. Plan 06 only changes Move, and Plan 08 documents it. Add a lightweight grep/audit/update for every existing Back control, or explicitly move that implementation to 15.2.
- **MEDIUM:** `oklch-ramp-golden.json` cannot have "top-of-file comments" if parsed as strict JSON. Use a `_meta` field or separate `.md`/script.
- **MEDIUM:** The golden ramp spec needs exact interpolation parameterization: where the mid control point lands, hex casing, RGB/ARGB format, and whether stops include endpoints.
- **MEDIUM:** Avoid `Color(longArgb)` unless the existing code proves it is correct. Compose `Color(Long)` can mean packed color, not unsigned ARGB. Prefer a shared `argbLong.toInt()` helper.
- **MEDIUM:** Console compound drawables will use the vector intrinsic size unless bounds are set. A 96dp vector in a TextView row is risky; set bounds to an `fsSp`-scaled pixel size.
- **LOW:** `seriesColor(i)` should either reject or normalize negative indices; public helper behavior should be explicit.

## Consensus Summary

Single independent reviewer (Codex). Overall verdict: **plans are well-sequenced and architecturally sound — extend-not-rebuild, correct wave ordering, D-06 supersession wired correctly.** No reviewer recommended re-planning from scratch. The actionable feedback clusters into two HIGH items and a handful of MEDIUM correctness/robustness tightenings.

### Agreed Strengths
- Wave-0-first discipline: type decision + compile-clean RED scaffolds before any wiring.
- `seriesColor` as a single toolkit-agnostic helper; `directional` re-derived centrally.
- D-06 supersession correctly rewires BOTH GraphView trace AND PrintStatus readout to the same accent.
- Persistence correctly reuses `writeScope` + the existing fail-safe sanitizer (the recurring trap is respected).
- Classic-Views console row handled as a `TextView`, not assumed Compose.

### Agreed Concerns (priority order)
1. **[HIGH] D-04 override precedence (Plan 04).** Status overrides must NOT apply unconditionally — High-Contrast must still force RYG, Simple must still collapse to text, regardless of a user's stored override. Override application must be mode-gated (effective in Colorful; ignored/overridden in Simple/High-Contrast). Needs explicit per-mode tests. *This is the one genuine correctness gap.*
2. **[HIGH] D-10 Back is "app-wide" but only Move is touched (Plan 06).** Either add a repo-wide Back-control inventory + update to 15.1, or explicitly defer the app-wide sweep to 15.2 (the conformance phase) and have Plan 08 document the deferral honestly. *Scope decision needed — the owner should pick.*
3. **[MEDIUM] Golden fixture must be strict-valid JSON.** My in-loop edit told Plan 01 to "document generation in a top-of-file comment" — that breaks strict JSON. Use a `_meta` field inside the JSON (or a sibling `.md`/script), and preserve the independent oracle script as a committed artifact.
4. **[MEDIUM] Lock the exact ramp parameterization.** Mid control point placement, hex casing, RGB-vs-ARGB, endpoints-inclusive — pin these so Plan 03 implements deterministically. Also reconcile the `bakeRamp(low, high, stops)` signature with the three-control-point spec.
5. **[MEDIUM] ARGB `Long` → Compose `Color` conversion.** Use a shared `argbLong.toInt()`-based helper, not `Color(longArgb)` (packed-color ambiguity), unless existing code proves the long form is correct.
6. **[MEDIUM] Console compound-drawable bounds.** Set explicit `fsSp`-scaled pixel bounds on the TextView compound drawable; a raw vector intrinsic size will blow up row height.
7. **[MEDIUM] Force-move lock drawables + stale-consumer greps.** Add any new lock-shape drawables to `files_modified`; add negative grep gates for stale `pool[0]`/`directional.temperature`/`red = back` across plans 05/06/08.
8. **[LOW] `seriesColor` negative-index behavior** should be explicit; **`ThemeTokens` constructor churn** from the new `mode` field needs a compile gate; **palette-mode enum** over spread string mapping.

### Divergent Views
None — single reviewer.
