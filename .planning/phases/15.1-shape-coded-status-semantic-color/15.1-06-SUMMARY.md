# Phase 15.1 Plan 06: Shape-Glyph Safety Layer + Move Summary

**Attaches the D-02 shape-glyph safety layer to the two classic status sites plan 05 doesn't cover — the console scrollback (ERROR=octagon, WARNING=triangle, at explicit fsSp bounds so row height stays correct) and the Move screen (unhomed-axis caution triangle, force-move green-closed/red-open lock silhouette) — and makes the Move Back button neutral/outline per D-10.**

- **Duration:** code-complete (close-out only; implementation + on-device UAT already done)

## Accomplishments
- Console ERROR rows now carry `ic_status_octagon` and WARNING rows `ic_status_triangle`, tinted from the resolved severity palette, at EXPLICIT `fsSp`-scaled `setBounds(...)` (not the 96dp vector intrinsic) so row height stays correct; recycled non-ERROR/WARNING rows clear the compound drawable (D-01/D-02; RESEARCH Pitfall 3).
- Move unhomed-axis state shows the `ic_status_triangle` caution glyph tinted from `t.heat` at an explicit `fsSp` size; the homed state stays color-only (D-02).
- Force-move renders the redundant non-color lock shape — green `ic_lock_closed` when SAFE, red `ic_lock_open` when ARMED — via two new padlock vector drawables (D-12, T-15.1-06-01).
- Move Back tile changed from `Intent.Go` to neutral/outline at a consistent gutter position, dropping the "overrides LAW's red=back" comment (D-10, Move-only; app-wide sweep deferred to 15.2).
