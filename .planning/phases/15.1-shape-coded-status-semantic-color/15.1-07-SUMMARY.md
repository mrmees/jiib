**Theme Editor now exposes user-editable stop/caution/go status-color swatches (writeScope-routed via setActiveStatusOverride, no guard per D-03) with a shape-decorated preview strip (octagon/triangle) and mode-aware stored-vs-effective display; S/M/L samples confirmed accent+pool-sourced (Open-Q2).**

## Accomplishments
- Added 3 status-color swatches (StatusSlot.Stop / Caution / Go) to the Theme Editor, each opening the same ColorWheel picker as the pool-override grid via a parallel `editingStatusSlot` state, with NO editability guard (D-03 — shape carries safety, not color).
- Routed every status-override write through `container.setActiveStatusOverride(active, slot, argb)` on the process-lifetime writeScope — never `rememberCoroutineScope()` ([[dinghy-compose-write-scope-cancellation]]).
- Made the editor mode-aware: it distinguishes the STORED override from the EFFECTIVE rendered color (Simple/High-Contrast ignore the override per plan 04), so the UI never implies an override "took" in a mode where it is gated off.
- Overlaid `ic_status_octagon` on the stop preview swatch and `ic_status_triangle` on the caution swatch (go stays shapeless, D-02) at explicit fsSp glyph size.
- Confirmed the S/M/L preview samples draw from `seriesColor(0)`+plain pool slots only — never status tokens nor `seriesColor(1+)` (Open-Question-2).
