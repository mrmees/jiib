# Phase 15.1 Plan 04: Status-Slot Persistence Summary

Extends the proven per-profile durable override path to the three status slots (Stop/Caution/Go,
D-03), MODE-GATED per D-04: in Colorful a user override is applied over the generated status color and
clears back to generated when removed; in Simple status collapses to the text color (override ignored);
in High-Contrast status is forced to the fixed RYG safety palette regardless of any stored override.
Persisted per-profile through the existing `writeScope` + `mutateActive` path, fail-safe-sanitized
per-entry, applied in `TokenBridge`. Zero new persistence path, zero new sanitizer, zero new
dependencies.

## What Was Built

### Task 1 — Status overrides through the persisted tuple + mode-gated TokenBridge (commit `0a470d7`)
- **`StatusSlot.kt`** — `enum class StatusSlot(val key: String) { Stop("stop"), Caution("caution"),
  Go("go") }` + a `companion fromKey(s): StatusSlot?` (null for non-status keys). The canonical keys
  used everywhere in the override path — NO bare `"stop"`/`"caution"`/`"go"` string literals in
  TokenBridge/Profile/AppContainer (grep-clean), NO integer keys for status.
- **`Long.toComposeColor()`** — the shared `.toInt()`-based ARGB-Long → Compose `Color` helper (replaces
  the inline `Color(it.value.toInt())` at AppContainer; NEVER `Color(longArgb)` packed-color). All status
  AND pool Long→Color conversions now route through this one helper.
- **`ThemeTuple.statusOverrides: Map<String, Long>`** — the plan-01 typing decision realized: a separate
  String-keyed field (the Int-keyed `poolOverrides` cannot hold `"stop"`). `sanitizeTuple` splits the ONE
  persisted wire map per-entry, with the status check BEFORE `toIntOrNull` so a key never crash-hits
  `key.toInt()`: valid ARGB + `StatusSlot.fromKey` match → `statusOverrides`; valid ARGB + integer-string
  key → `poolOverrides`; anything else (junk value OR unknown/bad-int key) → DROPPED.
- **`TokenBridge.build`** — added a defaulted `statusOverrides: Map<String, Color>` param and applies it
  MODE-GATED: `colorful = !gen.simple && !gen.highContrast`; a `statusColor(slot, generated)` helper
  returns the override only in Colorful, else `bake(generated)`. The generator already collapses status
  to text (Simple) / forces RYG (High-Contrast), so ignoring the override there preserves the safety
  semantics. The soft/glow halos derive from the resolved status Color via `.copy(alpha=…)` so an
  override drives its halo too.
- **`ThemeResolver`** — `statusOverrides` field threaded through `compute()` (→ `TokenBridge.build`) and
  the FULL-tuple `apply(...)` (defaulted trailing param); added `setStatusOverride(slot, argb)` mirroring
  `setOverride`.
- **`StatusOverrideTokenBridgeTest` GREEN** — the 3 RED scaffold cases turned green PLUS the full per-mode
  matrix: (a) Colorful applies + soft/glow halo + clear-to-generated; (b) Simple ignores → status=text;
  (c) High-Contrast ignores → fixed RYG; malformed-key drop (unknown string + bad int-looking key, valid
  status key still applies, no crash); the key-split unit test; and BOTH the active-profile
  (`Profile.toThemeTuple`) AND idle-global (`ThemePrefs.sanitizeTuple`) resolution paths exercised through
  `ThemeResolver.apply`.
- **`ThemePrefsFallbackTest` extended** — good-status-override kept in the status map (not the pool map),
  and a junk/out-of-range `"stop"` value dropped fail-safe while a good `"go"` survives.

### Task 2 — Durable status-override write on writeScope (commit `7d60264`)
- **`AppContainer.setActiveStatusOverride(active, slot: StatusSlot, argb: Long?)`** — mirrors
  `setActiveOverride` exactly: active → `mutateActiveProfile { p -> … p.poolOverrides[slot.key] = argb and
  0xFFFFFFFFL / remove }`; idle → `writeScope.launch { themePrefs.mutateOverrides { … } }`. The
  read-modify-write happens inside ONE atomic edit (`mutateActiveProfile` / `mutateOverrides`).
- **[[dinghy-compose-write-scope-cancellation]] honored:** routes through the process-lifetime
  `writeScope` ONLY — never a composition `rememberCoroutineScope()` (the Phase-14 switch-revert /
  slow-flash dropped-write trap). The edit re-emits through `seedTheme`'s single `apply` (one re-emit),
  where the override is mode-gated on resolution.
- `seedTheme` converts both `poolOverrides` and `statusOverrides` Long maps via the shared
  `toComposeColor` helper and passes `statusOverrides` to `apply`.
