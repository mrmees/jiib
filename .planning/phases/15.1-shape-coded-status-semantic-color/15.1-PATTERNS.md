## Pattern Assignments

### NEW `res/drawable/ic_status_octagon.xml` + `ic_status_triangle.xml` (asset, static)

**Analog:** `app/src/main/res/drawable/nozzle.xml` (verbatim pattern, also `heat_bed.xml`).

**The exact convention to copy** — geometry only, white stroke, tinted at the call site (THEME-01):
```xml
<!-- header comment explains: strokes drawn white, recolored at runtime via Icon(tint=...) -->
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="96dp" android:height="96dp"
    android:viewportWidth="96" android:viewportHeight="96">
    <path android:pathData="M…L…Z"
        android:strokeColor="#FFFFFFFF" android:strokeWidth="4"
        android:strokeLineCap="round" android:strokeLineJoin="round" />
</vector>
```

**D-01 load-bearing requirement:** the octagon and triangle must differ at the OUTER CONTOUR (true 8-gon vs filled/outlined triangle), not just the inner ✕/! mark — the silhouette is the safety mechanism and must survive grayscale/CVD. The inner mark (`✕` for stop, `!` for caution) is secondary redundancy, drawn as additional `<path>` elements. **Do NOT ship Unicode glyphs** — the JS reference's `⯃`/`▲` are HTML-preview-only (font-dependent, no silhouette guarantee on the Nexus 7).

**D-02 coverage:** only `ic_status_octagon` (stop) and `ic_status_triangle` (caution). NO circle for `go` — benign states stay color-only.

### NEW `theme/SeriesColor.kt` — `fun ThemeTokens.seriesColor(i: Int): Color` (utility, pure)

**Analog:** `GraphView.applyTokens` pool-read at `GraphView.kt:186-200` (the thing it replaces) + `fsSp` at `ThemeTokens.kt:154` (the toolkit-agnostic-pure-fn placement precedent).

**The D-05 sequence** (RESEARCH Pattern 2, verified `heat` IS caution per `ThemeTokens.kt:62-67`):
```kotlin
// Lives in theme/ as a top-level/object fn reading ONLY ThemeTokens fields — no Android view imports,
// host-testable. Both toolkits already hold a ThemeTokens (Compose LocalTokens, Views applyTokens).
fun ThemeTokens.seriesColor(i: Int): Color = when (mode) {
    PaletteMode.Colorful     -> if (i == 0) accent else pool[(i - 1) % pool.size]
    PaletteMode.Simple       -> if (i % 2 == 0) accent else text
    PaletteMode.HighContrast -> listOf(accent, stop, heat, go, text).let { it[i % it.size] }
}
```

**Mode plumbing (RESEARCH recommendation, Claude's discretion D-05):** add `mode: PaletteMode` as a field on `ThemeTokens` — the resolver already knows it (`ThemeResolver.compute` derives `simple`/`highContrast` at `ThemeResolver.kt:135-136`); thread it into `TokenBridge.build`. Cleaner than detecting from baked tokens.

**Empty-pool guard (mandatory, CR-02 precedent):** GraphView already guards this at `GraphView.kt:190` (`val pool = if (t.pool.isNotEmpty()) t.pool else listOf(t.accent)`). `seriesColor` MUST do the same — `pool[(i-1) % pool.size]` div-by-zero crashes the render surface on an empty pool.

### NEW `theme/OklchRamp.kt` — bed-mesh sequential ramp (utility, color math)

**Analog:** `TokenBridge.lShift` at `TokenBridge.kt:51-54` (the canonical "delegate to Palette's internal OKLCH helpers, never re-port the matrices" pattern):
```kotlin
// TokenBridge.kt:51 — the pattern to mirror: hex → Palette.hexToOklch → mutate → Palette.oklchToHex → bake.
private fun lShift(hex: String, dL: Double): Color {
    val o = Palette.hexToOklch(hex)
    return bake(Palette.oklchToHex(clamp01(o.L + dL), o.C, o.H))
}
```

**The helpers are already `internal` and golden-tested** in `Palette.kt`: `hexToOklch` (`:121`), `oklchToHex` (`:138`, 20-iter gamut clamp built in), `OklchValue(L,C,H)` (`:61`), the OKLab 3×3 matrices `linToLab`/`labToLin` (`:91`/`:106`, "copied VERBATIM from color.js"). `render/` is the same `:app` module — they are reachable (RESEARCH A1 verified). **Do NOT re-derive matrices** (golden-drift risk on the Nexus-7 floor).

**Bake-once contract (RESEARCH Pitfall 5, anti-pattern):** compute a small ARGB lookup (~32 stops) ONCE in `applyTokens`; `onDraw` indexes/`lerpArgb`s between baked ints — NEVER `oklchToHex` per cell per frame (50×50 grid × 20-iter gamut search would tank fill rate). Reuse `BedMeshHeatmapView.lerpArgb` (`BedMeshHeatmapView.kt:235`) for the inter-stop blend.

**Recipe (RESEARCH Pattern 3):** lerp L, C, H (H along the shorter arc) between two endpoints; viridis/cividis-style blue→teal→yellow off pure red/green (D-11 — so a tall spot doesn't read "FAILED"). Exact stops = Claude's discretion (D-11); owner can tune live via the on-device loop.
