<objective>
Build the two floating cycler widgets (D-06 style cycler + D-07 size cycler) and wire them as an
AppShell overlay above all routes, gated on the dev-enable boolean from plan 01. Each tap advances the
appropriate axis and pushes a transient `ThemeOverride` into the layer built in 15.2-01, flipping the
whole live app; dismiss clears it back to the real theme. This is the conformance accelerant the rest of
the phase rides on (D-09).

Per the cross-AI review (HIGH-4), the steppers MERGE onto the current override so the two axes are truly
independent at runtime: a style advance preserves the active size override and vice-versa — tapping one
never reverts the other. Per the Codex confirmation pass (MEDIUM — atomic stepping), each tap routes
through the ATOMIC `container.updateThemeOverride { next*Override(it) }` (from 15.2-01) rather than reading
a Compose-captured `currentOverride`, so rapid taps cannot read a stale snapshot and drop an axis.

Purpose: One device walk per combo instead of six rebuilds — make the app-wide sweep (D-10/D-11) cheap.
Output: `DevThemeCyclerOverlay.kt`, the AppShell overlay wiring, host-pure cycler-stepping tests, the
TEMP `devEnableFlow`-default flip that makes the cyclers appear in the release APK for this checkpoint,
and an on-device cycler-walk sign-off.
