# 15.2 Theme Conformance Scorecard (D-12)

The app-wide UI-conformance scorecard the sweep (plans 03/05/06) fills, one row per DISTINCT SURFACE.
Each cell is scored as the sweep walks the device per theme combo using the dev cyclers (the override
layer built in 15.2-01). Placeholder `-` = not yet audited; fill with `OK`, `FIX` (mechanical, fixed
silently per D-13), or `FLAG` (judgment call surfaced to the owner).

## Inventory provenance (reproducible — MEDIUM-2 / LOW FIX 5)

Surface rows were GENERATED from a programmatic inventory of `ui/**` + `render/**` (NOT a hand-built
list), so no overlay/dialog/drawer-chrome/scan-surface/prompt/render-View is silently omitted. The
file-level inventory command:

```
grep -rEl "fun .*Screen\(|fun .*Dialog\(|fun .*Overlay\(|fun .*Popup\(|fun .*Sheet\(|: View\(|class .*View " \
  app/src/main/java/works/mees/dinghy/ui app/src/main/java/works/mees/dinghy/render
# + a chrome pass for the shell surfaces the screen/dialog pattern misses:
grep -rEl "AppDrawer|ScanSurface|ProgressRing|RootController|fun AppShell|SplashScreen" \
  app/src/main/java/works/mees/dinghy/ui app/src/main/java/works/mees/dinghy/render
```

The `grep -rEl` inventory is FILE-level. A single file can host MULTIPLE distinct surfaces (a screen
plus its dialogs/overlays/popups), so every multi-surface file is EXPANDED into its distinct SURFACE
rows below — coverage is proven at SURFACE granularity, not file granularity. Expansions made:

- `AppShell.kt` → its hoisted overlay surfaces: MacroExecutionPopup, ScanSurface, PromptDialog,
  DevThemeCyclerOverlay (the last is built in a later 15.2 plan — row reserved now so the sweep can't
  skip it).
- The prompt surfaces (`prompt/**`) → PromptDialog (the overlay frame + close control) vs the content
  renderers PromptMarkupText and PromptImageItem as separate surface rows.

## Hardened criteria — the C-series (15.2-05 D-10 guided core-screen review)

The D-10 guided on-device review of the core daily-driver screens (15.2-05 Task 2) surfaced seven new
LAW criteria, now folded into `docs/ui_design/THEMING.md` ("Conformance criteria — the C-series"; C3/C6
also in `LAYOUT.md`). **Plan 06's app-wide sweep audits EVERY surface against these in addition to the
7 dimension columns below.** They sharpen the intent/status/density rules into testable checks:

| C | Criterion (testable) | Dimension it sharpens | Doc home |
|---|---|---|---|
| **C1** | A button performing the screen's EXPECTED physical action uses ACCENT, not caution/danger. | Intent | THEMING.md |
| **C2** | The increment picker is a 3-cell `[−][value][+]` pattern with shared-increment vs single-measurement modes. | Intent / FFG | THEMING.md |
| **C3** | Vertical adjustments (Z) use a vertical arrangement when the orientation layout allows it (not a horizontal row). | FFG | LAYOUT.md + THEMING.md |
| **C4** | A control that ENABLES a catastrophic state (force-move unlock) is FILLED with the STOP color while active. | Intent / 15.1 | THEMING.md |
| **C5** | The screen's NATURAL PRIMARY ACTION takes ACCENT, and may be context-dependent (Temp: Presets↔Cooldown; Files: Print file). | Intent | THEMING.md |
| **C6** | Config/settings-type surfaces are EXEMPT from ≥64px and should be DENSIFIED (print-control surfaces stay bound). | ≥64 / FFG | LAYOUT.md + THEMING.md |
| **C7** | BACK is Neutral ONLY for plain nav; a Back that DISCARDS input / REJECTS a pending result stays RED. | Intent / 15.1 | THEMING.md + OutlinedControl docstring |

## Conflict policy (D-13) + sanctioned literals

- **Mechanical conflicts** (a raw color where a token exists, a sub-64dp target, a missing `fsSp`
  scale, a hardcoded px): FIX SILENTLY during the sweep, note in the row.
- **Judgment calls** (a layout that violates Focus/Field/Gutter, a color-role reassignment, a
  pool→role semantic question): FLAG to the owner, do NOT silently change.
- **Sanctioned raw-color literals are CONFORMANT per THEMING.md — do NOT flag them:**
  - `PromptMarkupText` author-hex color spans (D-03 carve-out — the macro author chooses the color).
  - `SpoolPicker` filament swatches (the filament's real color, not a theme role).
  - Theme swatches in `ThemeEditorScreen`/`ColorWheel` (they DISPLAY raw colors by definition).

## Scorecard

Columns = the 6 LAW dimensions + a 7th 15.1-conformance dimension:

1. **Token** — token-purity (no raw color where a role token exists; THEME-01)
2. **Intent** — button-intent color (red stop/back · green accept · amber peril · accent command · white setting)
3. **FFG** — Focus/Field/Gutter grammar (portrait stack · landscape 50/50 · ratio-only sizing)
4. **≥64** — ≥64dp touch targets
5. **fsSp** — `fsSp(baseSp, t.fs)` text scale (no hardcoded sp; floor 15sp metadata)
6. **D/L/C** — dark / light / custom render correctly across all three palette modes
7. **15.1** — shape-coded status (octagon stop / triangle caution / shapeless go) · pool→role color · Back neutral+position
