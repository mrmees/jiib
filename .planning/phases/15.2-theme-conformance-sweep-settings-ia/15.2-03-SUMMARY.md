# Phase 15.2 Plan 03: Printers absorbs Connection + per-profile webcam toggle Summary

Began the Settings IA dissolve (D-02/D-04): renamed Devices → Printers in-place, moved the Connection
(host/port/key + mDNS) editor OUT of Settings and INTO the Printers screen so Printers is the single
per-printer management surface, and added a per-profile `webcamEnabled` toggle that actually GATES the
Webcam tile (not just persisted). apiKey edit semantics are now explicit (blank-preserves / Clear-nulls /
non-blank-replaces) as a pure, host-tested helper, and validation + redaction survive the move.

## What was built

- **`Profile.webcamEnabled` (D-04)** — a per-profile feature toggle (default **true**, preserving today's
  capability-only `webcamCount > 0` behavior) added to `Profile` + `PersistedProfile` and threaded through
  BOTH `toPersisted()` and `fromPersisted()` so it round-trips through `ProfileStore.mutateActive`'s wire form.
- **`AppContainer.setActiveWebcamEnabled`** — `mutateActiveProfile { it.copy(webcamEnabled = on) }`: durable
  via the process-lifetime writeScope, lost-update-safe via the atomic read-modify-write (WR-01).
- **`AppContainer.webcamTileEnabled` (MEDIUM-4)** — a `combine(webcamCount, activeProfile)` flow returning
  `count > 0 && profile.webcamEnabled` (null profile → keeps the prior always-on default). This is the WIRED
  gate that REPLACES the bare `webcamCount > 0`; plan 04 repoints the AppShell.kt:183 consumer to collect it.
- **Pure helpers (companion)** — `webcamTileGate(count, webcamEnabled)` (the gate predicate) and
  `resolveApiKeyEdit(existing, fieldInput, cleared)` (MEDIUM-5: `cleared` → null; blank → existing; else →
  field). Both host-tested, no IO.
- **`PrintersScreen` (D-02/LOW-1)** — the renamed/extended `DevicesScreen` (the old file was DELETED, not
  copied — no orphaned divergent body). The tile-grid switch is verbatim; a per-tile `edit` glyph and the
  Add-printer tile open a `ConnectionEditor` sub-screen (a local back-stack) that absorbs the host/port/key +
  mDNS form. Every persist routes through `saveProfile`/`deleteProfile`/`setActiveProfile`; the lone
  `rememberCoroutineScope()` drives the mDNS scan ONLY. The apiKey field never pre-fills the raw key (seeds to
  `""`, shows a "Key saved" hint); save resolves via `resolveApiKeyEdit`; Clear writes null via the same helper.
- **`SettingsScreen`** — the Connection section (host/port/key + mDNS + delete guard) and its supporting
  state/imports/private composables (`DiscoveredPrinterRow`, `FieldError`, `SCAN_WINDOW_MS`) were removed.
  Settings is now purely app-level (Appearance + Feature toggles + System). The Appearance theme mirror still
  reads `activeProfile`. `onConnectionSaved` is retained as a (now-unused) param for call-site compat (plan 04
  cleans the IA).
- **`AppShell`** — the `Dest.Devices ->` arm repointed `DevicesScreen` → `PrintersScreen` (one-line; the
  enum/label/routing changes are plan 04).
