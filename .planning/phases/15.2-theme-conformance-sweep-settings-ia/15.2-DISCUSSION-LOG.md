## Settings / Devices IA

Initial binary framing (printer-settings hub vs app-settings-only vs hybrid) was rejected by the
owner in favor of a **three-area model**, refined to four drawer destinations.

**Owner's framing (verbatim):** "I think we want to have them be THREE separate items. *The printer
management area, where you add/remove printers and make connections... *Theme area, lives in the
drawer, changes with printer... *Settings area, lives in the drawer, changes with printer. Lets the
user change the functionality of the device."

### App-global placement
| Option | Description | Selected |
|--------|-------------|----------|
| Bottom of Settings | Small app/system block at bottom of per-printer Settings | |
| In Printers/management | App-level lives with device management | |
| Own About tile | A 4th small drawer destination for app-global items | ✓ |

### Drawer tile naming
| Option | Description | Selected |
|--------|-------------|----------|
| Printers / Theme / Settings | Rename Devices→Printers + new Theme/Settings tiles | ✓ |
| Devices / Theme / Settings | Keep Devices label | |

### Functionality-toggle scope
| Option | Description | Selected |
|--------|-------------|----------|
| Truly per-printer | Each profile stores its own toggles | ✓ |
| App-wide, shown here | One app-wide set living on the tile | |

**Result:** Four drawer tiles — **Printers** (add/remove/switch + Connection), **Theme**
(per-printer look), **Settings** (per-printer functionality toggles), **About** (app-global/system
+ hidden dev-widget enable).
