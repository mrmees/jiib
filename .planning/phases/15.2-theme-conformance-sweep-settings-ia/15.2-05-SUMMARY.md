# Phase 15.2 Plan 05: App-wide Back-Intent Sweep + D-10 Guided Core-Screen Review Summary

The largest single conformance fix — flipping every Back affordance to `Intent.Neutral`/outline
app-wide (D-10) — plus the D-10 guided on-device review of the core daily-driver screens, whose findings
are now folded into THEMING.md/LAYOUT.md as seven testable conformance criteria (C1-C7) and scored into
the AUDIT scorecard before the app-wide sweep (plan 06) runs on the hardened criteria.

## What was done

**Task 1 — App-wide Back-intent sweep (committed `a921cc8`, pre-continuation).** Every Back affordance
flipped to `Intent.Neutral` (resolves to `t.outline`), matching the MoveScreen reference. The sweep went
beyond the plan's enumerated offenders (Extrude/Temperature/Spool/Webcam/Console/Devices) into the
calibration screens, macros screens, and scan surface too — 17 files. The two **destructive** Backs
(`MeasuredWeightPage`, `ScanConfirmCard`) were deliberately LEFT red per the owner's ruling — they
discard a pending measurement / reject a pending scan result (cancel-with-loss, not plain navigation).

**Task 2 — D-10 guided core-screen review (checkpoint, human-completed).** The owner walked the 9 core
screens with the dev cyclers and returned the findings folded in Task 3.

**Task 3 — fold findings into LAW + score the AUDIT (this continuation, committed `279118b`):**
- **THEMING.md** gained a "Conformance criteria — the C-series" section (C1-C7) as testable LAW; **C3 +
  C6** (the layout/density criteria) also added to **LAYOUT.md**.
- **OutlinedControl/Intent docstring** updated with **C7** (a discarding/rejecting Back stays Danger/red).
- **15.2-AUDIT.md** hardened: C-series criteria table + a finding-tag vocabulary block; core-screen rows
  (Move/Temp/Files/Console/Settings/Theme/Printers/About) scored with per-dimension findings; **M1-M4**
  tagged `mechanical (plan-06)`; **R1-R4** tagged `redesign (deferred)` with todo paths; **Print-Status**
  and **icons/glyphs** exemptions recorded so plan 06 skips them.
- **Four redesign todos** created (R1 3-cell increment picker → P17; R2 Move-Z vertical layout → P17; R3
  theme/settings densify-to-one-page → P20, cross-linking the settings-vs-devices-boundary todo; R4
  Printers edit-mode/delete-mode toggle buttons → P16).

## The seven new criteria (C1-C7)

| C | Criterion | Where |
|---|---|---|
| C1 | Expected physical action = ACCENT, not caution/danger | THEMING |
| C2 | Increment picker is a 3-cell `[−][value][+]` pattern (shared vs single-measurement modes) | THEMING |
| C3 | Vertical adjustments (Z) use a vertical arrangement when orientation allows | LAYOUT + THEMING |
| C4 | A control enabling a catastrophic state is FILLED with STOP color while active | THEMING |
| C5 | The screen's natural primary action = ACCENT, may be context-dependent | THEMING |
| C6 | Config/settings surfaces EXEMPT from ≥64px, should be DENSIFIED | LAYOUT + THEMING |
| C7 | Back is Neutral ONLY for plain nav; discarding/rejecting Back stays RED | THEMING + OutlinedControl |
