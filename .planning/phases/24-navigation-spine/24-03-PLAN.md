<objective>
Replace AppShell's ~1000-line `when(dest)` hub-and-spoke holder with a Navigation-Compose `NavHost`
back-stack — the heart of the phase. Hoist all ~20 session holders ABOVE the NavHost (preserve every
`remember(store)` re-key and every `DisposableEffect { onDispose { holder.cancel() } }` leak-cancel
verbatim), keep all overlays floating as Box siblings above the NavHost, and convert the swipe-suppress
set, the webcam lifecycle effect, and the AppShell-level BackHandlers to read `navBackStackEntry`
instead of the retired `dest` enum. Wire the D-04 pop-to-root on print start/end for the three foot-gun
destinations. Slim `ShellNavState` to carry only in-screen sub-nav state.

The four in-screen sub-navs (Calibration routine, Fine-Tune group, Outputs detail, Macros
bookmarked-vs-system) STAY in-screen (D-01) — do NOT promote them to nav routes.

Decisions honored by the gate-above structure: the connection lifecycle stays the TOP tier of the
waterfall (D-02) — `RootController`'s `when{}` and `TopRoute.derive()` are UNCHANGED, the NavHost mounts
only in Shell state, so the not-ready connection states remain HARD OVERRIDES the back-stack cannot
dismiss (D-03), and no new onboarding/wizard is built. The App Drawer stays LIVE as-is (D-12) — it
remains a floating overlay above the NavHost and is the interim System hub; its inert "Power" tile stays
unwired (D-11). None of these change behavior; they are preserved through the migration.

This plan does NOT touch PrintStatusScreen's internals (the morph + idle list is this plan's sibling
plan 24-04) — `composable<NavDest.WaterfallHome>` mounts the existing PrintStatusScreen with its
`onNavigate` seam now typed `(NavDest) -> Unit`.

⚠ ACCEPTED REGRESSION (owner-locked 2026-06-09): after a reconnect/recovery Splash the user LANDS ON
WaterfallHome (the morphing root). The top-level drill-down back-stack is NOT preserved across the
recovery Splash — the NavHost is composition-local inside AppShell and decomposes during the Splash
(gate-above). This is the deliberate, simpler path replacing the old FIX-4 dest-preservation gate
(AppShell.kt:854). In-screen sub-nav state (Calibration routine page, FineTune group) STILL survives
via ShellNavState — only the top-level destination resets to root. The executor and verifier must
EXPECT this; it is not a bug.

Purpose: Retire the hand-rolled back-stack for the real Nav-Compose one (predictive-back, process-death
restoration, type-safe routes) without tearing down session state on navigation. Output: a NavHost shell.
</objective>
