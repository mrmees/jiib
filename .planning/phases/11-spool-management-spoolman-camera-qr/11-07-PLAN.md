Build the camera half of the view: the full-screen `ScanSurface` (CameraX `PreviewView` + `QrCodeAnalyzer` bound to the lifecycle, released on dispose — D-14), the `CameraPermission` Activity-Result glue feeding the headless `ScanState` machine (11-03), the `ScanConfirmCard` (D-12 confirm-first: a decoded valid id resolves the spool and asks before setting active), and the `MeasuredWeightPage` (D-04 — reuse `NumpadPage`, show remaining/used are linked). Purpose: This is the headline feature (QR-scan-to-assign, SPOOL-05) plus the graceful-degrade contract (SPOOL-06) and the measured-weight nice-to-have (SPOOL-09). The QR text is the V5 untrusted-input boundary; this plan wires the already-locked id-only parser (11-03) into the runtime so the host is never navigated. Files are disjoint from the sibling wave-4 UI plan (11-06) — this plan owns the `scan/` subpackage + the measured-weight page.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scanned QR text → spool id | **The load-bearing V5 boundary.** The decoded string is untrusted; QrPayloadParser (11-03, D-12 allow-list) parses id-only; the host is NEVER navigated or used as a base URL. |
| camera hardware → app | First on-device camera; CAMERA permission requested only at scan entry, released on dispose, no frame persistence. |
| confirm → set active | A decoded id must not auto-mutate the printer; confirm-first (D-12) gates the set-active dispatch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-07-01 | Tampering / Spoofing | QR with a hostile host or non-spoolman scheme | mitigate | D-12 (allow-list, 11-03): parseSpoolId returns id only; the host is never read, returned, or navigated; non-spoolman → Unsupported/NotRecognized, stay scanning |
| T-11-07-02 | Tampering (state) | Auto-set active on decode bypasses confirm | mitigate | D-12: valid decode → AwaitingConfirm only; set-active fires solely on the explicit green confirm in ScanConfirmCard |
| T-11-07-03 | Info disclosure | Camera over-grant / frame leakage | mitigate | Request CAMERA only on scan entry; unbindAll() on dispose (D-14); decode in-memory, no frame stored; uses-feature required=false (11-05) |
| T-11-07-04 | Tampering (real device) | Measured-weight write corrupts a real spool | mitigate | measureSpool is an explicit user action; the end-to-end UAT (11-09) uses the save→change→restore protocol on the sacrificial spool |
| T-11-07-05 | DoS (camera stall) | Unclosed frame / front-camera fixed-focus | mitigate | QrCodeAnalyzer closes in finally (11-05); DEFAULT_BACK_CAMERA first, never hard-code front (D-14) |
| T-11-07-SC | Tampering | npm/pip/cargo installs | accept | No package installs here (camera/zxing deps + legitimacy audit handled in 11-05; all VERIFIED first-party) |
