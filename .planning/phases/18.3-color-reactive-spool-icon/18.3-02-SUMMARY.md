# Phase 18.3 Plan 02: SpoolGlyph Composable Summary

**The dedicated `SpoolGlyph` composable — a token-tinted body `Icon` under a runtime-colored band `Canvas` with a neutral keyline — is the single render seam for the color-reactive spool; its swatch-count branch (empty/solid/two-stop gradient) is factored into a pure host-tested helper, and a `@Preview` matrix proves the three band states across all six themes at `fs=L` plus the white/black keyline-stress cases.**

## Accomplishments
- Authored `SpoolGlyph.kt`: a `Box(Modifier.size(sizeDp))` wrapping (1) the body — `Icon(painterResource(R.drawable.spool), tint = bodyTint)` reusing the existing flat-tint contract for the neutral, non-reactive flanges (D-02); and (2) the band — a `Canvas(fillMaxSize())` that draws nothing when empty (D-03), a `SolidColor` for one swatch (D-08), or a two-stop `Brush.linearGradient` for 2+ (D-04), then strokes the band edge with the neutral `keyline` (D-05). Both layers share ONE coordinate frame (Pitfall 3); the band rectangle reproduces `spool.xml`'s documented fractions exactly (Pitfall 3 seam-free).
- Factored the swatch-count → render decision into a pure `internal sealed interface BandRender` (`Empty`/`Solid`/`Gradient`) + `internal fun bandRenderFor(swatches)` so it is host-testable with plain JUnit (no Compose/Robolectric). The Canvas consumes that same function.
- Gradient uses EXPLICIT `start`/`end` Offsets bound to the band rectangle (Pitfall 4) — horizontal flange-to-flange — so the two-stop transition lands on the band instead of washing out across the whole DrawScope.
- Wrote `SpoolGlyphTest.kt`: four host tests proving 0→Empty, 1→Solid, 2→Gradient, 3+→Gradient(first two only) — all GREEN.
- Wrote `SpoolGlyphPreviews.kt`: the Wave-0 validation matrix — a band-state `@PreviewParameter` (empty/single/two-color), the full six-theme wrapper set on the gradient state, an explicit empty-spool confirm panel (D-03), the SC5 keyline-stress cases (white PLA `#FFFFFF` on light, black `#000000` on dark), and an `fs=L` shot via `fsLargeSeed`. No live Moonraker; `fsSp(40/64, t.fs).dp` sizing; neutral token body/keyline.

## Decisions Made
- **Band geometry as consts:** `BAND_LEFT/RIGHT/TOP/BOTTOM_FRACTION` (0.34/0.66/0.18/0.82) live as `private const` in `SpoolGlyph.kt`, copied verbatim from `spool.xml`'s documented header so the Canvas band registers seam-free with the vector's gap.
- **Pure helper shape:** a `sealed interface BandRender` with `data object Empty` / `data class Solid(color)` / `data class Gradient(start, end)` makes the four behaviors assertable by value equality in plain JUnit — the cleanest host-test seam.
- **Keyline + gradient (Claude's discretion, RESEARCH Q3):** keyline width = `box.minDimension * 0.033` (~1.3dp at a 40dp tile, holds at launcher size without dominating); gradient is horizontal flange-to-flange (reads naturally for a side-view spool). On-device verification is plan 04.
- **No brush cache:** the band is static and one-per-surface, so the brush is built inside the `DrawScope` per recomposition — negligible on Adreno 320 (RESEARCH A2); a `remember`-cache is only warranted if profiling shows cost (it won't at these sizes).

## TDD Gate Compliance
Task 1 is `tdd="true"`. The pure helper (`bandRenderFor`) and its test were authored together because the project's Gradle test sourceset compiles as a whole before the `--tests` filter runs (the "Wave-0 RED scaffolds must compile" trap) — a test referencing an undefined `bandRenderFor`/`BandRender` would brick ALL test compilation, not fail RED cleanly. The helper was therefore defined alongside the test, and the GREEN gate (`:app:testDebugUnitTest --tests …SpoolGlyphTest`) passed on first run (4/4). The test asserts the contract independently of the rendering and would fail if the branch logic regressed.
