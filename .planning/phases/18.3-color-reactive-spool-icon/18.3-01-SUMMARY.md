**Custom side-view spool VectorDrawable (body/flanges only, band excluded) replaces the `database` ligature for `LauncherSpool`; the hex parser is promoted to one shared `internal` helper and the live `PrintMetadata` now carries `filament_colors` as the D-07 gcode color fallback.**

## Accomplishments
- Authored `res/drawable/spool.xml` — a genuinely-custom side-view filament-spool glyph following the `nozzle.xml`/`heat_bed.xml` convention (96×96 viewBox, white stroke paths, header comment). The wound-filament band region is deliberately empty negative space owned by plan 02's `SpoolGlyph` Canvas; the band rectangle is documented as fixed fractions of the 96-unit box. No `<gradient>` is baked in (filament color is dynamic data).
- Flipped `DinghyIcons.LauncherSpool` from `IconRef.Ligature("database")` to `IconRef.Drawable(R.drawable.spool)` (SC1, D-01), `alternate = "launcher_spool"` preserved; obsolete WR-02/`database` comment rewritten; entry stays in `all`.
- Updated `DinghyIconsTest.registryDrawableEntries_areOnlyTheCustomKeepers` in the SAME wave so the keeper set is `{nozzle, heat_bed, launcher_spool}` with matching KDoc + assertion message — drift-guard stays green (SC6, Pitfall 1).
- Promoted `parseNormalizedHex` to an `internal` top-level helper so `SpoolGlyph` (plan 02) and surface wiring (plan 03) share one parser (Pitfall 6).
- Added `PrintMetadata.filamentColors: List<String>` populated from `filament_colors[]` so the active print's gcode colors are reachable for the D-07 fallback without a new flow.

## Decisions Made
- **Spool silhouette:** two full flange circles (r=30 at (33,48) and (63,48)) + small hub bores (r=6) + top/bottom drum edges (y=18, y=78) connecting them, framing the empty band gap. Chosen for a clean side-view read at small launcher-tile size while leaving an unambiguous rectangular band region for the Canvas overlay.
- **Band rectangle fractions:** left 0.34 / right 0.66 / top 0.18 / bottom 0.82 (documented in the XML header) — these are the exact coordinates plan 02's `SpoolGlyph` Canvas must reproduce for a seam-free band.
- **De-duplication scope:** the plan only named `SpoolScreen.kt` for the parser promotion, but two byte-identical private copies already existed in `ActiveSpoolCard.kt` and `SpoolPicker.kt`. Promoting one to `internal` top-level collided with them (same-package overload resolution ambiguity), so both private copies were removed — turning the promotion into genuine de-duplication, exactly the plan's stated intent.
