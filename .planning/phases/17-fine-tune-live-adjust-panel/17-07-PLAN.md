<objective>
Close GAP 1 (UAT Check 6, MAJOR): the Fine-Tune whole-group busy-lock wedges permanently when a tuner is nudged at its clamp ceiling.

Root cause (CONFIRMED in 17-UAT.md, build 7ed8e70): at Flow=150% tapping '+' calls `markPending(FLOW, 151)` with the UNCLAMPED target, while the wire command `flowFactor(151)` coerceIn-clamps to `M221 S150`. Klipper accepts S150 as a no-op (no RpcError → no Failure → no toast → clearPending never fires). The reported value stays 150, `reached()` compares 150 vs 151 → never reached → `_pendingStateFlip` stuck → `groupBusy` permanently true → the whole group dims AND goes inert (`FineTuneTile` strips +/-/long-press handlers when `!enabled`), so the user cannot even nudge back down. The holder lives in `AppShell` `remember(store)`, surviving sub-nav — only a process restart recovers. WHOLE-CLASS bug: every unclamped-max '+' tuner (FLOW, SPEED, MAX_VELOCITY, MAX_ACCEL, SCV, PA, SMOOTH_TIME) plus the FwRetraction '+' paths. MIN_CRUISE + PART_FAN are already safe (they clamp the display target before markPending).

The load-bearing correctness piece (BLOCK 1 / Codex review): the existing flat `FLIP_TOLERANCE = 0.5` is WRONG once the clamped target is fed to `markPending`. Tuner steps span four orders of magnitude — PA = 0.001, smooth = 0.01, SCV = 0.1, FLOW = 1, SPEED/MIN_CRUISE/FAN = 5, VEL = 10, ACCEL = 100 — all but ACCEL/VEL are at or BELOW 0.5. With a flat 0.5 tolerance:
  (a) the skip-arm guard would fire on a LEGITIMATE in-range PA/smooth/SCV/FLOW nudge (the new target is < 0.5 from the current report) → the busy-lock never arms → Check 5 regression for those tuners; and
  (b) `reached()` would declare a real in-flight small-step flip "reached" instantly → the lock releases BEFORE the printer confirms → Check 5 broken again.

Fix (BLOCK 1, with the second Codex pass sharpening it): the tolerance is NOT half a step — a half-step `<=` comparison releases at a MIDPOINT reading (target 1.1, tol 0.05, a reported 1.05 satisfies `0.05 <= 0.05`), which contradicts "release only on the real flip." Instead the per-tuner tolerance is a small float EPSILON whose only job is to absorb float round-trip error: it must be (i) LARGER than realistic float compare error on that tuner's value, and (ii) STRICTLY SMALLER than one step — and the comparison is STRICT `<` (`abs(current - target) < toleranceFor(tuner)`). So a genuine one-step nudge is never declared reached until the reported value actually EQUALS the commanded (clamped) target, on EVERY tuner including PA (step 0.001) and smooth (0.01). Concretely the epsilon is `step * 0.1` (one-tenth of the step) per tuner, so even the smallest step (PA 0.001 → eps 0.0001) stays comfortably above float jitter yet an order of magnitude below the step. Wire that epsilon through BOTH `reached()` and the skip-arm guard (the skip-arm fires only when the clamped target is within epsilon of the already-reported value — a true no-op at the cap).

Fix strategy (single-source-of-truth, per <constraints>): make `PrinterCommands` the ONE clamp authority — its existing gcode builders already clamp via `coerceIn(*_MIN, *_MAX)`. Expose those clamps as pure public functions, refactor the builders to call them, and have each screen call site feed the CLAMPED target to `markPending` so target and wire can NEVER disagree. Add a defensive skip-arm guard in the holder (target ≈ reported within the per-tuner epsilon → don't arm) AND a seq-guarded bounded self-clearing timeout backstop so no future unreachable flip can wedge the group permanently. Add the missing regression tests (small-step arm-and-hold-until-equal, at-cap no-op release, unreachable timeout release, rapid-double-tap stale-timer no cross-clear).

Purpose: an at-cap nudge must be a harmless no-op, an in-range nudge on EVERY tuner must still arm the busy lock and hold it until the real flip (the reported value EQUALS the target, not merely a midpoint), and the recovery path must be robust even against a future tuner whose flip can't be reached.
Output: clamp authority + per-tuner float epsilon (strict-<) + holder skip-arm guard/seq-guarded timeout backstop + clamped call sites (incl. FwRetraction) + regression tests. Host unit suite GREEN.
