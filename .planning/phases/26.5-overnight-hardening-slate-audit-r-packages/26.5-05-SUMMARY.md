### Auto-fixed Issues

**1. [Rule 3 - Blocking] DisplayPrefsTest round-trip case hit the Windows back-to-back DataStore write race**
- **Found during:** Task 1 (GREEN gate, first run)
- **Issue:** `setKeepScreenOnTrueAfterFalse_roundTrips` — the second `dataStore.edit` on the temp-file store failed with `IOException: Unable to rename …preferences_pb.tmp` (Windows-host file-handle artifact on a rename over an existing blob; not a DisplayPrefs bug — single-write tests pass on the real file path). Attempt 1 (interleaved read between writes) did not clear it.
- **Fix:** Attempt 2 — the two-write case runs on an in-memory `DataStore` (the ThemeOverrideTest `MemDataStore` shape), matching the repo's documented precedent (`ProfileStoreTest`: "use two separate stores to avoid the back-to-back host race"). The contract under test is DisplayPrefs KEY semantics (true overrides persisted false), which the in-memory store proves; the temp-file harness still covers default, fail-safe, and single-write round-trip.
- **Files modified:** app/src/test/java/works/mees/dinghy/ui/settings/DisplayPrefsTest.kt
