## Report Notes

**For the morning report — what a fork-and-edit user actually changes:** one file, `app/src/main/java/works/mees/dinghy/command/CommandMap.kt`. If their Klipper config uses a different filament macro (say `M701`, or `FILAMENT_EJECT BEEP=1`), they edit the one `Slot(...)` line — `macro` is the name the button's visibility gates on (case-insensitive, from `printer.objects.list`), `gcode` is the exact line sent to the printer (defaults to the macro name) — then rebuild. Nothing else in the app hardcodes these names anymore: research corrected the audit's "four hardcode sites" to **six** (ExtrudeHolder's two `hasMacroIgnoreCase` gates were missed), and all six now read from CommandMap, proven by tests that reference the map symbolically so they'd still pass after any rename. Safety commands (M112/emergency_stop) are deliberately NOT remappable. The README "Customizing for your printer" section is deferred to R5b; until then the file's KDoc header is the documentation. Suggest updating `docs/top-down-audit-roadmap.md` Part 3's "four places" wording to six when R5b touches docs.
