- One plan per R-package, `autonomous: true` on every plan.

### Rails on top of GSD's (owner-mandated for the unattended run)
- **Build gate per plan:** `gw.bat :app:testDebugUnitTest` + `:app:assembleDebug` green
  (PLUS `:app:assembleRelease` + `verifyMinSdkRelease` for R5a and R1). Exit code authoritative
  (pipe through `tr -d '\r'`).
- **Fail-forward:** a plan that can't go green in 3 attempts or ~90 min is reverted, marked
  `failed` in its SUMMARY with the blocker, and the wave moves on. One plan never eats the night.
- **Deep code review via codex after each plan** (codex CLI, e.g.
  `codex exec --sandbox read-only -` with the diff piped in; codex is the REVIEWER, never the
  author). Note: this GSD build's `workflow.code_review_command` only fires at `/gsd-ship`, so the
  orchestrator dispatches codex directly per plan — this instruction is the mechanism of record.
  Act on agreeable show-stoppers; log the rest in the report as acted/deferred.
- **Push the branch at every wave boundary** — `gsd/phase-26.5-overnight-hardening`, via
  **Windows git.exe** (`"/mnt/c/Program Files/Git/cmd/git.exe" push`; Linux git fails on drvfs
  config locks). NEVER push master.
- **Device is best-effort only:** flox via adb may be probed but NOTHING blocks on it
  (ShellPresenceTest is known-flaky — don't chase it). Acceptance criteria needing flox or the
  S25 Ultra are written as `checkpoint:human-verify` items so the verifier records them
  `human_needed` (human_verify_mode is already end-of-phase).
