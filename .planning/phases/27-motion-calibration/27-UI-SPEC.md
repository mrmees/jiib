## Spacing Scale

Declared values — all multiples of 4dp. This project uses Compose Dp, not CSS px.

| Token | dp | Usage |
|-------|-----|-------|
| xs | 4dp | Icon gaps, inline element padding |
| sm | 8dp | Column/row element spacing (e.g. `spacedBy(8.dp)` in vertical columns) |
| md | 16dp | Screen-edge horizontal padding; element spacing within cards |
| lg | 24dp | Section separators |
| xl | 32dp | Major layout divisions |
| 2xl | 48dp | Focus/Field region transitions (portrait stack) |

**Phase 27 special case — unit `U` overrides fixed sizes for all interactive controls:**
Every interactive element height (ListRow, FootButtonBar, OutlinedControl) is sized
via `rememberUnitGrid(minOf(maxWidth, maxHeight))` — `uDp` is the authoritative control
height. The spacing table above governs padding and gaps between elements, not control heights.

**Touch target floor:** ≥64dp (enforced by `OutlinedControl` and `ListRow.heightIn(min=uDp)`).
**UAT-5:** controls cap at 1U unless explicitly named as an exception (none in this phase).

Exceptions: The BedMeshHeatmapHost (Views surface) uses its own internal sizing — do not
apply Compose padding conventions to it.

All sizes are `fsSp(baseSp, t.fs)` where `t.fs` is the S/M/L user setting (S≈1.0, M≈1.15, L≈1.32).
**Never a bare `.sp` value — always `fsSp`.** The OS fontScale is pinned to 1f at the Compose root.

| Role | Base sp | Weight | Font | Line height | Usage |

| Body / label | 16sp | 400 | Geist | 1.5 | ListRow primary label (routine name, profile name, screw name) |
| Focus title / heading | 20sp | 600 | Geist | 1.25 | Hub Focus routine title, BedMesh heatmap header, screen section titles |

**Note:** The center cells of the vertical 3-cell columns (Z readout, step readout) use Geist Mono
(tabular) so digits don't reflow as values change. Routine names and labels use Geist (proportional).

## Layout Contract

### Grammar: Focus / Field, gutter = null (LAW)

Every screen in this phase is a **two-region** `ScreenScaffold(focus = { … }, field = { … }, gutter = null)`.
The old `gutter` slot is ALWAYS null on rebuilt screens. Actions live in `FootButtonBar` inside
the `field` lambda as the last column element.

### Unit U (load-bearing)

```
nTarget = round(contentMinDim / 41dp).coerceIn(5, 7)
nMaxFit = (contentMinDim / 64dp).toInt().coerceAtLeast(5)
N       = min(nTarget, nMaxFit)
U       = contentMinDim / N
```

Derived at screen root via `rememberUnitGrid(minOf(maxWidth, maxHeight))`. Passed explicitly as
`uDp` to child components. Constant through rotation (portrait inherits the same U as landscape).

**Must survive at 5U (phone landscape).** Minimum content at 5U:
- MoveScreen: JogPad + 2 vertical columns + FootButtonBar row
- CalibrationHub: 1+ ListRows visible in Field + FootButtonBar + Focus (if landscape)
- Routine screens: 2 vertical columns (Probe) or ListBlock + FootButtonBar + Focus content

### MoveScreen — specialized-layout exemption (D-01..D-04)

MoveScreen uses `BoxWithConstraints` for manual sizing, not `portraitFocusAspect`. The sacred-square
3×3 JogPad is NOT resized or restructured.

**Portrait (D-03):**
```
padSize = (maxHeight * 0.60f).coerceAtMost(maxWidth)
```
The JogPad renders at `padSize × padSize` (the 60%-of-height cap ensures guaranteed room for Z/
distance columns). The remaining height below the pad holds the two vertical 3-cell columns +
FootButtonBar.

**Landscape:**
The JogPad fills the full height of its half (existing `fillMaxHeight` behavior — no change). The
Z column and distance stepper column sit beside the pad in the other half. FootButtonBar spans
full content-area width at the bottom.

**Column motif (D-01, D-02, D-08 — VERBATIM OWNER STEER):**
"3 equally spaced rows, just like the vertical Z column."

```
Column(Modifier.weight(1f).fillMaxHeight(), verticalArrangement = Arrangement.spacedBy(8.dp)) {
    OutlinedControl(/* + or Z-up */,  modifier = Modifier.weight(1f).fillMaxWidth(), ...)
    StepDisplay(/* readout */,        modifier = Modifier.weight(1f).fillMaxWidth())
    OutlinedControl(/* − or Z-down */, modifier = Modifier.weight(1f).fillMaxWidth(), ...)
}
```

All three cells use `Modifier.weight(1f)` — equal thirds. Do NOT give the center cell weight(2f)
to accommodate a larger readout. The readout content must be compact enough for the 1/3 slot.

**Z column uses `t.directional.z` outline** (matching the JogPad's Z corner affordance identity).
**Distance stepper column uses `t.outline`** (neutral — a step-selector, not a directional control).

**Pad internals carry over unchanged (D-04):**
- Home-XY center button (accent intent)
- Axis-corner live readouts + tap-to-home
- Red force-move toggle (C4: filled stop-red when armed, `t.stopSoft` fill)
- XY outline = `t.directional.xy`, Z corner outline = `t.directional.z`

**FootButtonBar (Move): [Home All (accent) | Disable (stop/red) | Back (neutral)]**

### CalibrationHubScreen — list + Focus (D-05)

**Focus:** `DetailCard` — icon (UAT-1 prominent: ~70-80% of U) + title + description + Open button.

- Unsupported (D-06): `t.text3` label, `t.text3` icon tint — dimmed but listed, NOT hidden
- Selection: `t.accentSoft` fill + `t.accentLine` border on selected row
- First entry pre-selected on load so Focus is never empty (D-05)

**FootButtonBar (Hub): [Back (neutral)]**

**Scrollable Field → suppresses swipe-up App Drawer.** Must verify at UAT: swipe up inside
the list does NOT open the App Drawer.

**Landscape (50/50):** Focus = DetailCard (left), Field = ListBlock + FootButtonBar (right).

### ProbeCalibrateScreen — vertical TESTZ columns (D-08, D-09)

**Focus:** probe offset display + live Z value (the existing ProbeFocus content, unchanged in
information — restyled onto tokens; `t.accent` for the current probe offset number).

**Field:** two vertical 3-cell columns side by side (the same motif as MoveScreen):
- **Column 1 (Z-nudge):** Z-up / live-Z readout (Geist Mono, `t.directional.z` outline) / Z-down
- **Column 2 (step selector):** + (increment step) / step readout / − (decrement step)

Z-nudge column outline = `t.directional.z` (Z-plane identity — same color as Move's Z column).
Step column outline = `t.outline` (neutral).

**FootButtonBar (Probe — state-adaptive, D-09):**

| State | Foot buttons |
|-------|-------------|
| Idle, unhomed | [Home All (accent) \| Back (neutral)] |
| Idle, homed, `starting` (inFlight) | [Starting… (disabled, neutral) \| Back (neutral)] |
| Idle, homed, ready | [Start (accent) \| Back (neutral)] |
| Active | [Accept (go) \| Abort (danger/stop)] — Back SUPPRESSED (nav layer BackHandler) |
| Accepted | [amber Save (caution/heat) — ConfirmGuard SAVE_CONFIG restart gate \| Back (neutral)] |

**Back suppression (D-09 — nav layer, not in-screen):**
`BackHandler(enabled = vm.state == Active || starting)` in the `composable<NavDest.CalibrationProbe>`
lambda in AppShell. System Back is swallowed while a session is live. The user must Accept or Abort.

**`starting` state definition (carry verbatim):**
`vm.state == ProbePageState.Idle && ("probe_calibrate" in inFlight || "z_endstop_calibrate" in inFlight)`
— also suppresses Back during the klicky multi-second macro run.

**ConfirmGuard for Remove:** red "cannot be undone" — standard ConfirmGuard with stop intent.

### Orientation rules (all screens)

- **Portrait:** Focus stacks above Field (~40/60). Full-width regions.
- **Landscape:** Focus | Field as 50/50 columns on the single shared grid.
- **U constant through rotation.** Same `uDp` in both orientations.
- **Square content (JogPad) must render square in both orientations.** D-03 portrait cap (60% height)
  + landscape fill-height achieves this — do not flatten the portrait layout.
- **Rotation does NOT reset ephemeral UI state** (selected profile, selected routine, field mode).
  Use `rememberSaveable` or hoist to holder scope for any state that must survive rotation.

## Navigation Contract

### D-07: Calibration sub-nav converts to real NavDest routes (Option A)

Six new `@Serializable data object` NavDest members added to the sealed interface:

```kotlin
@Serializable data object CalibrationHub        : NavDest
@Serializable data object CalibrationProbe      : NavDest
@Serializable data object CalibrationBedMesh    : NavDest
@Serializable data object CalibrationScrewsTilt : NavDest
@Serializable data object CalibrationZTilt      : NavDest
@Serializable data object CalibrationQgl        : NavDest
```

`NavDest.Calibration` is REMOVED/RENAMED to `CalibrationHub`. `knownNavDests` gains all 6 members.

**FOOT_GUN_DESTS must cover ALL 6 calibration NavDest members + Move:**
```kotlin
val FOOT_GUN_DESTS: Set<NavDest> = setOf(
    NavDest.Move,
    NavDest.Extrude,
    NavDest.CalibrationHub,
    NavDest.CalibrationProbe,
    NavDest.CalibrationBedMesh,
    NavDest.CalibrationScrewsTilt,
    NavDest.CalibrationZTilt,
    NavDest.CalibrationQgl,
)
```

A host unit test asserts ALL six calibration sub-dests are in `FOOT_GUN_DESTS`.

`ShellNavState.calibrationRoutine` field is REMOVED. Back-stack management moves to NavHost.

### Back-stack behavior

- **Hub → routine:** `navController.navigate(NavDest.CalibrationXxx)` pushes to back-stack
- **Routine → hub:** system Back or Back button in FootButtonBar calls `navController.popBackStack()`
- **Hub → App Drawer / other:** normal AppShell navigation (hub is itself a top-level destination)
- **Back while probe Active:** SUPPRESSED at AppShell level via `BackHandler(enabled = isActive)`

### Pop-to-root on print start (D-17)

Pre-existing `shouldPopToRoot` predicate fires when print state changes, popping to
`NavDest.WaterfallHome`. All 6 calibration dests + Move are in `FOOT_GUN_DESTS` so the predicate
covers the whole calibration sub-tree. No special handling needed at the screen level.

## Anti-Patterns to Avoid

1. **Gutter rows on rebuilt screens.** Do NOT pass actions to `ScreenScaffold.gutter`. Always `gutter = null` + `FootButtonBar` inside the field lambda.
2. **Raw `MaterialSymbol(name = "…")` for hub routine icons.** Route every glyph through `DinghyIconView(DinghyIcons.XxxToken, …)`.
3. **Keeping full-screen BedMesh dialogs.** `SaveNameDialog` and `LoadSelectorDialog` are deleted entirely. Replace with `MeshFieldMode` sealed class + `when(fieldMode)` in the field lambda.
4. **`rememberCoroutineScope` for DataStore writes.** Composition scope is cancelled on navigation. Use `AppContainer.writeScope.launch { }`.
5. **In-screen BackHandler only for probe back-suppression.** The current pattern (hiding the Back button) does NOT suppress system Back gesture. Add explicit `BackHandler(enabled = isActive)` at the NavHost `composable<NavDest.CalibrationProbe>` level.
6. **`ShellNavState.calibrationRoutine` after D-07.** Once sub-routes are NavDest members, this field must be removed. Grep for `calibrationRoutine` across the entire codebase before declaring migration complete.
7. **Non-equal weight cells in the 3-cell column.** All three cells MUST be `Modifier.weight(1f)`. The center readout must fit in the 1/3 slot — do not compensate with `weight(2f)`.
8. **Auto-picking icons.** Owner law — never.
