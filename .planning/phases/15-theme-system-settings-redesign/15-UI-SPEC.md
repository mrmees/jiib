> Visual and interaction contract for the **Theme System & Settings Redesign** phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a NATIVE ANDROID project (Kotlin + Jetpack Compose + classic-Views hybrid, ADR 0001).** shadcn / React / web-registry concepts are NOT APPLICABLE. The app already has a **complete, canonical, authored design system that SUPERSEDES generic UI research:** `docs/ui_design/` (`CLAUDE.md` philosophy + non-negotiables, `LAYOUT.md` Focus/Field/Gutter grammar, `THEMING.md` token vocabulary + button-intent-by-safety) + `reference/hifi.css` (canonical token/component values) + `images/*.png` (the 10 core-screen mockups), now extended by the generative color system in the sibling repo `../theme_theory/` (`COLOR-SYSTEM.md` + `color.js`).

## Spacing Scale

The design system is **ratio-first** (LAYOUT.md NON-NEGOTIABLE 3: regions/cells/structural gaps are `%`/`fr`/`aspect-ratio`/weight — never absolute px). Settings and the editor sub-page are **FFG-exempt** (a plain `Column.verticalScroll`, the one conventional-Android screen class), so they use a conventional vertical-stack rhythm rather than the FFG grid — but the fixed-dp leaf values below are still the ONLY permitted absolutes, every entry a **multiple of 4**, matching the existing `SettingsScreen`/`AppDrawer` code.

| Token | Value | Usage |
|-------|-------|-------|
| section gap | 8dp | Gap between a `SectionLabel` and its content (matches existing Settings) |
| control gap | 12dp | Gap between sibling controls/rows in a section |
| screen pad | 16dp | Outer screen padding (matches existing Settings `.padding(16.dp)`) |
| swatch gap | 8dp | Gap between swatches in the preset row / generated swatch strip |

**Shape tokens (radii — canonical `THEMING.md` shape tokens, not spacing):**

| Token | Value | Use |
|-------|-------|-----|
| `--r-ctrl` | 16px (`t.rCtrl`) | Buttons, the seed wheel handle ring, pool-slot swatch tiles, control corner radius |
| `--r-card` | 22px (`t.rCard`) | Section card / preview-panel corner radius (if a section is carded) |
| `--r-pill` | 999px (`t.rPill`) | The preset seed swatches and generated swatch-strip chips read as pills/dots |

**Fixed non-spacing absolutes (design-system-sanctioned):** touch floor **≥64dp** (every editor/Settings control, incl. the wheel handle hit area and each pool-slot swatch) · control outline stroke **2dp** · the `--fs` text-size step. These are the LAYOUT.md-permitted fixed values. The **color wheel itself** is sized by its cell's constraining dimension via `aspect-ratio(1f)` (a sacred square/circle — it must render circular, never elliptical); only its **handle** carries a fixed ≥64dp touch floor.

Exceptions: none beyond the design-system-sanctioned fixed values noted above.

## Typography

Type uses **Geist/Geist Mono** sized via `fsSp(baseSp, t.fs)` (the S/M/L `--fs` multiplier, M=1.15 default). **Honor the fsSp floors** — this project has a recurring lesson `[[dinghy-font-sizes-too-small]]` (Claude sizes Dinghy fonts too small everywhere); **do not go below the floors.** Weights are limited to two: **Regular (400)** and **SemiBold (600)** (matches every existing screen — do not introduce a third).

This phase's new/extended Settings + editor surfaces use this hierarchy (all sizes are `fsSp` base values):

| Role | Base size (fsSp) | Weight | Notes |
|------|------------------|--------|-------|
| Screen title (`SectionHeader` "Settings" / "Edit theme") | **22sp** | SemiBold (600) | Geist. The top-of-screen title. Title tier. |
| Section label (`SectionLabel` — "Connection", "Appearance", "Feature toggles", "System", "Presets", "Pool colors") | **20sp** | SemiBold (600) | Geist. The per-section header inside the scroll. |
| Body / row label / button label | **17sp** | Regular (400) / SemiBold on a primary action | Geist. Row labels, toggle labels, `OutlinedControl` button text. Body floor. |
| Hex value / data string (the seed hex, a pool-slot hex) | **17sp** | Regular (400) | **Geist Mono** (a hex is a data value). Body floor. |
| Metadata / sub-label (greyed-placeholder "Coming soon", app version/build, swatch caption, the per-slot edit hint) | **15sp** | Regular (400) | Geist. 15sp metadata floor; ellipsize if long. |

**Not a new text-size decision (documented, not counted):**
- **`OutlinedControl` button label** — **scales to fill** per the component (no fixed size); editor/gutter buttons keep icon+label where present.
- **`MaterialSymbol` glyph render size** — an icon glyph render size (e.g. 40f on a tile, ~24f inline), NOT a text tier.
- **App version/build string** — rendered in **Geist Mono** at the 15sp metadata tier (a version is a data value).

Net new-decision text tiers: **5** (22 / 20 / 17 / 17-mono / 15sp). Line height: Compose defaults tuned by `fsSp` (titles ~1.2, body ~1.4 implicit) — no override. **Do not introduce a third weight.**

## Color

All color routes through **semantic role tokens** (`LocalTokens` / `ThemeTokens` / `THEMING.md`) — **never a raw color literal** (THEME-01). The editor's two carve-outs (below) are the only places a literal/data color is rendered, and both have established precedent. The 60/30/10 framing maps to the token system; the whole point of this phase is that these token *values* are now **seed-generated** (cusp-anchored accent + neutral surfaces + the contrast-ranked pool), but the *roles* are invariant.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (~60%) | `--bg` (`t.bg`) | App/screen background. **Now PURE NEUTRAL (D-16)** — the faint cool tint (`oklch .012` chroma) is dropped; the generator emits a polarity-flipping neutral bg. This **supersedes `THEMING.md`'s `--bg`** value. |
| Secondary (~30%) | `--surface` / `--surface-2` / `--surface-3` (`t.surface`/`t.surface2`/`t.surface3`) | Section cards, the preview panel, swatch wells, the wheel's backing surface. Tiers are now **derived from the generated `surface`** (`tokensFromPalette` lShift), not the old hand-tuned table. |
| Accent (10%) | `--accent` / `--accent-line` / `--accent-soft` (`t.accent`/…) | **Reserved-for list below.** The accent is the **cusp-anchored seed hue** — the editor's primary identity color. |
| Destructive | `--stop` (`t.stop`) | The **Reset** confirmation's destructive button ONLY (clears overrides + poolShift — see Copywriting). |
| Caution | `--heat` (`t.heat`) | **`heat` now means ONLY caution** (D-13/D-2). Used for the **Randomize** button (an unexpected live change → proceed-at-peril, amber). NOT used as a heater-identity color anymore. |
| Success / Back | `--go` (`t.go`) | Green **Back/Done** in the editor gutter (backing out of the editor changes nothing irreversible — Back is green, not red, per THEMING). |
| Data identity | `--pool[i]` (`t.pool`, NEW) | The generated **contrast-ranked data pool**. Rendered in the editor's swatch strip and per-slot override grid; the live consumers are GraphView traces + temp readouts. |
| Directional | `--directional.{temperature,xy,z}` (NEW) | `pool[0..2]` re-tagged by warmth. Live consumers: Move jog-pad outline (`xy`), Z-row outline (`z`), heater identity (`temperature` = `pool[0]`). |
| Muted / faint | `--text-2` / `--text-3` (`t.text2`/`t.text3`) | Sub-labels, greyed forward-entry placeholders, the per-slot edit hint, captions. |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The **active/primary affordance** in the editor — the currently-selected preset swatch's emphasis ring, and the seed wheel's handle (the handle is the one primary "you are picking this" affordance).
2. The **"Edit theme…" forward-entry row** outline in Settings Appearance (the row that pushes the editor).
3. The **selected palette-mode chip** (Colorful/Simple/High-Contrast) — the active selection gets the accent outline + `--accent-soft` fill; the inactive two stay neutral (`--outline`).
4. The **selected dark/light and S/M/L chips** (the existing Appearance pattern — active = `Intent.Accent`, inactive = `Intent.Neutral`).

**Two bounded color carve-outs in the editor (both precedented, both NOT token-purity violations):**
- **Generated swatch strip + pool-slot swatches render their actual generated/overridden color literally.** A swatch's whole job is to *show the palette* — like the Spoolman spool-color detail border (Phase 11) and the macro-author PromptMarkup hex (Phase 12, D-03), these are **theme DATA being previewed**, not chrome. They are baked sRGB `Color` ints from the resolver, surfaced for display. All editor *chrome* (panel bg, headers, button outlines/intents, the wheel ring's backing, captions) stays fully token-routed.
- **The preset seed swatches render their seed color literally** — same carve-out as today's accent picker (`AccentSwatch` in `SettingsScreen.kt`): a seed swatch IS the data being chosen.

**Status-by-color, not a dedicated cell (LAYOUT/SHELL law):** the editor conveys state by color/fill on existing elements (selected swatch ring, override-applied marker, the live retheme itself) — never a new status bar or badge row.

**Pool-wiring visual-consequence rules (D-13/D-16) — pin so the executor can't regress:**
- **Same sensor = same `pool` index everywhere.** The Print-Status nozzle/bed/chamber readout index MUST equal the GraphView trace index MUST equal the heater-scrubber color (canonical order nozzle=`pool[0]`, bed=`pool[1]`, chamber=`pool[2]`, rendered from `pool[0]` down per COLOR-SYSTEM Part II §C). Retire the hand-picked `violet` (→`pool[2]`).
- **Heater identity = `pool[0]` = `directional.temperature`**, NOT `--heat` (which is now caution-only). An amber-free nozzle number must still read as a heater (its color + its label carry identity).
- **Move directional:** jog-pad/XY outline → `directional.xy`; Z-row outline → `directional.z`. (Move's homed/unhomed *status* color + force-move lock shape stay with the follow-on — out of scope.)
- **Consumers wrap `pool[i % pool.size]`** (D-14 cycle-infinitely — a consumer-side wrap, NOT a generator change; the pool is sized exactly to `maxItems`). **`GraphView.MAX_TRACES = 3` is a hard cap** — fine this phase (no printer shows >3 graph traces); flagged for the planner, not changed here.
- **Pure-neutral surfaces (D-16):** do NOT reintroduce a surface tint; `--bg` is the generated neutral.

## New surface — Theme-editor sub-page (FFG-exempt) layout & interaction contract

The one screen with no mockup. It is a **pushed sub-page** off Settings → Appearance (D-10), and — like Settings — it is **FFG-EXEMPT**: a plain `Column.verticalScroll`, token-themed, keyboard-allowed (though the wheel+presets are the chosen affordance; hex entry NOT required, D-06). It does **not** follow Focus/Field/Gutter. It keeps an explicit exit (gutter **Done/Back**, green).

**Section order (top→bottom in the scroll):**

1. **Seed color** — the touch **color wheel/ring** (`Canvas` + `pointerInput`):
   - A hue ring (the generator normalizes L/C to the cusp, so the control primarily picks **hue** — COLOR-SYSTEM §2/§5). A small L/C handle is **optional** (planner discretion; hue-only is the minimum viable control).
   - **Gloved-finger friendly:** the handle has a **≥64dp** touch hit area + a 2dp outline + static glow; the ring is a sacred circle (`aspect-ratio(1f)`, sized by its cell's constraining dimension — must render circular).
   - **Settle-not-stream regen (D-07):** the handle moves freely during the drag (cheap — just repaint the handle, NO color math); the palette **regenerates + rethemes the whole app on lift/settle** only. One `awaitEachGesture` (the `ScrubberPage` WR-01 pattern) — regen on pointer-up. **This protects the Adreno-320 floor from a regen-storm.**
2. **Presets** — a row of **curated preset seed swatches** (validated seeds covering the 90% case, D-06). Each is a pill/dot swatch rendering its seed color (the carve-out); tapping one **lands the seed → regenerates on land** (same settle semantics). The active seed's swatch gets an accent emphasis ring.
3. **Preview** — the **generated swatch strip (D-08):** accent · `pool[0..n]` · the three status colors, each a swatch rendering its actual generated color (carve-out). This is the at-a-glance read of both chrome and data colors. The **live app retheme** (the editor itself sits inside `DinghyTheme`, so the resolver change retints everything live) is the other half of preview — no separate sandbox preview screen.
4. **Pool colors** — the **per-slot data-pool override grid (D-09):** each `pool[i]` is a tappable swatch (≥64dp, its actual/overridden color, 2dp outline). Tapping opens a color picker (reuse the wheel or a swatch grid — planner discretion) to set that one slot → writes `poolOverrides[i]`. An **override-applied marker** (an accent dot/ring on the slot — must not repeat a glyph already on screen) distinguishes overridden slots. **Data-pool slots ONLY** are editable; chrome (accent/surfaces) stays seed-only (D-04). Status-slot editability rides with the follow-on.
5. **Actions** (gutter-style row, but inline since FFG-exempt): **Randomize** (amber `Intent.Warn`) · **Reset** (red `Intent.Danger`, guarded) · **Done/Back** (green `Intent.Go`).

**Button intents (explicit, by SAFETY — THEMING):**

| Editor control | Intent | Token | Why |
|----------------|--------|-------|-----|
| Seed wheel handle / active preset swatch | accent | `--accent`/`--accent-line` | the primary "this is selected" affordance |
| Randomize | **Warn** (amber) | `--heat` | an unexpected live palette change — proceed-at-peril |
| Reset | **Danger** (red) | `--stop` | clears the user's custom overrides — destructive, guarded by `ConfirmGuard` |
| Done / Back | **Go** (green) | `--go` | backing out is non-destructive (changes already persisted live) |
| A pool-slot swatch (override) | Neutral until overridden | `--outline` → accent marker | a setting; override-applied gets an accent marker |
| Palette-mode chip (in Settings, not editor) | active=Accent / inactive=Neutral | `--accent-line` / `--outline` | selection state |

**States to render:**
- **Mid-drag (wheel):** handle tracks the finger; palette **unchanged** (no regen yet); handle shows the in-progress hue.
- **Settled:** on lift/land, regenerate → the whole app (incl. the visible swatch strip) rethemes in one re-emit (apply the full tuple in ONE `ThemeResolver.apply(...)` call — never 3 sequential `set*` calls = 3 flickers; Pitfall 3). Theme-switch flicker handling during the rebind is planner discretion (carried from Phase 14 D-09).
- **Override applied:** the edited pool slot shows its new color + an accent override marker; the swatch strip updates live.
- **Reset confirmed:** overrides + poolShift cleared; swatch strip + app return to the seed-derived/default palette.
- **No looping/breathing animation** (Adreno-320 floor) — static outline + glow only; the retheme is a one-shot cheap transition.

**Suppress swipe-drawer** for the editor sub-page if it grows scrollable (the established scroll-Field rule) — it keeps its explicit gutter exit regardless.

### Reused-surface contracts (pin, don't redesign)

- **Settings hub (`SettingsScreen.kt`) re-organization (D-10/D-11):** stays a flat `Column.verticalScroll`, token-themed, FFG-exempt, keyboard-allowed. Reuse the existing `SectionHeader`/`SectionLabel`/`ProfileRow`/`AddPrinterRow`/`OutlinedControl`/`TokenTextField` grammar **verbatim** — only the section set + order changes. Sections in order: **Printers** (the Phase-14 profile CRUD list — reused 1:1), **Connection** (host/port/key + mDNS form — reused), **Appearance** (dark/light + S/M/L + the **palette-mode chip row** + the **"Edit theme…"** forward-entry row that pushes the editor), **Feature toggles** (webcam live; outputs/WebRTC/fine-tune as **greyed capability-gated placeholders** — the established forward-entry tile pattern, faint `--text-3`, disabled, "Coming soon"), **System** (version+build only).
- **Appearance inline vs. pushed (D-10):** the **quick controls** (dark/light, S/M/L, palette mode) sit **inline** in the Appearance section (small enough); the **full seed/pool editor** is **pushed** (wheel + per-slot grid is too big to inline). The "Edit theme…" row is the seam.
- **Palette-mode selector (D-15):** a row of three `OutlinedControl` chips ("Colorful"/"Simple"/"High contrast"), active = `Intent.Accent` + `--accent-soft`, inactive = `Intent.Neutral` — mirrors the existing dark/light + S/M/L chip rows exactly. Default = **Colorful**. (The *visual effect* of Simple/High-Contrast — mono pool, RYG status — is engine output, not new chrome; the High-Contrast *status* rendering proper rides with the shape-status follow-on, but the mode **selector** ships now and the engine honors `simple`/`highContrast`.)
- **Accent picker REMOVED:** the old single-accent `AccentSwatch` override (`SettingsScreen.kt`) is **replaced** by the seed model (D-04 retires per-role `TokenDelta` chrome overrides) — accent now derives from the seed. Do not keep the old accent-swatch row.
- **Pool-wired data surfaces** (GraphView, Print-Status/Temp readouts, Move outlines): **visual consequence only** — the token *values* flip to pool/directional colors per the rules in the Color section. No new components, no layout change. Same-sensor-same-index identity is the load-bearing rule.
