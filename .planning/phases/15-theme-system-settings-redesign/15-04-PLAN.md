<objective>
Rewire `ThemeResolver` from baked-table-lookup to a runtime generate-and-cache model: `recompute()` calls `Palette.generate()` then `TokenBridge.build()` once per discrete change, caches the result on the UNCHANGED `StateFlow<ThemeTokens>` boundary, adds the seed/mode/pool API, demotes `BakedTokens` to a fail-safe snapshot, and constructs with the validated default seed. **The old per-role `TokenDelta` API (`TokenDelta`/`Role`/`setBase`/`setDeltas`/`setFs`/top-level `resolve(base,deltas,fs)`/3-arg `apply(base,deltas,fs)`) is NOT hard-deleted here — it is kept as thin `@Deprecated` bridge shims so every existing consumer (GalleryScreen + the theme/prompt/config tests) keeps compiling at this wave boundary.** The hard delete + obsolete-test cleanup happens in 15-06 when SettingsScreen/GalleryScreen are rebuilt (D-04 is a TWO-STEP retirement, completed by phase end).

Purpose: This is the substrate seam that makes everything "extended not rewritten" — Compose `DinghyTheme` and Views `ThemeableView` consume the same `StateFlow<ThemeTokens>` untouched. The render loop reads CACHED Color ints; the device never does color math (Adreno-320 floor). Gradle compiles the WHOLE main AND test sourcesets before any `--tests` filter, so a hard symbol delete at THIS wave (with GalleryScreen + ~5 test files still referencing it) would brick `:app:compileDebugKotlin`/`:app:testDebugUnitTest` for every plan. The deprecated-shim bridge keeps both sourcesets green until the rebuild wave removes the call sites.
Output: rewired `ThemeResolver.kt` (new API + deprecated shims), demoted `BakedTokens.kt`, extended `ThemeResolverTest`.
</objective>
