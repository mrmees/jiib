<objective>
Tie it all together (SHELL-01): the swipe-up full-screen **App Drawer** (D-14) of square tiles
(Status + Settings live; Move/Temp/Files/Tools/Macros/Devices + red Power greyed "coming soon"),
the `AppShell` host that renders the active destination full-bleed with no persistent chrome, and
the grown-up `MainActivity` that hosts the whole UI in one `DinghyTheme` boundary, starts the
foreground service, and drives top-level routing — splash hard-override, Print Status home, Settings.

Purpose: The app becomes navigable and whole — one screen at a time, full canvas, swipe up for the
drawer, no enterprise chrome — exactly the `docs/ui_design/` shell model.

Review fixes applied to the original plan (concern #2 + #11 — top-level routing has no single source
of truth): collapse routing to ONE root controller. A small `RootController` composable (hosted by
MainActivity) is the SOLE place that consumes `derive()` and decides Splash vs Shell, AND owns the
ONE "open Settings outside the Shell" escape state (used by first-run/Connect and by the Splash
"Set up / Edit connection" actions). Splash and AppShell NEVER navigate themselves: Splash emits an
`onEditConnection` event the RootController handles; AppShell hosts Settings as a normal
`Dest.Settings`. This removes the original's dangling `onOpenSettings`-vs-`Dest.Settings` ambiguity
(concern #11): there is exactly one open-Settings path, owned by the root.
Output: `ui/shell/RootController.kt`, `ui/shell/AppDrawer.kt`, `ui/shell/AppShell.kt`, rewritten
`MainActivity.kt`, and an instrumented `ShellPresenceTest`.
</objective>
