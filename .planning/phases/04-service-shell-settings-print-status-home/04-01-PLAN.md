<objective>
Create the persisted connection model and store that replaces the static `DevConfig` as the
runtime config SOURCE (D-04, CONN-01), plus the additive best-effort mDNS discovery utility
(D-04). This is the persistence floor everything downstream connects through: the foreground
service (04-03) collects `ConnectionStore.config` to build/rebuild the spine, and the Settings
screen (04-04) writes to it.

Purpose: User can enter and save their Moonraker connection and have it survive restarts —
replacing the hardcoded Phase-2 dev config — with input validated and the API key never logged.
Output: `ConnectionConfig` (model), `ConnectionStore` (DataStore + pure sanitize), `MoonrakerDiscovery`
(lazy NsdManager scan), and a host-side `ConnectionStoreTest`.

Review fixes applied to the original plan:
- **#5 (mDNS premature/eager):** D-04 locks mDNS IN-SCOPE (additive scan; manual entry is the
  floor). Keeping it, but making the discovery machinery FULLY LAZY — `MoonrakerDiscovery`
  acquires no NsdManager/multicast lock and registers no listener at construction; all of that
  happens only inside `discover()` on collect, and is released on `awaitClose`.
- **#12 (config-cleared-while-running):** `ConnectionStore.clear()` must make `config` emit null
  so the 04-03 service idles cleanly with no leaked connection and routing returns to Connect.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → ConnectionStore | host/port/key typed in Settings cross into persisted prefs (untrusted text) |
| LAN mDNS → MoonrakerDiscovery | service-discovery responses from the local network (untrusted advertisers) |
| stored API key → disk | optional Moonraker key persisted plaintext-at-rest in DataStore on the device |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-I | Information Disclosure | ConnectionConfig / ConnectionStore | mitigate | `ConnectionConfig.toString()` redacts apiKey to `***`; key never logged (asserted in test); the key DataStore is a separate `connection.preferences_pb` from theme prefs |
| T-04-01-T | Tampering | ConnectionStore.sanitize | mitigate | pure sanitize() rejects blank host + port outside 1..65535 before any persist; trims host |
| T-04-01-S | Spoofing | MoonrakerDiscovery (mDNS) | accept | a malicious LAN advertiser could surface a fake host; user explicitly picks/edits the host before connecting, manual entry is the floor, local-LAN trusted posture — low value, no auto-connect to discovered hosts |
| T-04-01-DoS | Denial of Service | MoonrakerDiscovery | mitigate | empty/failed scan is a normal no-op; machinery acquired only on collect and released on awaitClose so a scan can't pin the radio; listener failure callbacks never rethrow |
</threat_model>
