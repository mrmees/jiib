<objective>
Build the conventional Settings screen (SET-01) — the ONE screen exempt from the Focus/Field/Gutter
grammar (D-15) and the ONLY place the system keyboard is allowed (PRIM-02). It owns connection
entry (host/port/optional key + an mDNS scan button, CONN-01/D-04), the theme controls, and the
accent picker (D-16). Saving connection writes `ConnectionStore`, which drives the service rebuild
(04-03, D-03).

Purpose: The user can finally type in their printer's address and pick a theme — the last piece of
"install an APK, point it at the printer."
Output: `ui/screen/TokenTextField.kt` (token-aware field wrapper), `ui/screen/SettingsScreen.kt`
(a scrollable token-themed Compose list).

Review fixes applied to the original plan:
- **#7 (Material vs token system):** a thin `TokenTextField` wrapper maps Material3
  `OutlinedTextField` colors/typography to `LocalTokens` so Settings does not drift off the Phase-3
  theme. All connection fields use it (no bare OutlinedTextField for chrome).
- **#10 (key-saved affordance):** the key edit field is blank on load (never the secret), but a
  non-secret "key saved" indicator shows when a key is already stored.
- **#12 (no-clobber / clear-key):** saving with the key field left blank PRESERVES the saved key; a
  distinct "Clear key" action explicitly removes it.
</objective>
