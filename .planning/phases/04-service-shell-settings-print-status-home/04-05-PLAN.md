<objective>
The splash/recovery surface — a hard override (no App Drawer reachable) shown during klippy
startup/error/shutdown and first-run. Surfaces klippy reason text + self-contained recovery
actions (D-11/D-12/D-13): first-run setup prompt, retry, firmware_restart, host restart.

Purpose: SHELL-05 — the splash is the only escape hatch when klippy is down, so every
recovery action must live here.

This revision resolves two review concerns:
- **#8 (Klippy detail):** the current `PrinterState` has NO status/message field for klippy
  (only `PrintStats.message`, which is a print-cancel reason). This plan adds a nullable
  `klippyStateMessage: String?` to `PrinterState`, populated by the reducer from the
  `notify_klippy_shutdown` / `printer.info` `state_message` field, so the splash shows the real
  Moonraker/Klippy recovery message the context (D-12) calls for — not just the enum name.
- **#1 (SessionControl):** recovery actions go through the SAME `SessionControl` contract
  defined in 04-03 (`requestReconnectNow()`, `restartFirmware()`, `restartHost()`) — the splash
  never touches a raw `MoonrakerSession`.
Output: `PrinterState`/`PrinterStateReducer` change, `SplashScreen`, `SplashViewModel`.
</objective>
