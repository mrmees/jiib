<objective>
Build the splash/initializing surface (SHELL-05) — a **hard override** with no reachable App Drawer
(D-06), so EVERY escape hatch must live on the splash itself or the user is trapped. It covers the
three trapped states: first-run/no-config (D-11 → Settings), Klippy shutdown/error with Moonraker
reachable (D-12 → Retry + firmware_restart + restart), and a saved-but-failing connection (D-13 →
Retry + Edit connection). This is the recovery surface the E-stop (04-06) lands on when it drives
`klippy_state → shutdown`.

Purpose: A printer that's starting up, shut down, or unreachable never leaves the user stranded — the
exact recovery action is always one tap away on the screen they're stuck on.
Output: a `PrinterState`/`PrinterStateReducer` change (the klippy message field) and
`ui/screen/SplashScreen.kt`.

Review fixes applied to the original plan:
- **#8 (splash loses Klippy detail):** the current `PrinterState` has NO klippy message field — the
  splash could only show enum-derived text. The reducer ALREADY reads `webhooks.state` (and notes
  `webhooks.state_message` carries the human reason). This plan adds a nullable
  `klippyStateMessage: String?` to `PrinterState`, populated from `webhooks.state_message`, so the
  splash shows the real Moonraker/Klippy recovery message D-12 calls for. (Verified the Phase-2
  shape: only `PrintStats`-style fields exist; no state-message field present — confirmed in
  PrinterState.kt and the reducer's webhooks block.)
- **#1 (SessionControl):** Retry/firmware/host-restart go through the SAME narrow `SessionControl`
  contract (04-03) — the splash never touches a raw `MoonrakerSession`.
</objective>
