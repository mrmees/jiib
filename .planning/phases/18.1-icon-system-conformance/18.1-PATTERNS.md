## Pattern Assignments

### 1. `res/drawable/disabled_by_default.xml` + `res/drawable/warning.xml` (CREATE — authored official-vector)

**Analog:** `app/src/main/res/drawable/detector.xml` (an existing official Google Material Symbols vector
already in the repo). Confirmed structure (full file, verified):

```xml
<!--
  Material Symbols Outlined "detector" glyph ... Source SVG uses the Material Symbols 960 viewBox with
  a -960..0 Y range, so the path is wrapped in a group translated +960 into Android's 0..960 viewport.
  Filled white, recolored at runtime via Compose Icon(tint = …) (THEME-01).
-->
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="24dp"
    android:height="24dp"
    android:viewportWidth="960"
    android:viewportHeight="960">
    <group android:translateY="960">
        <path
            android:pathData="M480,-120q-88,0 ... Z"
            android:fillColor="#FFFFFFFF" />
    </group>
</vector>
```

**The template contract to copy EXACTLY when authoring the two new vectors:**
- `android:width="24dp"` / `android:height="24dp"` / `viewportWidth="960"` / `viewportHeight="960"`.
- A single `<group android:translateY="960">` wrapper (the Material Symbols `-960..0` Y range → Android
  `0..960` viewport convention). `text_select_move_forward_word.xml` uses the identical wrapper — both
  in-repo official vectors confirm this is THE established convention.
- `android:fillColor="#FFFFFFFF"` (white fill — recolored at the call site via `DrawableCompat.setTint`;
  THEME-01). Do NOT bake a status hex.
- A header comment in the `text_select_move_forward_word.xml` style: "OFFICIAL Google vector
  (google/material-design-icons), path data verbatim, NOT hand-traced."

**Where to get the path data (RESEARCH A3):**
`github.com/google/material-design-icons` → `symbols/android/<name>/materialsymbolsoutlined/<name>_24px.xml`
— published as ready Android `<vector>` drawables (no SVG conversion). Use the FILL0/wght400/GRAD0/24px
variant for `warning` and `disabled_by_default`. Path data goes in verbatim.

**Naming:** use bare `disabled_by_default.xml` / `warning.xml` (matches `detector.xml` /
`text_select_move_forward_word.xml` official-vector naming), NOT an `ic_` prefix.

### 4. Raw Compose call-site swaps — `ProbeCalibrateScreen.kt` / `MoveScreen.kt` / `ThemeEditorScreen.kt`

**Analog for the swap target:** `MaterialSymbol.kt:31` (`MaterialSymbol(name, tint, sizeSp)`) and
`DinghyIconView.kt:39` (the a11y-aware wrapper). There is **no pre-existing in-repo example of a raw
`painterResource(R.drawable.*)` site already converted to a ligature** — Phase 18 added the registry but
left these raw sites on drawables. So the swap pattern is derived from the render primitives, per
RESEARCH "Pattern: raw Compose call-site swap".

**RESEARCH recommendation (apply uniformly):** for raw sites that pass a real `contentDescription`, use
`DinghyIconView(DinghyIcon(IconRef.Ligature("name"), alternate="…"), contentDescription=…)` inline — it
gets TalkBack handling for free WITHOUT a registry entry (D-09: do not promote raw sites to the registry).
For decorative sites (`contentDescription = null`), a bare `MaterialSymbol(name=…, tint=…, sizeSp=…)` is the
minimal swap.

⚠ **Sizing (Pitfall 5):** preserve the existing magnitude. Drawable sites use `Modifier.size(...)` /
`weight().aspectRatio(1f)`; the ligature path sizes via `sizeSp`/`sizeDp` (`MaterialSymbol` pins
`fontScale=1f` so dp↔sp is 1:1). Do NOT silently shrink.

**Per-site, verified current call sites:**

`ProbeCalibrateScreen.kt` — uses `Icon(painter = painterResource(...))` (lines 331-348) for the
detector/expand/nozzle row, and `ProbeIconButton(painter = painterResource(...))` (lines 411-447) for the
jog pad. Note `ProbeIconButton` takes a `painter: Painter` parameter (:483) — converting its call sites to
ligatures requires either changing that param to accept a ligature name / `DinghyIcon`, OR rendering the
ligature inside the button. Swap targets:
- `:332 R.drawable.detector` → `detector` (cd="Probe", tint=t.text2)
- `:338 R.drawable.expand` → `expand` (cd="Z offset")  [keep nozzle.xml at :344 — D-10 custom]
- `:412 R.drawable.add` → `add` (cd="Larger step", via ProbeIconButton)
- `:421 R.drawable.remove` → `remove` (cd="Smaller step")
- `:432 R.drawable.arrow_upward` → `arrow_upward` (cd="Raise nozzle (TESTZ +)")
- `:441 R.drawable.arrow_downward` → `arrow_downward` (cd="Lower nozzle (TESTZ -)")

`MoveScreen.kt` — renders status drawables through a local `StatusShape` composable (:447-455) that wraps
`Icon(painter=painterResource(resId), tint, size(sizeSp.dp))`. `StatusShape` takes `resId: Int`; to convert
to ligatures, either change `StatusShape` to take a ligature name, or replace its body with `MaterialSymbol`.
Swap targets:
- `:425 R.drawable.ic_status_triangle` (StatusShape, unhomed caution) → `warning`
- `:481 if (enabled) R.drawable.ic_lock_open else R.drawable.ic_lock_closed` (ForceMoveCell) →
  `lock_open_right` / `lock` respectively

`ThemeEditorScreen.kt` — `DataSwatch(..., glyph: Int? = null)` takes a `@DrawableRes glyph` param (:535).
Swap targets (these are status PREVIEW swatches):
- `:377 glyph = R.drawable.ic_status_octagon` → `disabled_by_default`
- `:378 glyph = R.drawable.ic_status_triangle` → `warning`
- `:627 StatusSlot.Stop -> R.drawable.ic_status_octagon` → `disabled_by_default`
- `:628 StatusSlot.Caution -> R.drawable.ic_status_triangle` → `warning`

⚠ The `DataSwatch`/`StatusShape`/`ProbeIconButton` helper signatures currently take `Int`/`Painter`. The
planner must decide per-helper: (a) change the helper's param to a ligature name / `DinghyIcon`, or
(b) keep the helper and convert at the call site. Whichever — the underlying render target is `MaterialSymbol`.

## Shared Patterns

### THEME-01 (white-fill + tint-at-call-site) — applies to ALL converted glyphs
**Source:** `detector.xml` header (`android:fillColor="#FFFFFFFF"`, recolored at runtime) +
`MaterialSymbol.kt:34` (`tint: Color = LocalTokens.current.text`) + `ConsoleRowsAdapter.kt:214`
(`DrawableCompat.setTint(d, tint)`).
**Apply to:** every authored vector (white fill) and every ligature swap (preserve the existing `tint=` /
`setTint` argument). NEVER bake a status hex into the new vectors.

### The drawable→ligature flip shape
**Source:** `DinghyIcons.kt` — existing `IconRef.Ligature(name)` entries (e.g. `:74 FanMode`, `:82
KeyboardReturn`) vs the `IconRef.Drawable(R.drawable.*)` entries being flipped.
**Apply to:** the six registry flips (D-15).

### Sizing preservation (`fsSp` / `sizeSp` / `sizeDp`)
**Source:** `MoveScreen.StatusShape` (`size(sizeSp.dp)`, fed `fsSp(20f, t.fs)` / `fsSp(40f, t.fs)`);
`DinghyIconView.dpToSp` (1:1 under `fontScale=1f`). Memory `dinghy-font-sizes-too-small`.
**Apply to:** every Compose swap — keep the existing magnitude; do not shrink.

### Completeness via the compiler (RESEARCH "Completeness guarantee")
**Source:** typed `R.drawable.*` references. A deleted drawable with a missed call site = compile error,
not runtime tofu. **Apply to:** delete each drawable ONLY after its call sites are converted; lean on
`:app:assembleDebug` as the deletion-completeness check.
