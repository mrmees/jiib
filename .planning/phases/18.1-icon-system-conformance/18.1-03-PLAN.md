<objective>
Swap the raw (non-registry) Compose call sites for the converted drawables from
painterResource(R.drawable.*) to the Material Symbols ligature render path — a pure glyph-SOURCE swap.
Per D-09 these raw sites are NOT promoted into the DinghyIcons registry and NOT string-extracted (Phase 22
owns that); the change is source-only. Three files, disjoint from Plan 02's file set so this runs in
parallel in Wave 1:

1. ProbeCalibrateScreen.kt (6 sites): detector, expand, add, remove, arrow_upward, arrow_downward ->
   ligatures. KEEP nozzle (D-10 custom). add/remove/arrows go through the local ProbeIconButton(painter:)
   helper — see the per-helper decision below.
2. MoveScreen.kt (3 sites): unhomed-caution StatusShape(resId=ic_status_triangle) -> warning; ForceMoveCell
   lock if(enabled) ic_lock_open else ic_lock_closed -> lock_open_right / lock. StatusShape takes resId: Int.
3. ThemeEditorScreen.kt (4 sites): status-preview swatches ic_status_octagon -> disabled_by_default (x2),
   ic_status_triangle -> warning (x2). DataSwatch(glyph: Int?) + the StatusSlot when take a @DrawableRes Int.

Render-target rule (RESEARCH "Pattern: raw Compose call-site swap" + PATTERNS section 4): sites passing a
REAL contentDescription use the inline DinghyIconView(DinghyIcon(IconRef.Ligature("name"), alternate="..."),
contentDescription=..., tint=..., sizeDp=...) form (TalkBack handling for free, NO registry entry).
DECORATIVE sites (contentDescription = null) use a bare MaterialSymbol(name=..., tint=..., sizeSp=...).
Apply ONE convention uniformly.

Per-helper signature decision (PATTERNS section 4 flags ProbeIconButton(painter:), StatusShape(resId:),
DataSwatch(glyph: Int?) take drawable types): for EACH helper, EITHER change its parameter to accept a
ligature name (glyphName: String / DinghyIcon) and render the ligature internally, OR keep the helper and
convert at the call site — whichever is the smaller, cleaner diff. Document the choice per helper in the
SUMMARY. The render target is always the ligature path.

Sizing (Pitfall 5): preserve the existing magnitude at EVERY site (drawable sites use Modifier.size /
weight().aspectRatio(1f) / fsSp; the ligature path sizes via sizeSp/sizeDp, fontScale pinned 1f, dp-to-sp
1:1). Do NOT shrink. THEME-01: preserve each site's existing tint= argument. Do NOT delete any drawable
here (Plan 04). Do NOT touch nozzle (D-10).

PRE-FLIGHT: python tools/verify_ligatures.py must print missing: [] before swapping.
Output: every raw status/lock/arrow/detector/add/remove/expand Compose site renders a real ligature.
</objective>
