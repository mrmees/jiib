# Phase 18.1 Plan 01: Wave-0 Tooling & Assets Summary

Landed the Wave-0 ligature gate, two official status vectors, and an additive drift-guard test that every downstream 18.1 drawable→ligature flip and deletion depends on — WITHOUT touching any existing call site or deleting any drawable. `verify_ligatures.py` exits 0 (`missing: []`); `:app:assembleDebug` is green.

## What Was Built

**Task 1 — `tools/verify_ligatures.py` (D-04, D-13).** A fonttools-based, device-free gate that opens the bundled `material_symbols_outlined.ttf`, traverses the GSUB `LookupList` (unwrapping LookupType 7 Extension subtables), collects every `LigGlyph` from LookupType 4 (LigatureSubst), and asserts the `NEEDED` set (every current `IconRef.Ligature` name + the 13 D-08 targets) is a subset, printing `… missing: []` and `sys.exit(1 if missing else 0)`. Uses `text_select_move_forward_word` WITH the `_word` suffix (the font carries `_word`; the bucket bookmark dropping it is stale — RESEARCH A2 / D-15). bake_tokens.py-style header (`#!/usr/bin/env python3`, `WHY THIS EXISTS`, `USAGE (WSL python 3.13)`).

Run result: `48 needed, 3953 ligatures in font, missing: []`, exit 0.

**Task 2 — `disabled_by_default.xml` + `warning.xml` (D-05, D-07).** Official Google Material Symbols Outlined vectors, path data verbatim from `google/material-design-icons` (FILL0/wght400/GRAD0/24px variant). Match the `detector.xml` template exactly: `24dp`, `viewport 960×960`, a single `<group android:translateY="960">`, `fillColor="#FFFFFFFF"` (recolored at the call site via `DrawableCompat.setTint`; THEME-01, no status hex baked). Header comment marks them OFFICIAL + verbatim + NOT hand-traced, and flags them as KEEPERS for the single classic-Views status site (`ConsoleRowsAdapter` ERROR/WARNING rows) where a font ligature is not viable on the minSdk-23 floor (`setFontVariationSettings` is API 26+). Shape-distinct (square+✕ vs triangle+!) safety coding preserved, not the literal octagon (D-06).

**Task 3 — `registryDrawableEntries_areOnlyTheCustomKeepers()` drift-guard (D-15, SC-3b).** One additive `@Test` filtering `DinghyIcons.all` for `IconRef.Drawable` entries, mapping `it.alternate`, and asserting the set equals `setOf("nozzle", "heat_bed")`. Goes GREEN once Plan 02 flips the six registry entries; the other two tests in the class stay GREEN. `DinghyIcons.kt` was NOT modified in this plan. `:app:assembleDebug` (Windows helper) → BUILD SUCCESSFUL with the two new drawables + the new test method (Wave-0 build gate).

## Deviations from Plan

**None affecting behavior.** One authoring choice worth recording (not a plan departure):

- **Official-vector path-data form.** The newer upstream `symbols/android/<name>/materialsymbolsoutlined/<name>_24px.xml` exports now use a `0..960` positive-Y viewport with `@android:color/white` fill and a `colorControlNormal` tint attr — which would NOT need the `translateY="960"` group. To match the in-repo template contract EXACTLY (the `detector.xml`/`text_select_move_forward_word.xml` `-960..0` + `+960` translate convention, `#FFFFFFFF` fill, no tint attr), the verbatim path data was taken from the upstream `materialsymbolsoutlined` SVG (`viewBox="0 -960 960 960"`, negative-Y) and wrapped in the `+960` group — the established in-repo pattern. Path data is still verbatim from `google/material-design-icons`; only the coordinate-range variant was chosen to match the template.
