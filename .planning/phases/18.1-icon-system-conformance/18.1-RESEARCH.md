## Summary

The decisive, somewhat surprising finding: **the font already in the repo carries every glyph this phase needs.** The bundled `app/src/main/res/font/material_symbols_outlined.ttf` is **Material Symbols Outlined v2.944**, the full **variable** font (10,600,212 bytes ≈ 10.6 MB), with axes `FILL 0..1`, `wght 100..700`, `GRAD -50..200`, `opsz 20..48` — exactly the locked D-02 axis space. I inspected its GSUB table directly with fonttools: it contains **4,253 resolvable ligatures**, and **all 13 D-08 conversion targets plus all 35 already-used ligatures resolve** — `disabled_by_default`, `warning`, `compress`, `expand`, `detector`, `lock`, `lock_open_right`, `add`, `remove`, `arrow_upward`, `arrow_downward` are every one present as a true ligature. The only name that does NOT resolve is the bucket's `text_select_move_forward` — because the font carries it as **`text_select_move_forward_word`** (with the `_word` suffix). That settles the D-08 name discrepancy: the existing drawable name is correct, the bucket bookmark is the stale/wrong one.

Practical consequence for the planner: **D-01 (font refresh) is technically a no-op for correctness** — no glyph the phase converts is missing from the bundled cut. A refresh is still defensible as hygiene (pin a known upstream version for reproducibility, future-proof Phase-22 subsetting), but it MUST NOT be allowed to silently re-introduce the `text_select_move_forward` vs `_word` ambiguity or drop `opsz` range. If you refresh, re-run the ligature-resolution check (below) against the new binary before deleting any drawable. If you skip the binary swap, the phase still satisfies every D-04/D-08 dependency. Recommend: **refresh + pin to a recorded upstream commit, gate the swap behind the automated ligature check, then proceed with conversions.**

The D-07 render split resolves cleanly: only **one** call site renders status glyphs in classic Views — `ConsoleRowsAdapter` (a `TextView` using `setCompoundDrawables` + `DrawableCompat.setTint`). Every other status/lock/arrow/etc. call site is Compose (`Icon(painterResource)` / `MaterialSymbol`). The clean rule: **Compose call sites → font ligature; the single Views compound-drawable call site → official Google vector drawable.**

**Primary recommendation:** Refresh + pin the font (optional but advised), then run the automated ligature-resolution gate; flip the four registry entries `Drawable→Ligature`; swap the raw Compose call sites to `MaterialSymbol`/`DinghyIconView` ligatures; keep `disabled_by_default`/`warning` as **official vector drawables for the one Views console row only**; delete superseded drawables once unreferenced; fix two (not three) KDoc link symbols.

  `https://raw.githubusercontent.com/google/material-design-icons/<COMMIT_SHA>/variablefont/MaterialSymbolsOutlined%5BFILL,GRAD,opsz,wght%5D.ttf`

### A2 — Post-refresh ligature resolution (D-04): how to verify, what becomes a ligature

**The name discrepancy is resolved:** the font carries **`text_select_move_forward_word`** (the existing drawable's exact name) and does **NOT** carry `text_select_move_forward` (the bucket bookmark). So `DinghyIcons.PressureAdvance` should become `IconRef.Ligature("text_select_move_forward_word")` — keep the `_word` suffix, ignore the bucket's truncated bookmark. `[VERIFIED: fonttools GSUB — text_select_move_forward absent, text_select_move_forward_word present]`

**Glyphs that previously had to ship as official vectors and CAN now be ligatures (all confirmed present):**
- `detector` ✓ (drawable `detector.xml` was an official MS vector; now redundant — flip to ligature)
- `text_select_move_forward_word` ✓ (drawable `text_select_move_forward_word.xml` was official; now redundant)
- `expand` ✓, `compress` ✓, `disabled_by_default` ✓, `warning` ✓, `lock` ✓, `lock_open_right` ✓, `add` ✓, `remove` ✓, `arrow_upward` ✓, `arrow_downward` ✓

**Device-free verification method (recommended — bake into CI/test, not just a one-off):**
fonttools is the right tool and is already pip-installable in this env. The reliable check is GSUB ligature-output traversal (glyph-name-present is necessary but the ligature-output set is the authoritative "renders by typing the name" test). Reference script the planner can drop into `tools/` or a test fixture:

```python
# tools/verify_ligatures.py  (run with: python tools/verify_ligatures.py)
from fontTools.ttLib import TTFont
import sys
FONT = "app/src/main/res/font/material_symbols_outlined.ttf"
def resolvable_ligatures(path):
    f = TTFont(path); gsub = f["GSUB"].table; out = set()
    def subtables(lk):
        for st in lk.SubTable:
            if lk.LookupType == 7:  # Extension
                yield st.ExtensionLookupType, st.ExtSubTable
            else:
                yield lk.LookupType, st
    for lk in gsub.LookupList.Lookup:
        for lt, st in subtables(lk):
            if lt == 4:  # LigatureSubst
                for _first, ligs in st.ligatures.items():
                    for lg in ligs:
                        out.add(lg.LigGlyph)
    return out
NEEDED = {  # every IconRef.Ligature(...) name currently in DinghyIcons + every D-08 target
  "arrow_back","check","edit","instant_mix","height","altitude","layers","scale","storefront",
  "timer_arrow_down","timer_arrow_up","donut_large","pause_circle","inventory_2","palette",
  "calendar_add_on","check_circle","archive","print_connect","thermostat","open_with",
  "output_circle","tune","database","bolt","terminal","more_horiz","mode_fan","speed",
  "keyboard_return","arrow_shape_up_stack_2","sprint","directions_boat","rounded_corner",
  "avg_time","input_circle",
  # D-08 conversion targets:
  "disabled_by_default","warning","compress","expand","detector","lock","lock_open_right",
  "add","remove","arrow_upward","arrow_downward","text_select_move_forward_word",
}
have = resolvable_ligatures(FONT)
missing = sorted(NEEDED - have)
print(f"{len(NEEDED)} needed, {len(have)} ligatures in font, missing: {missing}")
sys.exit(1 if missing else 0)
```
Running this against the **current** bundled font prints `missing: []` (verified). After any refresh, re-run; non-empty `missing` blocks the swap.

### A3 — The D-07 render split (the key technical question) — RESOLVED

**Finding: there is exactly ONE classic-Views status-glyph call site.** A full grep shows `DrawableCompat.setTint` / compound-drawable rendering appears only in
`app/src/main/java/works/mees/dinghy/ui/console/ConsoleRowsAdapter.kt` (`applySeverityGlyph`, lines ~196–222). It is a `TextView` (`AppCompatTextView`) that attaches the glyph as a **leading compound drawable** via `setCompoundDrawables(d, null, null, null)` with explicit `setBounds` (deliberately NOT `…WithIntrinsicBounds`, to avoid the 96dp intrinsic blowing up row height), tinted by `DrawableCompat.setTint(d, paletteArgbInt)`. `[VERIFIED: grep + file read]`

Every other status / lock / arrow / babystep / detector / add / remove call site is **Compose** (`Icon(painterResource(...))` or `MaterialSymbol`): MoveScreen `StatusShape`/`ForceMoveCell`, ThemeEditorScreen `DataSwatch`/status preview `Icon`, ProbeCalibrateScreen `Icon(painterResource)`. `[VERIFIED: grep of all R.drawable.* call sites]`

**(a) Where to get official vector path data for `disabled_by_default` / `warning`:**
- `github.com/google/material-design-icons`, per-icon vector at:
  `symbols/android/<icon_name>/materialsymbolsoutlined/<icon_name>_<weight>_<grade>_<opsz>px.xml`
  (Android `<vector>` drawables are published directly — no SVG→vector conversion needed). For the locked axes use the FILL0 / wght400 / GRAD0 / 24px variant.
  Example: `symbols/android/warning/materialsymbolsoutlined/warning_24px.xml` and
  `symbols/android/disabled_by_default/materialsymbolsoutlined/disabled_by_default_24px.xml`.
- These are the same -960..0 viewBox path convention the existing official drawables (`detector.xml`, `text_select_move_forward_word.xml`) already use, so the import pattern is established in-repo (wrap in a +960 translate group, white fill, tint at call site). `[CITED: github.com/google/material-design-icons/tree/master/symbols/android]`

**(b) Can a Material-Symbols ligature be cleanly rendered + tinted in a classic TextView?**
Yes, but with real friction on this project's render path:
- The console row is ALREADY a `TextView` whose `text` is the log line in **GeistMono**. The status glyph is a **leading compound drawable**, not text. To make it a font ligature you would have to either (i) prepend the ligature char to the text with a `Spannable` swapping `fontFamily`/`typeface` to Material Symbols for that one char + apply a `ForegroundColorSpan` for the tint, or (ii) render it in a separate sibling `TextView`/`ImageView`. Option (i) is fiddly (span boundaries, tabular-numeral interplay, per-`--fs` sizing of just that span) and option (ii) restructures the row layout.
- `fontVariationSettings` on a `TextView` requires **API 26+** (`setFontVariationSettings` is API 26). On the API-23 minSdk floor the variable axes can't be set per-call on a TextView — you'd rely on the font's default instance (FILL0/wght400/GRAD0 = the locked axes anyway, so acceptable, but it's a sharp edge). The Compose path sidesteps this because `MaterialSymbol` renders via Compose text with the default axes too.
- Net: a ligature-in-TextView is **possible but strictly more code and more API-floor risk** than the compound-drawable path the row already uses.

**(c) Decisive split rule for the planner:**
> **Compose call sites → font ligature** (`MaterialSymbol` / `DinghyIconView` with `IconRef.Ligature`).
> **The single classic-Views compound-drawable call site (`ConsoleRowsAdapter`) → official Google vector drawable** (`disabled_by_default_24px.xml` / `warning_24px.xml`, path verbatim from material-design-icons), kept as `R.drawable.*` and tinted via the existing `DrawableCompat.setTint` + `setBounds` + `setCompoundDrawables` machinery (zero render-path change — just swap the two `resId`s).

This means the **official vectors `disabled_by_default` and `warning` must be ADDED as drawables** (they replace `ic_status_octagon` / `ic_status_triangle`), and **must be kept** (not deleted) because the Views console row depends on them. The Compose status call sites switch to the ligature and stop referencing the old drawables.

**THEME-01 survival:** preserved on both paths. Compose ligature tints via `MaterialSymbol(tint=token)`; the Views vector tints via `DrawableCompat.setTint(d, paletteArgbInt)` exactly as today. White-fill-recolored-at-call-site holds. The new official vectors must be authored white-fill (matching the existing official-vector convention) so the tint reads.

**Naming suggestion for the new official vectors:** name them by their Material Symbol (`ic_disabled_by_default.xml` / `ic_warning.xml`, or `disabled_by_default.xml` / `warning.xml` to match the official-vector naming already used for `detector.xml`). Pick one convention and apply consistently; recommend the bare `disabled_by_default.xml` / `warning.xml` to match `detector.xml`/`text_select_move_forward_word.xml`.

## Architecture Patterns

### The icon render seam (unchanged by this phase)
```
                          DinghyIcon(primary: IconRef, alternate)
                                       │
                  ┌────────────────────┴────────────────────┐
            IconRef.Ligature(name)                    IconRef.Drawable(resId)
                  │                                          │
   Compose: DinghyIconView → MaterialSymbol            Compose: Icon(painterResource)
            (Text in MaterialSymbols font,             Views:   ConsoleRowsAdapter
             tint via token)                                    setCompoundDrawables +
                                                                DrawableCompat.setTint
```
This phase moves entries/call sites from the right arm to the left arm (drawable→ligature), EXCEPT the one Views console row which keeps a (new, official) drawable on the right arm.

### Pattern: drawable→ligature flip (registry)
```kotlin
// Before
val BabystepExpand = DinghyIcon(IconRef.Drawable(R.drawable.ic_babystep_expand), alternate = "babystep_expand")
// After
val BabystepExpand = DinghyIcon(IconRef.Ligature("expand"), alternate = "babystep_expand")
```

### Pattern: raw Compose call-site swap
```kotlin
// Before (ProbeCalibrateScreen.kt:332)
Icon(painter = painterResource(R.drawable.detector), contentDescription = "Probe", tint = t.text2, modifier = …)
// After — option A (lightest, matches MoveScreen StatusShape style): use MaterialSymbol
MaterialSymbol(name = "detector", tint = t.text2, sizeSp = <existing magnitude>, modifier = …)
// After — option B (preferred for tokenized consistency): route through DinghyIconView with a local DinghyIcon
```
Recommend **option A** for the raw (non-registry) sites — D-09 explicitly says NOT to promote them into the registry this phase; a bare `MaterialSymbol` call is the minimal source swap. Keep `contentDescription` semantics (ProbeCalibrate passes real cd strings — preserve them; `MaterialSymbol` doesn't take cd, so wrap with the `semantics{}` modifier as `DinghyIconView` does, OR use `DinghyIconView` with an ad-hoc `DinghyIcon(IconRef.Ligature(...))` to get the a11y handling for free without registering it in `.all`). **Cleanest: call `DinghyIconView(DinghyIcon(IconRef.Ligature("detector"), alternate="…"), contentDescription="Probe", …)` inline** — gets TalkBack handling, no registry entry. Planner: pick one and apply uniformly across the ProbeCalibrate/Move/ThemeEditor raw sites.

### Anti-patterns to avoid
- **Ligature-in-TextView for the console row.** Don't — `setFontVariationSettings` is API 26+, span juggling is fragile, and the official-vector path is a 2-line resId swap. (A3.)
- **Deleting `disabled_by_default`/`warning` vectors after converting Compose sites.** They are LOAD-BEARING for the Views console row. Keep them.
- **Trusting the bucket bookmark name `text_select_move_forward`.** The font has `_word`. Use the font's name.
- **Instancing/subsetting the font.** Deferred to Phase 22 (D-03).
- **Shrinking icon sizes during the swap.** Preserve existing `fsSp`/`sizeSp`/`sizeDp` magnitudes.

## Common Pitfalls

### Pitfall 1: Refreshing the font and silently losing a glyph or the opsz range
**What goes wrong:** a newer/older upstream cut drops or renames a glyph, or you grab an instanced (non-variable) file.
**How to avoid:** run `tools/verify_ligatures.py` against the new binary BEFORE deleting any drawable; confirm `fvar` still has the four axes with `opsz 20..48`; gate the swap on a green check. If it fails, keep v2.944.
**Warning signs:** on-device tofu boxes; `missing: [...]` non-empty.

### Pitfall 2: Deleting the official vectors the Views console row needs
**What goes wrong:** after converting Compose status sites to ligatures, deleting `disabled_by_default`/`warning` vectors → `ConsoleRowsAdapter` red build (or, if names overlap, runtime miss).
**How to avoid:** the NEW official vectors `disabled_by_default.xml`/`warning.xml` are KEEPERS. Only the OLD `ic_status_octagon.xml`/`ic_status_triangle.xml` get deleted. Console row's `resId` swaps to the new vectors.
**Warning signs:** unresolved `R.drawable.ic_status_*` in ConsoleRowsAdapter.

### Pitfall 3: Using the bucket's truncated name `text_select_move_forward`
**What goes wrong:** flipping `PressureAdvance` to `IconRef.Ligature("text_select_move_forward")` → tofu (not in font).
**How to avoid:** use `text_select_move_forward_word` (the `_word` suffix; the existing drawable name was right).
**Warning signs:** PressureAdvance tile renders a box on FineTune.

### Pitfall 4: Token name lies after the octagon flip
**What goes wrong:** `StatusOctagon` token now renders `disabled_by_default` (square+✕), not an octagon — the name misleads future maintainers.
**How to avoid:** rename `StatusOctagon`→`StatusStop` (+ `alternate "status_stop"`) with a KDoc note citing D-06. Keep `alternate` unique.

### Pitfall 5: Sizing regression on the swap
**What goes wrong:** ligature glyphs sized differently than the drawables they replace (the drawables had 24/96dp intrinsics).
**How to avoid:** preserve the existing `sizeSp`/`sizeDp`/`fsSp(...)` magnitude at each call site; `MaterialSymbol`/`DinghyIconView` already pin `fontScale=1f` so dp↔sp is 1:1. (memory `dinghy-font-sizes-too-small`.)
