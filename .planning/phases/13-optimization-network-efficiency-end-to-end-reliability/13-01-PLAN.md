Wave 0 — capture-first + harden the mock-that-lied. This plan BLOCKS every fix task (D-10): no
re-handshake fix code may be written until the real klippy-restart wire sequence is captured live on
BOTH printers and the test harness replays it faithfully. It also lands the RED regression tests the
Wave-1 fix must turn GREEN, plus the GREEN ProbeZOffsetFreshnessTest that gates the 13-03 cadence removal.

Purpose: The fix shape literally branches on what the capture shows (does `notify_klippy_ready`
arrive on the same socket? is the signal `webhooks.state` instead? is the failure printer-dependent?).
The current `KlippyReadyResyncTest` is GREEN while reality fails on-device — it asserts sent-frame
counts against a mock that auto-replies instantly and unconditionally (the third strike of the
project's mock-vs-reality class). Worse, `FakeWebSocket.inject(frame)` (FakeWebSocket.kt:55-57)
delivers a frame straight to `listener.onMessage` regardless of any subscription state, so an injected
post-restart status frame arrives whether or not a re-subscribe happened — a "resumed diffs" test built
on raw inject() passes even when the fix is absent. AND `FakeWebSocket.cancel()` (FakeWebSocket.kt:98-100)
only flips `closed = true` and fires NO listener callback, so the self-heal escalation
(RpcConnection.close(cause)→webSocket.cancel()) can never produce a SocketEvent.Closed in tests and the
reconnect is unobservable. We capture the truth, harden the mock to it (subscription-gated frame
delivery INSIDE inject(), and a cancel() that fires onFailure), and rewrite the test to assert resumed
diffs before touching production code.

Output: two committed `.jsonl` capture fixtures (E5 + E3) each replaying the FULL runHandshake +
post-restart re-handshake replies, a reusable capture script, a klippy-down window + subscriptionActive
gate (in FakeWebSocket.inject + SessionTestHarness) + a cancel()-fires-onFailure change, a rewritten
resumed-diff `KlippyReadyResyncTest`, a new RED `KlippyRecoveryStateTest` (D-03), a new RED self-heal
test (escalation-observable via the cancel() change), a GREEN `ProbeZOffsetFreshnessTest` (the 13-03
removal gate), and an extended `ReconnectSupervisorTest` (D-07b).
