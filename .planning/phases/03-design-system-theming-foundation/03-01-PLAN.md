<objective>
Build the headless theming core: the baked oklch→sRGB token table (D-03), the toolkit-agnostic
`ThemeTokens` value type (D-05), the `ThemeResolver` StateFlow that combines (base + custom deltas +
`--fs`) into resolved tokens (D-01/D-02/D-04), and DataStore-backed `ThemePrefs` persistence. This is
the single source of truth every later UI surface (Compose and Views) consumes. Adds the ONE new
dependency this phase needs (DataStore) to the version catalog and proves the minSdk-23 floor holds.

Purpose: "A theme is a token remap" must be literally true and API-23-safe. oklch silently renders
WRONG on API<26 (RESEARCH Pitfall 1) — baking to sRGB once is mandatory, not cosmetic. This phase
INTRODUCES the persistence mechanism before any editor UI (Phase 4 SET-01), so a corrupt/partial
persisted blob MUST fail safe — it must never crash or black-screen the printer display (D-02:
"a half-configured custom theme is still fully usable").
Output: The headless theme core + Wave-0 unit tests + the committed bake script.
</objective>
