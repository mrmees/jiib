<objective>
The second big D-01 restructure: push the 28 `AppShell` `collectAsStateWithLifecycle` collections DOWN so the shell collects only what it directly renders (connection status, nav.dest, drawer-open, drawer-tile visibility). This kills the wide-recomposition root cause where any 4 Hz emission re-evaluates all 28 collected flows in the shell scope. The calibration screens are migrated to the EXISTING holder-passing pattern (ScrewsTiltScreen already does this); the inline `.map{}` flows are hoisted to named `AppContainer` StateFlows on a dedicated state scope (process-scoped flows only — session-scoped ones stay shell-side). Then take the final SC1 gfxinfo AFTER sweep and run the SC2/SC5 owner UAT — the phase's closing measurement + regression gate.

Purpose: D-01 move #2 + the SC1/SC2/SC5 close-out. Depends on Plan 02 (immutable state the screens collect), Plan 04 (PrintStatus split + self-collecting), and Plan 05 (View hygiene — added as an EXPLICIT dependency so the final sweep reflects all View guards even if Plan 06 is rejected; see review note).
Output: A lean shell, calibration screens on the holder pattern, hoisted container flows on a dedicated scope, the collection audit (with holder-lifetime-scope classification), the post-fix gfxinfo sweep, and an owner-confirmed print-loop + nav regression check.

REVIEW NOTE (Codex HIGH, 22-07): the riskiest plan; four corrections. (1) Wrong wiring assumption — TiltScreen/BedMeshScreen/ProbeCalibrateScreen take a resolved `vm`, NOT `container`. Concrete strategy: change them to take their HOLDER (mirroring the existing `ScrewsTiltScreen(container, holder, ...)` which already collects `holder.vm` internally and calls holder methods for entry-reset) — that removes the four shell-side collections AND moves the `LaunchedEffect(Unit){onEnter()}` reset into the screen intact. (2) AppContainer has no general state scope — only `writeScope` (IO, for DataStore writes). A dedicated process-lifetime `stateScope` (Default dispatcher, SupervisorJob, WhileSubscribed) is added and designed BEFORE any `stateIn`. (3) A `stays/moves/split` collection-audit table — WITH a holder-lifetime-scope column — is now a prerequisite task; a value is only hoist-eligible if its producing scope is process-lifetime (errorLines may legitimately stay a session-scoped SPLIT). (4) `22-05` is an explicit dependency (not just transitive via 06), and nav regression checks are added.
</objective>
