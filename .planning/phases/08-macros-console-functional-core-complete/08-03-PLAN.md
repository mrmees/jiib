POLICY IS REJECT, NOT ESCAPE: validate every string value BEFORE concatenation (this is the EXPLICIT exception to the PrinterCommands invariant — D-10 allows the alpha keyboard here, so the keyboard text is the injection vector). The FORBIDDEN character set is, exactly: carriage return `\r` (0x0D), line feed `\n` (0x0A), semicolon `;` (Klipper treats `;` as a gcode comment delimiter → enables command-smuggling), tab `\t` (0x09), and ALL OTHER ASCII control characters (the full ranges 0x00-0x1F and 0x7F). If a string value contains ANY character from that set, REJECT the whole invocation by throwing a typed `MacroParamRejected(paramName, reason)` exception that the 08-06 popup surfaces as a SeverityToast — do NOT attempt to escape, strip, or quote-around the bad character (Klipper's quote-parsing behavior is UNCONFIRMED in RESEARCH, so reject-on-any-suspicious-char is the safe default; escaping a char whose parser semantics we have not verified is exactly the insecure path). A CLEAN string value (no forbidden chars) is quoted as `KEY="<value>"` per Klipper's `KEY="VALUE"` grammar. Numeric values pass through as `KEY=<value>` (numeric range-clamping is OWNED by NumpadPage in 08-06 — NOT this file; MacroInvocation does not clamp numbers, it only string-validates and formats). The macro NAME itself is from the discovered macro list (not free-text) — uppercase it for dispatch. Result is fed to `PrinterCommands.scriptParams(line)` by the caller (08-06), NEVER raw. No I/O. This turns the pre-existing `MacroInvocationTest` RED scaffold (from 08-01 Task 2) GREEN.
