# Phase 3 — UI Design Contract

> Visual and interaction contract for the Service / Shell / State-Driven-Navigation phase of **Dinghy Display**, a NATIVE Android app (Kotlin / Jetpack Compose Material 3 + classic Views hybrid). All measurements are Android units: **dp** for layout, **sp** for type, Material 3 **color roles** for color. This is NOT a web app — there is no CSS/Tailwind/shadcn here. shadcn gate is **not applicable** (no React/Next/Vite stack).
>
> **Shell model (REVISED):** the content surface is **full-bleed — maximum open canvas**. There is NO persistent navigation rail, NO persistent top app-bar, and NO persistent status bar. The ONLY persistent chrome on the canvas is a **thin edge handle**; navigation is an **edge-swipe-opened, full-screen app drawer** of big function tiles. Connection/printer status lives inside that drawer and contextually (splash), not on the content canvas. This supersedes the earlier rail + top-bar design.
>
> Generated by gsd-ui-researcher, verified by gsd-ui-checker. Authoritative inputs: `03-CONTEXT.md` (locked decisions — Shell decision REVISED, success criteria #3/#4 updated), `03-RESEARCH.md` (architecture), ADR `0001` (hybrid toolkit = LAW), the `mobile-android-design` skill (Material 3 reference), and the live `PrinterState` model.

| Preset | not applicable |

Hard-code the scheme.

## Spacing Scale

Declared values — **multiples of 4 (dp)**, Material 8-point grid. Use `dp` everywhere; never `px`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon-to-label gaps, inline chip padding, hairline separations |
| sm | 8dp | Compact element spacing, intra-row gaps, status-chip internal padding, keypad gutters |
| md | 16dp | **Default** content padding, card inner padding, gap between heater rows |
| lg | 24dp | Section padding, dialog inner padding, gap between dashboard regions, app-drawer tile gaps |
| xl | 32dp | Layout gaps, connect-form field grouping, splash vertical rhythm, app-drawer outer padding |
| 2xl | 48dp | Major section breaks; **standard minimum touch-target size** (see exceptions) |
| 3xl | 64dp | Screen-level outer margins on the wide 1920px landscape canvas; large-control sizing |

**Exceptions (touch-target minimums — load-bearing for a standing, greasy-fingered operator):**

| Target class | Minimum size | Rationale |
|--------------|--------------|-----------|
| Standard interactive (chip, list row, secondary button) | **48dp** | Material absolute minimum; never go below this. |
| Primary / destructive controls (Emergency Stop, confirm-dialog buttons, keypad keys, primary CTA) | **72dp** height (96dp+ for the E-stop) | Glanceable and hittable from a step back with imprecise fingers; the E-stop must be unmissable and un-mis-hittable. |
| App-drawer function tiles | **≥120dp × 120dp** | Big, glanceable launcher targets — the drawer is the only navigation surface, so its tiles must be impossible to miss. |
| Numeric-keypad keys | **72dp × 72dp** with 8dp gutters | Fat-finger-safe digit entry standing at the printer. |
| Edge handle (open-drawer affordance) | **~4–8dp visible width × tall**, but with a **≥48dp invisible touch slop** | The visible strip is intentionally thin (it is the only persistent chrome), but its hit/drag region is expanded to a comfortable target so the swipe/tap is forgiving. |

## Typography

**Sized up for a viewing-distance bench/wall screen** (operator stands ~0.5–1m back, not phone-in-hand). Sizes in **sp** so they respect system font scale. Map to Material 3 type-scale slots. **Two weights only:** Regular (400) and Medium (500) — Medium is Material's emphasis weight and reads cleaner than Bold on the Adreno 320 at high res.

| Role | M3 slot | Size | Weight | Line Height | Usage |
|------|---------|------|--------|-------------|-------|
| Display (temp readouts) | `displaySmall` (custom) | **36sp** | Medium (500) | 44sp | The live current-temperature value on heater rows + the E-stop label — the most-glanced numbers. |
| Heading | `headlineSmall` | **24sp** | Medium (500) | 32sp | Screen/section titles ("Connect to Printer", splash reason heading, dialog titles, app-drawer tile labels). |
| Title / label | `titleMedium` | **18sp** | Medium (500) | 24sp | Heater names, button labels, in-drawer status text, field labels. |
| Body | `bodyLarge` | **16sp** | Regular (400) | 24sp | Dialog body copy, splash reason detail, helper/validation text, connect-form input text. |

- **Body line-height ratio 1.5** (24/16); **heading ratio ~1.33** (32/24) — tighter for headings, generous for body, per the skill's defaults adapted up for distance.
- Minimum on-screen text is **16sp** (no 12/14sp captions) — anything smaller is unreadable at bench distance and fails the glanceability requirement. The `labelMedium`/`bodyMedium` 12–14sp Material defaults are **explicitly overridden up** for this app.
- **Title/label (18sp) vs Body (16sp) — differentiate by WEIGHT + ROLE, not by the 2sp size step.** Their sizes are deliberately close (4-size cap is intentional and stays). The executor must distinguish them by treatment: **Title/label = Medium (500)** applied to *interactive/structural* surfaces — button labels, heater names, in-drawer status text, field labels; **Body = Regular (400)** applied to *prose/secondary* surfaces — dialog body copy, splash reason detail, helper/validation text, input text. The size delta is reinforcement, not the carrier of the hierarchy.

## Color

**Single dark high-contrast scheme** expressed as Material 3 color roles. Values are concrete hex for the `darkColorScheme(...)` builder. The 60/30/10 split maps to surface / elevated-surface / accent.

| Role (M3) | Value | Usage |
|------|-------|-------|
| Dominant (60%) — `background` / `surface` | `#101418` | App canvas, full-bleed content backgrounds, the canvas behind the open app-drawer scrim. Near-black blue-grey, not pure `#000` (pure black smears on this LCD and kills depth cues). |
| Dominant text — `onBackground` / `onSurface` | `#E3E6EA` | Primary text/icons on the canvas. ~13:1 contrast on `#101418`. |
| Secondary (30%) — `surfaceVariant` / `surfaceContainer` | `#1C2127` | App-drawer overlay surface, drawer tiles, cards, heater-row surfaces, dialogs, the keypad/keyboard sheet. The "chrome" tier. |
| Secondary text — `onSurfaceVariant` | `#B6BCC4` | Labels, "coming soon" drawer tiles, target-temp / secondary metadata, the edge handle. |
| Accent (10%) — `primary` | `#5BC8FF` | **Reserved for:** the enabled app-drawer tile accent (icon/indicator on the active/focused tile), primary CTA fill ("Connect" / "Save & Connect"), focused text-field outline, and active/at-temp heater indication. NOT used for body text, not for every button. |
| Accent text — `onPrimary` | `#062536` | Text/icon on a `primary`-filled surface (primary button label). |
| Destructive — `error` | `#FF5A4D` | **Reserved for:** the Emergency Stop control, destructive confirm-dialog confirm buttons, error-severity toasts, and connection/Klippy `Error`/`Shutdown` status. |
| Destructive text — `onError` | `#3A0907` | Text/icon on an `error`-filled surface (E-stop label, destructive confirm button label). |
| Warning (semantic, custom) | `#FFB84D` | Heater actively-heating state, warning-severity toast, Klippy `Startup` status. Material 3 has no `warning` role — define as a custom theme extension color, do NOT abuse `tertiary`. |
| Success (semantic, custom) | `#5BD98A` | At-target / `Ready` / `Connected` status, success-severity toast. Also a custom extension color. |

**60/30/10 discipline:** `#101418` background dominates (~60%, and even more so now that the canvas is full-bleed), `#1C2127` chrome/cards/drawer (~30%), `#5BC8FF` accent appears only on the reserved short-list above (~10%). The two semantic extras (`error`, `warning`, `success`) are STATUS colors, not part of the decorative budget — they appear only to convey machine/connection state and destructive intent.

**Accent reserved for:** enabled app-drawer tile accent · primary CTA fill (Connect, Save & Connect) · focused input outline · at-temp/active heater accent. **Never** for: body text, all buttons, decorative fills, the edge handle.

**Contrast floors (verify at build):** all text/icon on its background ≥ **4.5:1** (WCAG AA); large display numbers ≥ **3:1** minimum but the palette above clears 4.5:1; the E-stop `error` fill vs `onError` clears 4.5:1.

**Tone:** plain, calm, mechanic-to-mechanic. No exclamation points except where genuinely urgent. Always tell the user the next action, not just the problem.

**Dismiss/CTA label rule:** every button names the specific thing it does — no bare "Cancel", "OK", "Submit", or "Save". Dismiss buttons name what the user is choosing NOT to do ("Keep Printing", "Keep Motors On", "Don't Restart", "Keep Heaters On", "Discard Entry"); confirm/CTA buttons name the action ("Cancel Print", "Disable Motors", "Connect", "Save & Connect", "Set"). (Note: "Cancel print" in the destructive-set list is the NAME of a printer operation, not a button label — that feature name stays.)

## Component & Screen Specs

> The structural decisions ("no persistent rail/bar, full-bleed canvas", "edge-swipe full-screen app drawer", "E-stop on Home/Dashboard only") are LOCKED in `03-CONTEXT.md` (Shell decision REVISED). Below is the visual/interaction *how*.

### 1. Shell & Canvas (full-bleed content — the ONLY persistent chrome is the edge handle)

- **Full-bleed content surface:** the active panel occupies the **entire** 1920×1200 landscape canvas — `background` (`#101418`), edge to edge. There is **NO persistent navigation rail, NO persistent top app-bar, NO persistent status bar.** This is the explicit goal: maximum usable space + a clean interface, iterated from a minimal baseline. Nothing decorative steals canvas width or height from the panel.
- **The single bit of persistent chrome — the edge handle:**
  - **Edge:** **left** edge of the screen (conventional origin for a left-opening drawer; the swipe-in direction and the drawer's slide-in both read naturally left-to-right).
  - **Appearance:** a **thin, low-contrast vertical strip ~4–8dp wide**, full screen height (or a tall centered segment ~30–40% of screen height), drawn in **`onSurfaceVariant`** (`#B6BCC4`) at reduced alpha (~40–60%) — present and discoverable, but quiet enough not to compete with panel content. A subtle rounded outer cap / faint grab-dots are acceptable to read as "grabbable."
  - **Behavior:** the handle is BOTH a passive hint ("swipe here") AND an active control — **tap it or drag it rightward to open the app drawer.** Its visible width is thin, but its touch/drag hit region is expanded to ≥48dp (see spacing exceptions) so the gesture is forgiving with greasy fingers.
  - This is Matthew's chosen discoverability affordance — **NOT a first-run coachmark, NOT a corner button.** It is always present, on every in-app panel.
- **Opening navigation:** an **edge-swipe from the left screen edge** (and/or the handle drag/tap) opens the full-screen app drawer (see §2). No other always-visible navigation exists.
- **No persistent status on the canvas:** connection state and Klippy state are NOT painted on content panels. They are surfaced **inside the app drawer's status area** (§2) and **contextually** (the splash route already owns the not-connected / startup / error states via top-level `klippy_state` routing). Panels stay clean.
- **Adding a destination (the contract):** a destination is **one entry in the `Dest` enum + one tile in the app drawer + one branch in the shell's `when(dest)` content host.** No Nav-Compose, no back-stack (CONTEXT-locked). Phase-4+ panels flip a "coming soon" tile to enabled and add their `when` branch — nothing else.

### 2. App Drawer (edge-swipe + handle trigger — full-screen tile launcher + status)

- **Trigger:** left-edge swipe-in OR tap/drag the edge handle (§1). Opens as a **full-screen overlay** above the current panel (drawer surface `surfaceVariant` `#1C2127`, with a brief `background` scrim fade underneath during the open transition). It is the launcher; there is no persistent menu or rail anywhere.
- **Dismiss:** swipe back to the left edge, tap a tile (collapses the drawer to that panel), or tap outside the tile grid onto the scrim. There is no bare "Close" button — selecting a destination or swiping closed is the model; if an explicit affordance is wanted, label it **"Back to {panel}"**, never "Close".
- **Tile grid (the function launcher):** big **function tiles** laid out on a grid (e.g. a 3-across grid on the wide landscape canvas, `lg` 24dp gaps, `xl` 32dp outer padding). Each tile is **≥120dp × 120dp**, `surfaceVariant`, 12dp corners, with a centered icon (≥48dp) over a `headlineSmall` label.
  - **Enabled tiles (v1 ships these):** **Home / Dashboard** (`Icons.Outlined.Dashboard`) · **Job Status** (`Icons.Outlined.Print`). Full-contrast (`onSurface` icon/label); the active destination carries a `primary` (`#5BC8FF`) accent indicator (icon tint or a thin top/edge bar) so the user sees where they are.
  - **Coming-soon tiles (greyed, reserve their slot):** **Temperature** (`Icons.Outlined.Thermostat`) · **Move** (`Icons.Outlined.OpenWith`) · **Files** (`Icons.Outlined.Folder`) · **Console** (`Icons.Outlined.Terminal`). Rendered **dimmed (~38% alpha), non-tappable**, each with a small **"Coming soon"** `bodyLarge` sub-label. They reserve their grid position so adding the panel later is the one-line flip from §1. Do NOT omit them — they communicate the roadmap. No tooltips (no hover on touch).
- **In-drawer status area (the home for connection + Klippy status — never on the canvas):** a dedicated region of the drawer overlay (e.g. a header strip or a bottom band) shows, **icon + color + text, NEVER color alone:**
  - **Connection status** (the 5 `ConnectionState` values — informational, NOT routing):
    - `Connecting` → spinner icon + "Connecting" + `onSurfaceVariant`
    - `Syncing` → spinner icon + "Syncing" + `warning` (`#FFB84D`)
    - `Connected` → `Icons.Filled.CheckCircle` + "Connected" + `success` (`#5BD98A`)
    - `Disconnected` → `Icons.Filled.CloudOff` + "Offline" + `onSurfaceVariant`
    - `Error` → `Icons.Filled.Error` + "Error" + `error` (`#FF5A4D`)
  - **Klippy status** (from `KlippyState`): `Ready` → "Ready" + success; `Startup` → "Starting" + warning; `Error`/`Shutdown` → "Error"/"Stopped" + error; `Disconnected` → hidden (the connection line covers it).
  - **Printer host/name** (`titleMedium`) shown alongside, so the drawer is also "which printer am I on."
  - This status area is only visible while the drawer is open — that is intentional. Persistent at-a-glance status is deferred to a later iteration (CONTEXT: "start with maximum open canvas… we iterate designs"); the FGS notification (chrome, not an in-app surface) carries the always-on status outside the app.
- **Tap-to-panel behavior:** tapping an enabled tile collapses the drawer and routes the shell's state-holder to that `Dest`; the panel renders full-bleed behind where the drawer was. The transition is a simple slide/collapse — no elaborate shared-element animation (motion policy).

### 3. Emergency Stop (Home/Dashboard surface ONLY — a dashboard element, not chrome)

- **Scope (CHANGED):** the Emergency Stop is **present only on the Home/Dashboard surface for now** — it is NOT global chrome, NOT on Splash, NOT on the connection screen, NOT in the app drawer, NOT in the edge handle. Rationale (Matthew): the E-stop only really matters while a print is running, during which the operator is almost always on Home/Dashboard. Additional surfaces gain their own E-stop by hand as later control panels are built. There is no top bar to host it now, so it is a **placed control on the dashboard content layout**, not chrome.
- **Placement on the dashboard:** a prominent, **fixed corner control** on the dashboard canvas — recommend **top-right** of the Home/Dashboard layout, where it is reachable and reads as the loudest, most-deliberate control on the screen. It must visually dominate the dashboard (nothing else competes with it for "biggest, reddest, most hittable").
- **Appearance:** filled `error` (`#FF5A4D`) button, `onError` (`#3A0907`) label/icon, **≥96dp wide × 56dp tall** (bigger than any other control on the screen). Label **"EMERGENCY STOP"** (`titleMedium`, allcaps acceptable here) with a stop/octagon icon. High contrast, flat, no subtle styling.
- **Gesture — LOCKED: hold-to-confirm (long-press ~800ms) with a visual fill.** While held, an `onError`-tinted progress arc/bar fills across the button; releasing early **aborts** the gesture (release-to-abort); completing the hold fires `printer.emergency_stop` through `CommandDispatcher`. Static hint label: **"Hold to stop"**.
  - *Rationale:* a hold with visible progress is self-documenting (the user SEES the commitment building), recoverable mid-gesture, and impossible to trigger by a single brush/bump on a greasy screen — fast but deliberate, not a slow modal.
- **Always goes through `CommandDispatcher`** (timeout + in-flight + debounce); while in-flight show the button in a disabled **"Stopping…"** state.

### 4. Splash screen (Klippy non-ready hard override — NO E-stop)

- **Layout:** centered single column on the `background` canvas, max content width ~480dp centered on the 1920 panel (don't stretch a form across the whole width). **No Emergency Stop on splash** (E-stop is Home/Dashboard-only now); no edge handle / drawer either (splash is a hard route override and there are no panels to navigate to). Splash is reachable purely via `klippy_state` routing and exposes only its recovery/retry actions.
- **Focal point:** the vertically-centered status block is the single dominant anchor and the user's eye lands there immediately. In the **startup state** that focal element is the **indeterminate spinner paired with the "Starting up…" `headlineSmall` heading** (everything else is absent). In the **shutdown/error state** the focal element is the **`error`-colored error icon + the reason heading ("Printer stopped" / "Printer error") + the row of recovery buttons** directly beneath — the icon draws the eye, the heading names the problem, the buttons are the obvious next action.
- **(a) Normal startup (`KlippyState.Startup`):** centered indeterminate `CircularProgressIndicator` (`primary` tint) · `headlineSmall` "Starting up…" · `bodyLarge` "Klipper is initializing. This usually takes a few seconds." · NO recovery buttons (nothing is wrong).
- **(b) Shutdown / Error (`Shutdown` / `Error`):** `Icons.Filled.Error` in `error` color (48dp) · `headlineSmall` title ("Printer stopped" / "Printer error") · `bodyLarge` reason = the live `state_message` text in a `surfaceVariant` card (scrollable if long) · then a **row of recovery buttons**: `[Retry]` (tonal) · `[Restart Klipper]` (tonal) · `[Firmware Restart]` (tonal). Each button ≥72dp tall, routes through `CommandDispatcher`; firmware-restart shows the "Will run when the printer reconnects." sub-note when `ConnectionState != Connected`.
- **(c) Disconnected (`KlippyState.Disconnected` with a saved config):** offline icon + "Can't reach the printer" + the host/port body copy + a single `[Retry]` button.
- The user CANNOT navigate to panels from Splash — it is a hard route override (CONTEXT). Only the recovery/retry actions are reachable.

### 5. Connection config screen (first run / no saved config)

- **Layout:** single centered column, max width ~520dp, vertical rhythm at `xl` (32dp) between groups, `lg` (24dp) screen padding. Title `headlineSmall` "Connect to Printer". No edge handle / drawer / E-stop here (pre-connection; no printer to navigate or stop).
- **Focal point:** the **manual-entry block — anchored by the Host/IP field and the full-width filled `primary` "Connect" (or "Save & Connect") button** — is the dominant anchor. The discovery/scan block sits above it as a helpful shortcut, but the manual fields + the bright `primary` CTA are deliberately the visual center of gravity, because manual entry is the guaranteed floor (CONTEXT: "manual entry is the floor and is always present"). On first run with focus on the Host field and the accent-filled CTA at the bottom of the column, the eye travels Host → Port → Connect.
- **Discovery block (top, optional):** a `[Scan for printers]` tonal button; while scanning, an inline spinner + "Scanning…". Results render as a tappable list (`surfaceVariant` rows, 72dp tall) showing discovered name + host:port; tapping one fills the manual fields below. The empty-scan state uses the "No printers found" copy — **shown as info, never an error**, with the manual fields remaining fully visible.
- **Manual entry block (always present — the floor):**
  - **Host / IP** — `OutlinedTextField`, `bodyLarge` text, label "Hostname or IP", keyboard type `Uri`/`Text` (no autocorrect), focused outline `primary`.
  - **Port** — `OutlinedTextField`, numeric, label "Port", **default `7125`** pre-filled, validates 1–65535.
  - **API key (optional)** — `OutlinedTextField`, label "API key (optional)", `PasswordVisualTransformation` by default with a show/hide toggle; helper text "Leave blank if your printer doesn't require one." NEVER logged, never echoed to the notification (security rule).
- **Primary action:** filled `primary` **"Connect"** button (≥72dp tall, full-width of the form column), disabled until Host non-empty AND Port valid. Validation errors render inline beneath the offending field in `error` color + text (not color-only).

### 6. Thermal dashboard (Home — full-bleed content canvas; the SHARED render/throttle proof, SHELL-04)

- **Layout:** the dashboard is now the **FULL content canvas** — no 88dp rail stealing width, no 64dp top-bar stealing height. It fills the entire 1920×1200 panel. A **`LazyColumn` of heater rows** (low-churn Compose) and the **mini temperature graph** (the Views-`Canvas` primitive via `AndroidView`) share the canvas: on the wide landscape, prefer heater rows in a left column (~35% width) and the graph filling the right (~65%) so the live graph is the dominant glanceable element. Outer padding `lg` (24dp); reserve the **top-right corner** for the placed Emergency Stop control (§3) — lay out the heater column / graph to not collide with it.
- **Placed control — Emergency Stop:** the dashboard hosts the E-stop as a fixed top-right element (per §3). It is the single loudest control on this canvas; everything else (graph, heater values) is read-mostly.
- **Focal point:** the **live temperature graph** (right ~65%) is the dashboard's dominant *informational* focal element — the largest, most motion-bearing surface, and the thing a passing operator reads at a glance; the big `displaySmall` 36sp current-temperature numbers in the heater rows are the secondary anchor. (The E-stop is the dominant *control*; it is intentionally loud but sits in the corner so it does not compete with the at-a-glance temperature read.)
- **Heater-row anatomy** (Compose, `surfaceVariant` card, 72dp+ tall, `md` inner padding):
  - Left: heater **name** (`titleMedium`, `onSurface`) — e.g. "Extruder", "Heater Bed".
  - Center/right: **current temperature** as the big `displaySmall` 36sp number with a small "°C" unit, color-coded by state (below) · beneath/beside it the **target** as `bodyLarge` `onSurfaceVariant` "→ 200°".
  - Far right: a **compact state-colored sparkline** (Views `Canvas`, ~120dp wide × row-height tall) OR the heater shares the main graph — see graph integration.
- **Heater visual states (color + a glyph, never color alone):**
  - **Off / idle** (target 0, near ambient): `onSurfaceVariant` value, no fill — neutral.
  - **Heating** (current < target, `power > 0`): `warning` (`#FFB84D`) value + a small up-arrow / flame glyph.
  - **At target** (within ~2°): `success` (`#5BD98A`) value + a check glyph.
  - **Cooling** (target 0 but still hot, e.g. >40°): `onSurfaceVariant` value + down-arrow glyph + a "HOT" caution treatment while >50°.
- **Mini-graph (the SHARED primitive — Views custom `Canvas`, ADR 0001, hosted via `AndroidView`):**
  - **Colors:** one line per heater, drawn in that heater's state color at the latest sample (extruder/bed visually distinct — give each a stable hue: extruder `#FF8A5B` warm, bed `#5BC8FF` accent, others cycle a fixed palette). Background transparent (sits on `surface`). Gridlines, if any, hairline `onSurfaceVariant` at ~20% alpha.
  - **Axes:** for the *dashboard mini-graph*, **minimal-to-none** — a sparkline, no labeled axes (glanceable trend, not a precise chart). Phase 4's full Temperature panel EXTENDS this same `TempGraphView` to add labeled axes/markers and a wider window. The contract here is: the *primitive draws a bounded ring buffer of samples efficiently*; chrome is additive later. (The extra full-bleed width now available makes the dashboard graph the visual centerpiece — but it stays a sparkline; the labeled chart is still Phase 4's job.)
  - **Sample window:** the bounded ring already fed at the state layer's ~4 Hz (`PrinterStateStore.DEFAULT_SAMPLE_MS=250`). Dashboard window ≈ **last 2–3 minutes** (~480–720 samples max ring). Do NOT add a second throttle (RESEARCH anti-pattern). `onDraw` reuses `Paint`/`Path`, no per-frame allocation, `postInvalidateOnAnimation()` (Adreno-320 jank rule).
- **Empty/connecting state:** before heaters arrive, show the "Waiting for printer…" empty copy centered in the content area; once `Connected` + heaters present, render rows + graph.

### 7. Primitive — Confirm-action dialog (PRIM-03)

- Material 3 `AlertDialog`, `surfaceVariant` container, `lg` (24dp) padding.
- **Anatomy:** `headlineSmall` title (the question) · `bodyLarge` body (consequence + what happens next) · action row at bottom-end. **Confirm button** sized ≥72dp tall; **destructive variant** = filled `error` (`#FF5A4D`) with `onError` label; **dismiss button** = text/tonal, the SAFE default, placed left of confirm. Dismiss copy is action-specific ("Keep Printing", "Keep Motors On", "Don't Restart", "Keep Heaters On" — never a bare "No"/"Cancel").
- **Destructive set gated by this primitive:** cancel print, disable motors, restart print, cooldown-while-printing. (Emergency Stop does NOT use this dialog — it uses the hold gesture.)
- Confirm dispatches through `CommandDispatcher`; while in-flight the confirm button shows a busy/disabled state and the dialog stays up until the call resolves (then dismisses) or times out (then shows the timeout toast).

### 8. Primitive — Numeric keypad (PRIM-01)

- A Compose bottom-sheet/overlay panel (`surfaceVariant`), used for temperature setpoints and any numeric entry later panels need.
- **Layout:** 3×4 grid — `7 8 9 / 4 5 6 / 1 2 3 / ± . 0` plus a **backspace** key and a target-value display strip above the grid showing the in-progress value (`displaySmall`) and the field being edited (e.g. "Extruder target").
- **Key sizing:** **72dp × 72dp** keys, **8dp** gutters, `titleMedium`+ digit. Decimal (`.`) and sign (`±`) keys present; backspace as an icon key. **"Set"** (`primary`, commits the value) and **"Discard Entry"** (text, closes without applying) actions at the bottom, ≥72dp tall — no bare "Confirm"/"Cancel" labels.
- Greasy-finger first: large keys, generous gutters, immediate visual press feedback (ripple/state-layer), high contrast digits on `surface`.

### 9. Primitive — On-screen keyboard (PRIM-02)

- **LOCKED: use the system IME for text entry (host/IP, API key, future console/macro params), NOT a custom keyboard — with the keypad above as the dedicated NUMERIC primitive.**
  - *Rationale:* the device runs full LineageOS/Android 11 with a working system IME; reimplementing a full QWERTY is wasted effort, worse than the OS keyboard, and a maintenance sink. The genuine ergonomic gap on this appliance is *numeric* entry (setpoints) — which the dedicated big-key keypad (PRIM-01) covers far better than any IME. So: **system IME for text fields; custom keypad for numbers.** PRIM-02 ("on-screen keyboard primitive") is satisfied by a thin wrapper that requests/configures the system IME with the right `KeyboardOptions` (type, no autocorrect for host/key) and is the surface the Console panel (Phase 7) reuses.
  - *If a kiosk scenario later forbids the system IME* (e.g. a locked-down launcher hides it), revisit with a minimal custom QWERTY then. Not now.
- Text fields set `imeAction` appropriately (Done/Next), `singleLine` where applicable, and dark-theme-friendly cursor/handle colors (`primary`).

### 10. Primitive — Severity toast (PRIM-04)

- A Compose `Snackbar`-style transient overlay (NOT Android's legacy `Toast` — that can't be styled/themed and looks foreign), anchored **bottom-center** of the content area, stacking newest-on-top with a small gap, max ~3 visible then collapse. Because there is no longer a rail or top bar, the toast simply respects the canvas safe area and never covers the dashboard E-stop in its top-right corner.
- **Four severities — color + icon + text (never color alone):**
  | Severity | Container | Icon | Default duration |
  |----------|-----------|------|------------------|
  | Info | `surfaceVariant` `#1C2127`, `onSurfaceVariant` text | `Icons.Outlined.Info` | 3s |
  | Success | `success` `#5BD98A` accent bar/icon, `onSurface` text | `Icons.Filled.CheckCircle` | 3s |
  | Warning | `warning` `#FFB84D` accent bar/icon | `Icons.Filled.Warning` | 5s |
  | Error | `error` `#FF5A4D` accent bar/icon | `Icons.Filled.Error` | 6s (or until dismissed for action-failure) |
- Error toasts that imply a retry carry an inline action ("Retry"). Text is `bodyLarge` (16sp) — readable at distance. Toasts never obscure the dashboard E-stop.

## Elevation, Shape & Motion policy (fill-rate budget — Adreno 320)

- **Elevation: flat.** Use **color/tonal differentiation, not shadows**, to separate tiers (`#101418` canvas vs `#1C2127` chrome/cards/drawer). Set surfaces to elevation **0dp**; avoid M3 tonal-elevation overlays stacking. No blur, no translucent scrims beyond the single dialog scrim and the brief app-drawer open scrim. Overdraw is the enemy on a fill-rate-bound GPU at 1920×1200 (ADR 0001).
- **Shape:** Material 3 default-ish rounded corners — cards/chips/drawer-tiles **12dp**, dialogs **16dp**, buttons **full/stadium** for the primary/destructive controls (clearly tappable). Keep it consistent; don't invent per-component radii.
- **Motion:** minimal. The app-drawer open/close is a single **slide/collapse** (drawer slides in from the left edge; tapping a tile collapses it to the panel) — no shared-element/cross-fade route choreography. Standard Material state-layer ripples on press (cheap, important press feedback for greasy fingers). The E-stop hold-progress fill is the one deliberate motion and is intrinsic to the gesture's safety. The temp graph repaints via `postInvalidateOnAnimation`, not animation APIs. Animated list-item insertion is explicitly forgone (ADR 0001 accepted "a smooth plain list beats a pretty stuttering one").

## Accessibility & Legibility (bench/wall viewing distance)

- **Contrast:** all text/icons ≥ **4.5:1** against their surface (palette designed to clear this); verify with a contrast check at build. Large 36sp readouts comfortably exceed it. The edge handle is intentionally low-contrast as a *decorative hint*, but its function is duplicated by the edge-swipe gesture, so it is not the sole carrier of any information.
- **Minimum text 16sp** on screen (no 12/14sp) — distance legibility is a hard requirement, not a nicety.
- **State is NEVER color-alone:** every status (in-drawer connection line, Klippy line, heater state, toast severity) pairs an **icon/glyph + text label** with its color. A colorblind operator (or one glancing from an angle in a dim shop) must still read state.
- **Touch targets:** standard ≥48dp, primary/destructive ≥72dp, E-stop ≥96dp, app-drawer tiles ≥120dp, edge-handle hit-region ≥48dp — per the spacing exceptions table.
- **Content descriptions:** every icon-only control (in-drawer status icons, edge handle, drawer tiles, backspace key, show/hide-key toggle, E-stop) carries a `contentDescription` for TalkBack and to document intent. The edge handle's description states its action ("Open navigation").
- **Discoverability without hover/tooltip** (touch device) — the persistent edge handle is the discoverability affordance for the drawer; the "coming soon" drawer tiles communicate disabled-ness visually (alpha + non-interactive) plus a "Coming soon" text label, not via tooltip.
- **Landscape-locked:** all layouts designed for landscape only (PROJECT.md); full-bleed-content + left-edge-drawer is the single orientation. Do not author portrait variants.
