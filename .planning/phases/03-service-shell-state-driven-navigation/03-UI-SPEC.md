# Phase 3 — UI Design Contract

> Visual and interaction contract for the Service / Shell / State-Driven-Navigation phase of **Dinghy Display**, a NATIVE Android app (Kotlin / Jetpack Compose Material 3 + classic Views hybrid). All measurements are Android units: **dp** for layout, **sp** for type, Material 3 **color roles** for color. This is NOT a web app — there is no CSS/Tailwind/shadcn here. shadcn gate is **not applicable** (no React/Next/Vite stack).
>
> Generated by gsd-ui-researcher, verified by gsd-ui-checker. Authoritative inputs: `03-CONTEXT.md` (locked decisions), `03-RESEARCH.md` (architecture), ADR `0001` (hybrid toolkit = LAW), the `mobile-android-design` skill (Material 3 reference), and the live `PrinterState` model.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — native Android Material 3 (`androidx.compose.material3` via Compose BOM `2026.05.00` → UI 1.11.1). shadcn gate N/A (not a web stack). |
| Preset | not applicable |
| Component library | **Material 3 Compose** (`androidx.compose.material3`) for the shell + most panels; **classic Android Views** (custom `Canvas`) for the temperature mini-graph, hosted via `AndroidView` (ADR 0001). |
| Icon library | **`androidx.compose.material:material-icons-extended`** (Material Symbols / `Icons.Default.*`, `Icons.Outlined.*`) — already the Compose-native default; no third-party icon dep. Confirm the artifact is in `libs.versions.toml` at plan time (it may not be yet). |
| Font | **System default** (`FontFamily.Default` → Roboto on LineageOS/AOSP). No custom font dependency — keeps APK lean for the 2GB target and avoids a glyph-load cost on weak hardware. |
| Theme base | `Theme.AppCompat.DayNight.NoActionBar` (XML, locked — required so the Views hybrid can inflate AppCompat widgets under one theme). Compose layers a `darkColorScheme` (below) on top via `MaterialTheme`. **Dark, high-contrast, single (dark) theme — no light variant, no dynamic color.** |

**Why no dynamic color:** Material You dynamic color (Android 12+) is irrelevant — the target is a fixed wall/bench appliance on API 30, dynamic color would be unpredictable per-device, and a printer-side screen wants a deliberate high-contrast dark palette, not wallpaper-derived hues. Hard-code the scheme.

## Spacing Scale

Declared values — **multiples of 4 (dp)**, Material 8-point grid. Use `dp` everywhere; never `px`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon-to-label gaps, inline chip padding, hairline separations |
| sm | 8dp | Compact element spacing, intra-row gaps, status-chip internal padding |
| md | 16dp | **Default** content padding, card inner padding, gap between heater rows |
| lg | 24dp | Section padding, dialog inner padding, gap between dashboard regions |
| xl | 32dp | Layout gaps, connect-form field grouping, splash vertical rhythm |
| 2xl | 48dp | Major section breaks; **standard minimum touch-target size** (see exceptions) |
| 3xl | 64dp | Screen-level outer margins on the wide 1920px landscape canvas; large-control sizing |

**Exceptions (touch-target minimums — load-bearing for a standing, greasy-fingered operator):**

| Target class | Minimum size | Rationale |
|--------------|--------------|-----------|
| Standard interactive (nav-rail item, chip, list row, secondary button) | **48dp** | Material absolute minimum; never go below this. |
| Primary / destructive controls (Emergency Stop, confirm-dialog buttons, keypad keys, primary CTA) | **72dp** height (96dp+ for the E-stop) | Glanceable and hittable from a step back with imprecise fingers; the E-stop must be unmissable and un-mis-hittable. |
| Numeric-keypad keys | **72dp × 72dp** with 8dp gutters | Fat-finger-safe digit entry standing at the printer. |

## Typography

**Sized up for a viewing-distance bench/wall screen** (operator stands ~0.5–1m back, not phone-in-hand). Sizes in **sp** so they respect system font scale. Map to Material 3 type-scale slots. **Two weights only:** Regular (400) and Medium (500) — Medium is Material's emphasis weight and reads cleaner than Bold on the Adreno 320 at high res.

| Role | M3 slot | Size | Weight | Line Height | Usage |
|------|---------|------|--------|-------------|-------|
| Display (temp readouts) | `displaySmall` (custom) | **36sp** | Medium (500) | 44sp | The live current-temperature value on heater rows + the E-stop label — the most-glanced numbers. |
| Heading | `headlineSmall` | **24sp** | Medium (500) | 32sp | Screen/section titles ("Connect to Printer", splash reason heading, dialog titles). |
| Title / label | `titleMedium` | **18sp** | Medium (500) | 24sp | Nav-rail item labels, heater names, button labels, top-bar status text, field labels. |
| Body | `bodyLarge` | **16sp** | Regular (400) | 24sp | Dialog body copy, splash reason detail, helper/validation text, connect-form input text. |

- **Body line-height ratio 1.5** (24/16); **heading ratio ~1.33** (32/24) — tighter for headings, generous for body, per the skill's defaults adapted up for distance.
- Minimum on-screen text is **16sp** (no 12/14sp captions) — anything smaller is unreadable at bench distance and fails the glanceability requirement. The `labelMedium`/`bodyMedium` 12–14sp Material defaults are **explicitly overridden up** for this app.
- **Title/label (18sp) vs Body (16sp) — differentiate by WEIGHT + ROLE, not by the 2sp size step.** Their sizes are deliberately close (4-size cap is intentional and stays). The executor must distinguish them by treatment: **Title/label = Medium (500)** applied to *interactive/structural* surfaces — nav-rail item labels, button labels, heater names, top-bar status text, field labels; **Body = Regular (400)** applied to *prose/secondary* surfaces — dialog body copy, splash reason detail, helper/validation text, input text. The size delta is reinforcement, not the carrier of the hierarchy.

## Color

**Single dark high-contrast scheme** expressed as Material 3 color roles. Values are concrete hex for the `darkColorScheme(...)` builder. The 60/30/10 split maps to surface / elevated-surface / accent.

| Role (M3) | Value | Usage |
|------|-------|-------|
| Dominant (60%) — `background` / `surface` | `#101418` | App canvas, screen backgrounds, the content area behind the nav-rail. Near-black blue-grey, not pure `#000` (pure black smears on this LCD and kills depth cues). |
| Dominant text — `onBackground` / `onSurface` | `#E3E6EA` | Primary text/icons on the canvas. ~13:1 contrast on `#101418`. |
| Secondary (30%) — `surfaceVariant` / `surfaceContainer` | `#1C2127` | Nav-rail, top app-bar, cards, heater-row surfaces, dialogs, the keypad/keyboard sheet. The "chrome" tier. |
| Secondary text — `onSurfaceVariant` | `#B6BCC4` | Labels, unselected nav items, target-temp / secondary metadata. |
| Accent (10%) — `primary` | `#5BC8FF` | **Reserved for:** the selected nav-rail item (indicator + icon/label), primary CTA fill ("Connect" / "Save"), focused text-field outline, and active/at-temp heater indication. NOT used for body text, not for every button. |
| Accent text — `onPrimary` | `#062536` | Text/icon on a `primary`-filled surface (primary button label). |
| Destructive — `error` | `#FF5A4D` | **Reserved for:** the Emergency Stop control, destructive confirm-dialog confirm buttons, error-severity toasts, and connection/Klippy `Error`/`Shutdown` status. |
| Destructive text — `onError` | `#3A0907` | Text/icon on an `error`-filled surface (E-stop label, destructive confirm button label). |
| Warning (semantic, custom) | `#FFB84D` | Heater actively-heating state, warning-severity toast, Klippy `Startup` status. Material 3 has no `warning` role — define as a custom theme extension color, do NOT abuse `tertiary`. |
| Success (semantic, custom) | `#5BD98A` | At-target / `Ready` / `Connected` status, success-severity toast. Also a custom extension color. |

**60/30/10 discipline:** `#101418` background dominates (~60%), `#1C2127` chrome/cards (~30%), `#5BC8FF` accent appears only on the reserved short-list above (~10%). The two semantic extras (`error`, `warning`, `success`) are STATUS colors, not part of the decorative budget — they appear only to convey machine/connection state and destructive intent.

**Accent reserved for:** selected nav-rail destination · primary CTA fill (Connect, Save) · focused input outline · at-temp/active heater accent. **Never** for: body text, all buttons, decorative fills, the whole top-bar.

**Contrast floors (verify at build):** all text/icon on its background ≥ **4.5:1** (WCAG AA); large display numbers ≥ **3:1** minimum but the palette above clears 4.5:1; the E-stop `error` fill vs `onError` clears 4.5:1.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — Connect screen | **"Connect"** (filled `primary` button; disabled until host + valid port present) |
| Primary CTA — saved-config edit | **"Save & Connect"** |
| Secondary action — Connect screen | **"Scan for printers"** (text/tonal button; triggers best-effort mDNS, never blocks) |
| Empty state — mDNS scan, nothing found | Heading: **"No printers found on the network"** · Body: **"That's normal — most printers don't advertise themselves. Enter your printer's address below."** (mDNS finding nothing is EXPECTED — Moonraker's `[zeroconf]` is opt-in. Never frame this as an error; keep the manual fields visible and prominent above/below this notice.) |
| Empty state — dashboard, no heaters yet (connecting) | Heading: **"Waiting for printer…"** · Body: **"Connected to {host}. Reading printer state."** |

If no message: **"The printer reported a {shutdown/error} state with no detail."** |
| Splash — disconnected from printer | Title: **"Can't reach the printer"** · Body: **"Couldn't connect to {host}:{port}. Check the printer is powered on and on the same network."** |
| Error state — connection failed (toast/inline) | **"Couldn't connect to {host}:{port} — {reason}. Tap Retry."** |
| Error state — command timed out (toast) | **"No response from printer — the command may not have run. Try again."** |
| Field validation — host empty | **"Enter the printer's hostname or IP"** |
| Field validation — port out of range | **"Port must be between 1 and 65535"** |
| Destructive confirmation — Emergency Stop | NOT a dialog (fast-but-deliberate gesture). Label on control: **"EMERGENCY STOP"** · gesture hint: **"Hold to stop"** (see Primitive: Emergency Stop). |
| Destructive confirmation — Cancel print | Title: **"Cancel this print?"** · Body: **"The print will stop and can't be resumed."** · Confirm: **"Cancel Print"** (error-styled) · Dismiss: **"Keep Printing"** |
| Destructive confirmation — Disable motors | Title: **"Disable stepper motors?"** · Body: **"The toolhead will move freely and axes lose their home position."** · Confirm: **"Disable Motors"** · Dismiss: **"Keep Motors On"** |
| Destructive confirmation — Restart print | Title: **"Restart this print?"** · Body: **"The print will start over from the beginning."** · Confirm: **"Restart Print"** · Dismiss: **"Don't Restart"** |
| Destructive confirmation — Cooldown while printing | Title: **"Turn off heaters during a print?"** · Body: **"This will ruin the active print."** · Confirm: **"Cool Down"** (error-styled) · Dismiss: **"Keep Heaters On"** |
| Numeric keypad — confirm action | **"Set"** (`primary`-styled — commits the entered value to the field being edited) |
| Numeric keypad — dismiss action | **"Discard Entry"** (text-styled — closes the keypad without applying the in-progress value) |
| Splash recovery actions | **"Retry"** (re-attempt connect) · **"Restart Klipper"** (`printer.restart`) · **"Firmware Restart"** (`printer.firmware_restart`). Show recovery buttons only on `Shutdown`/`Error`, not on normal `Startup`. Note copy near firmware-restart if Klippy is disconnected: **"Will run when the printer reconnects."** (the call is postponed, per RESEARCH Pitfall 6). |

**Tone:** plain, calm, mechanic-to-mechanic. No exclamation points except where genuinely urgent. Always tell the user the next action, not just the problem.

**Dismiss/CTA label rule:** every button names the specific thing it does — no bare "Cancel", "OK", "Submit", or "Save". Dismiss buttons name what the user is choosing NOT to do ("Keep Printing", "Keep Motors On", "Don't Restart", "Keep Heaters On", "Discard Entry"); confirm/CTA buttons name the action ("Cancel Print", "Disable Motors", "Connect", "Set"). (Note: "Cancel print" in the destructive-set list below is the NAME of a printer operation, not a button label — that feature name stays.)

## Component & Screen Specs

> The structural decisions ("a nav-rail exists", "a top bar carries the E-stop") are LOCKED in `03-CONTEXT.md`. Below is the visual/interaction *how*.

### 1. NavigationRail (persistent left chrome)

- **Container:** Material 3 `NavigationRail`, `containerColor = surfaceVariant` (`#1C2127`), full content height, pinned left. **Width: 88dp** (Material rail standard 80dp, widened to 88dp for fat-finger targets) — leaves ≥1832dp of the 1920 landscape width for content, satisfying CONTEXT's "must not starve the content area."
- **Item anatomy:** stacked icon (24dp) over label (`titleMedium` 18sp Medium). Item hit-target ≥72dp tall. Selected: `primary` (`#5BC8FF`) icon + label + the M3 pill indicator behind the icon (`secondaryContainer` tint). Unselected: `onSurfaceVariant` (`#B6BCC4`) icon + label.
- **v1 destination set (enabled):** **Home / Dashboard** (`Icons.Outlined.Dashboard`), **Job Status** (`Icons.Outlined.Print`). These are the only two real destinations this phase ships.
- **Coming-in-Phase-4+ destinations:** **Temperature** (`Icons.Outlined.Thermostat`), **Move** (`Icons.Outlined.OpenWith`), **Files** (`Icons.Outlined.Folder`), **Console** (`Icons.Outlined.Terminal`). Render these **disabled (greyed, ~38% alpha, non-tappable)** rather than omitted — they communicate the roadmap and reserve their position so adding the panel later is a one-line flip (matches CONTEXT "design so adding a destination is a one-line addition"). A small **"soon"** affordance is optional; do not add tooltips (no hover on touch).
- **Adding a destination (the contract):** a destination is one entry in the `Dest` enum + one `NavigationRailItem` + one branch in the shell's `when(dest)` content host. No Nav-Compose, no back-stack (CONTEXT-locked).

### 2. Top app-bar (persistent chrome — status + E-stop on every in-app screen)

- **Container:** Material 3 `TopAppBar`-style bar, `containerColor = surfaceVariant` (`#1C2127`), height **64dp**, flat (elevation 0 — see Elevation policy). Present on Shell screens (Dashboard, Job) AND reachable equivalents must exist on Splash (see Splash spec).
- **Layout (left→right):** printer name/host (`titleMedium`) · **connection status chip** · **Klippy status chip** · `Spacer(weight 1f)` · **Emergency Stop control** pinned far right.
- **Connection status chip** (the 5 `ConnectionState` values — chrome only, NOT routing): icon + short label + color, NEVER color alone:
  - `Connecting` → spinner icon + "Connecting" + `onSurfaceVariant`
  - `Syncing` → spinner icon + "Syncing" + `warning` (`#FFB84D`)
  - `Connected` → `Icons.Filled.CheckCircle` + "Connected" + `success` (`#5BD98A`)
  - `Disconnected` → `Icons.Filled.CloudOff` + "Offline" + `onSurfaceVariant`
  - `Error` → `Icons.Filled.Error` + "Error" + `error` (`#FF5A4D`)
- **Klippy status chip** (from `KlippyState`, surfaced glanceably): `Ready` → "Ready" + success; `Startup` → "Starting" + warning; `Error`/`Shutdown` → "Error"/"Stopped" + error; `Disconnected` → hidden (the connection chip covers it). Both chips use icon **and** color and text (accessibility — never color-only).

### 3. Emergency Stop (primitive — reachable on EVERY route incl. Splash)

- **Placement:** far-right end of the top app-bar on Shell screens; mirrored as a same-styled control on the Splash screen so it is reachable while Klippy is down (CONTEXT: every screen).
- **Appearance:** filled `error` (`#FF5A4D`) button, `onError` label/icon, **≥96dp wide × 56dp tall** (bigger than any other control — it must be the most hittable thing on screen). Label **"EMERGENCY STOP"** (`titleMedium`, allcaps acceptable here) with a stop/octagon icon. High contrast, flat, no subtle styling.
- **Gesture — RECOMMENDATION (confirm): hold-to-confirm (long-press ~800ms) with a visual fill.** While held, an `onError`-tinted progress arc/bar fills across the button; releasing early aborts; completing fires `printer.emergency_stop` through `CommandDispatcher`. Static hint label: **"Hold to stop"**.
  - *Rationale:* a hold with visible progress is self-documenting (the user SEES the commitment building), recoverable mid-gesture, and impossible to trigger by a single brush/bump — strictly better than double-tap on a greasy screen where an accidental double-contact is plausible. Double-tap is the documented alternative; hold-with-fill is the stronger fit for "fast but deliberate, not a slow modal." **Flagged for Matthew's confirmation** — both satisfy CONTEXT; this is the open interaction choice from RESEARCH OQ#3.
- **Always goes through `CommandDispatcher`** (timeout + in-flight + debounce); while in-flight show the button in a disabled "Stopping…" state.

### 4. Splash screen (Klippy non-ready hard override)

- **Layout:** centered single column on the `background` canvas, max content width ~480dp centered on the 1920 panel (don't stretch a form across the whole width). The E-stop control is still present (top-right) — the user must be able to e-stop even from splash.
- **Focal point:** the vertically-centered status block is the single dominant anchor and the user's eye lands there immediately. In the **startup state** that focal element is the **indeterminate spinner paired with the "Starting up…" `headlineSmall` heading** (everything else is absent). In the **shutdown/error state** the focal element is the **`error`-colored error icon + the reason heading ("Printer stopped" / "Printer error") + the row of recovery buttons** directly beneath — the icon draws the eye, the heading names the problem, the buttons are the obvious next action. The E-stop is the only competing element and is intentionally the loudest control on the screen.
- **(a) Normal startup (`KlippyState.Startup`):** centered indeterminate `CircularProgressIndicator` (`primary` tint) · `headlineSmall` "Starting up…" · `bodyLarge` "Klipper is initializing. This usually takes a few seconds." · NO recovery buttons (nothing is wrong).
- **(b) Shutdown / Error (`Shutdown` / `Error`):** `Icons.Filled.Error` in `error` color (48dp) · `headlineSmall` title ("Printer stopped" / "Printer error") · `bodyLarge` reason = the live `state_message` text in a `surfaceVariant` card (scrollable if long) · then a **row of recovery buttons**: `[Retry]` (tonal) · `[Restart Klipper]` (tonal) · `[Firmware Restart]` (tonal). Each button ≥72dp tall, routes through `CommandDispatcher`; firmware-restart shows the "Will run when the printer reconnects." sub-note when `ConnectionState != Connected`.
- **(c) Disconnected (`KlippyState.Disconnected` with a saved config):** offline icon + "Can't reach the printer" + the host/port body copy + a single `[Retry]` button.
- The user CANNOT navigate to panels from Splash — it is a hard route override (CONTEXT). Only the E-stop and the recovery/retry actions are reachable.

### 5. Connection config screen (first run / no saved config)

- **Layout:** single centered column, max width ~520dp, vertical rhythm at `xl` (32dp) between groups, `lg` (24dp) screen padding. Title `headlineSmall` "Connect to Printer".
- **Focal point:** the **manual-entry block — anchored by the Host/IP field and the full-width filled `primary` "Connect" (or "Save & Connect") button** — is the dominant anchor. The discovery/scan block sits above it as a helpful shortcut, but the manual fields + the bright `primary` CTA are deliberately the visual center of gravity, because manual entry is the guaranteed floor (CONTEXT: "manual entry is the floor and is always present"). On first run with focus on the Host field and the accent-filled CTA at the bottom of the column, the eye travels Host → Port → Connect.
- **Discovery block (top, optional):** a `[Scan for printers]` tonal button; while scanning, an inline spinner + "Scanning…". Results render as a tappable list (`surfaceVariant` rows, 72dp tall) showing discovered name + host:port; tapping one fills the manual fields below. The empty-scan state uses the "No printers found" copy — **shown as info, never an error**, with the manual fields remaining fully visible.
- **Manual entry block (always present — the floor):**
  - **Host / IP** — `OutlinedTextField`, `bodyLarge` text, label "Hostname or IP", keyboard type `Uri`/`Text` (no autocorrect), focused outline `primary`.
  - **Port** — `OutlinedTextField`, numeric, label "Port", **default `7125`** pre-filled, validates 1–65535.
  - **API key (optional)** — `OutlinedTextField`, label "API key (optional)", `PasswordVisualTransformation` by default with a show/hide toggle; helper text "Leave blank if your printer doesn't require one." NEVER logged, never echoed to the notification (security rule).
- **Primary action:** filled `primary` **"Connect"** button (≥72dp tall, full-width of the form column), disabled until Host non-empty AND Port valid. Validation errors render inline beneath the offending field in `error` color + text (not color-only).

### 6. Thermal dashboard (Home — the SHARED render/throttle proof, SHELL-04)

- **Layout:** the content area right of the nav-rail. A **`LazyColumn` of heater rows** at top (low-churn Compose), and below/beside them the **mini temperature graph** (the Views-`Canvas` primitive via `AndroidView`). On the wide 1920 landscape, prefer heater rows in a left column (~40% width) and the graph filling the right (~60%) so the live graph is the dominant glanceable element.
- **Focal point:** the **live temperature graph** (right ~60%) is the dashboard's dominant focal element — the largest, most motion-bearing surface, and the thing a passing operator reads at a glance; the big `displaySmall` 36sp current-temperature numbers in the heater rows are the secondary anchor.
- **Heater-row anatomy** (Compose, `surfaceVariant` card, 72dp+ tall, `md` inner padding):
  - Left: heater **name** (`titleMedium`, `onSurface`) — e.g. "Extruder", "Heater Bed".
  - Center/right: **current temperature** as the big `displaySmall` 36sp number with a small "°C" unit, color-coded by state (below) · beneath/beside it the **target** as `bodyLarge` `onSurfaceVariant` "→ 200°".
  - Far right: a **compact state-colored sparkline** (Views `Canvas`, ~120dp wide × row-height tall) OR the heater shares the main graph — see graph integration.
- **Heater visual states (color + a glyph, never color alone):**
  - **Off / idle** (target 0, near ambient): `onSurfaceVariant` value, no fill — neutral.
  - **Heating** (current < target, `power > 0`): `warning` (`#FFB84D`) value + a small up-arrow / flame glyph.
  - **At target** (within ~2°): `success` (`#5BD98A`) value + a check glyph.
  - **Cooling** (target 0 but still hot, e.g. >40°): `onSurfaceVariant` value + down-arrow glyph + a "HOT" caution treatment while >50°.
- **Mini-graph (the SHARED primitive — Views custom `Canvas`, ADR 0001, hosted via `AndroidView`):**
  - **Colors:** one line per heater, drawn in that heater's state color at the latest sample (extruder/bed visually distinct — give each a stable hue: extruder `#FF8A5B` warm, bed `#5BC8FF` accent, others cycle a fixed palette). Background transparent (sits on `surface`). Gridlines, if any, hairline `onSurfaceVariant` at ~20% alpha.
  - **Axes:** for the *dashboard mini-graph*, **minimal-to-none** — a sparkline, no labeled axes (glanceable trend, not a precise chart). Phase 4's full Temperature panel EXTENDS this same `TempGraphView` to add labeled axes/markers and a wider window. The contract here is: the *primitive draws a bounded ring buffer of samples efficiently*; chrome is additive later.
  - **Sample window:** the bounded ring already fed at the state layer's ~4 Hz (`PrinterStateStore.DEFAULT_SAMPLE_MS=250`). Dashboard window ≈ **last 2–3 minutes** (~480–720 samples max ring). Do NOT add a second throttle (RESEARCH anti-pattern). `onDraw` reuses `Paint`/`Path`, no per-frame allocation, `postInvalidateOnAnimation()` (Adreno-320 jank rule).
- **Empty/connecting state:** before heaters arrive, show the "Waiting for printer…" empty copy centered in the content area; once `Connected` + heaters present, render rows + graph.

### 7. Primitive — Confirm-action dialog (PRIM-03)

- Material 3 `AlertDialog`, `surfaceVariant` container, `lg` (24dp) padding.
- **Anatomy:** `headlineSmall` title (the question) · `bodyLarge` body (consequence + what happens next) · action row at bottom-end. **Confirm button** sized ≥72dp tall; **destructive variant** = filled `error` (`#FF5A4D`) with `onError` label; **dismiss button** = text/tonal, the SAFE default, placed left of confirm. Dismiss copy is action-specific ("Keep Printing", "Keep Motors On", "Don't Restart", "Keep Heaters On" — never a bare "No"/"Cancel").
- **Destructive set gated by this primitive:** cancel print, disable motors, restart print, cooldown-while-printing. (Emergency Stop does NOT use this dialog — it uses the hold gesture.)
- Confirm dispatches through `CommandDispatcher`; while in-flight the confirm button shows a busy/disabled state and the dialog stays up until the call resolves (then dismisses) or times out (then shows the timeout toast).

### 8. Primitive — Numeric keypad (PRIM-01)

- A Compose bottom-sheet/overlay panel (`surfaceVariant`), used for temperature setpoints and any numeric entry later panels need.
- **Layout:** 3×4 grid — `7 8 9 / 4 5 6 / 1 2 3 / ± . 0` plus a **backspace** key and a target-value display strip above the grid showing the in-progress value (`displaySmall`) and the field being edited (e.g. "Extruder target").
- **Key sizing:** **72dp × 72dp** keys, **8dp** gutters, `titleMedium`+ digit. Decimal (`.`) and sign (`±`) keys present; backspace as an icon key. **"Set"** (`primary`, commits the value) and **"Discard Entry"** (text, closes without applying) actions at the bottom, ≥72dp tall — no bare "Confirm"/"Cancel" labels.
- Greasy-finger first: large keys, generous gutters, immediate visual press feedback (ripple/state-layer), high contrast digits on `surface`.

### 9. Primitive — On-screen keyboard (PRIM-02)

- **RECOMMENDATION (confirm): use the system IME for text entry (host/IP, API key, future console/macro params), NOT a custom keyboard — with the keypad above as the dedicated NUMERIC primitive.**
  - *Rationale:* the device runs full LineageOS/Android 11 with a working system IME; reimplementing a full QWERTY is wasted effort, worse than the OS keyboard, and a maintenance sink. The genuine ergonomic gap on this appliance is *numeric* entry (setpoints) — which the dedicated big-key keypad (PRIM-01) covers far better than any IME. So: **system IME for text fields; custom keypad for numbers.** PRIM-02 ("on-screen keyboard primitive") is satisfied by a thin wrapper that requests/configures the system IME with the right `KeyboardOptions` (type, no autocorrect for host/key) and is the surface the Console panel (Phase 7) reuses.
  - *If a kiosk scenario later forbids the system IME* (e.g. a locked-down launcher hides it), revisit with a minimal custom QWERTY then. Not now. **Flagged for Matthew's confirmation** — RESEARCH did not lock this.
- Text fields set `imeAction` appropriately (Done/Next), `singleLine` where applicable, and dark-theme-friendly cursor/handle colors (`primary`).

### 10. Primitive — Severity toast (PRIM-04)

- A Compose `Snackbar`-style transient overlay (NOT Android's legacy `Toast` — that can't be styled/themed and looks foreign), anchored **bottom-center** of the content area (clear of the nav-rail and the top-bar E-stop), stacking newest-on-top with a small gap, max ~3 visible then collapse.
- **Four severities — color + icon + text (never color alone):**
  | Severity | Container | Icon | Default duration |
  |----------|-----------|------|------------------|
  | Info | `surfaceVariant` `#1C2127`, `onSurfaceVariant` text | `Icons.Outlined.Info` | 3s |
  | Success | `success` `#5BD98A` accent bar/icon, `onSurface` text | `Icons.Filled.CheckCircle` | 3s |
  | Warning | `warning` `#FFB84D` accent bar/icon | `Icons.Filled.Warning` | 5s |
  | Error | `error` `#FF5A4D` accent bar/icon | `Icons.Filled.Error` | 6s (or until dismissed for action-failure) |
- Error toasts that imply a retry carry an inline action ("Retry"). Text is `bodyLarge` (16sp) — readable at distance. Toasts never obscure the E-stop.

## Elevation, Shape & Motion policy (fill-rate budget — Adreno 320)

- **Elevation: flat.** Use **color/tonal differentiation, not shadows**, to separate tiers (`#101418` canvas vs `#1C2127` chrome/cards). Set surfaces to elevation **0dp**; avoid M3 tonal-elevation overlays stacking. No blur, no translucent scrims beyond the single dialog scrim. Overdraw is the enemy on a fill-rate-bound GPU at 1920×1200 (ADR 0001).
- **Shape:** Material 3 default-ish rounded corners — cards/chips **12dp**, dialogs **16dp**, buttons **full/stadium** for the primary/destructive controls (clearly tappable). Keep it consistent; don't invent per-component radii.
- **Motion:** minimal. Standard Material state-layer ripples on press (cheap, important press feedback for greasy fingers). NO elaborate shared-element/cross-fade transitions between routes — a `when(route)` swap is fine. The temp graph repaints via `postInvalidateOnAnimation`, not animation APIs. Animated list-item insertion is explicitly forgone (ADR 0001 accepted "a smooth plain list beats a pretty stuttering one").

## Accessibility & Legibility (bench/wall viewing distance)

- **Contrast:** all text/icons ≥ **4.5:1** against their surface (palette designed to clear this); verify with a contrast check at build. Large 36sp readouts comfortably exceed it.
- **Minimum text 16sp** on screen (no 12/14sp) — distance legibility is a hard requirement, not a nicety.
- **State is NEVER color-alone:** every status (connection chip, Klippy chip, heater state, toast severity) pairs an **icon/glyph + text label** with its color. A colorblind operator (or one glancing from an angle in a dim shop) must still read state.
- **Touch targets:** standard ≥48dp, primary/destructive ≥72dp, E-stop ≥96dp — per the spacing exceptions table.
- **Content descriptions:** every icon-only control (status chips' icons, backspace key, show/hide-key toggle, E-stop) carries a `contentDescription` for TalkBack and to document intent.
- **No reliance on hover/tooltip** (touch device) — the "coming soon" rail items communicate disabled-ness visually (alpha + non-interactive), not via tooltip.
- **Landscape-locked:** all layouts designed for landscape only (PROJECT.md); the nav-rail-left + content-right pattern is the single orientation. Do not author portrait variants.
