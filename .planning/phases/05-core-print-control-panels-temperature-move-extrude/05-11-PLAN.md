<objective>
Close gap **G4 (MED)**: a long-running-but-successful gcode shows a false error.

Confirmed live on flox + a real Ender 5 Plus: tapping Z-home pops "command could not be sent", yet the
printer homes successfully and the printer console shows no error. `printer.gcode.script` only returns its
JSON-RPC reply when the gcode COMPLETES, so a Z-home (move-to-center + probe, >10s) trips the flat
`DEFAULT_TIMEOUT_MS = 10_000L` the dispatcher applies to EVERY command. The inner `JsonRpcClient.request()`
timeout converts that expiry into an `RpcConnectionException`, which the dispatcher reports as "command could
not be sent" — wrong twice over (it WAS sent, and it did NOT fail). The same trap hits every legitimately-slow
gcode the app issues: homing variants, filament load/unload macros, mesh/calibration.

Purpose: G4 is in the **shared command-dispatch primitive (PRIM-05, D-18)** that fronts EVERY Move / Temp /
Extrude / home / disable action, so a false-error on slow gcode degrades the whole phase's control surface.
Fix it without regressing G1 (printer rejections must still surface fast) or the genuine-connection-failure path.

Output: A per-command timeout (long for `gcode.script`, short default for instant calls), a typed
`ConnectionError.Timeout` reason that distinguishes a request-await timeout from a true transport failure, and
disambiguated dispatcher messaging — proven via TDD with a delayed-but-successful gcode fake (closing the
mock-vs-reality gap that let the original false-error ship).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dispatcher → host toast (DispatchEvent.Failure) | Only a redacted, human-readable message may cross; never the API key or a `?token=` URL. |
| transport reply timing → dispatcher | A reply may be slow (valid long gcode) or absent (true failure); the dispatcher must not conflate the two. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-05-11-01 | Information disclosure | RpcConnectionException catch (CommandDispatcher) | mitigate | Both branch messages are built from the non-secret `method`/`key` + a fixed string; `e.message` (which can carry a `?token=` URL on a send failure) is NEVER interpolated. Guarded by `failureMessageNeverEmbedsApiKeyOrToken`. |
| T-05-11-02 | Denial of service | per-command timeout in dispatch() | accept (bounded) | `GCODE_TIMEOUT_MS = 120_000L` is generous but FINITE; the key is still removed in `finally`, so even a truly-wedged gcode cannot permanently disable a control (T-04-02-DoS preserved). 120s ceiling justified against real Klipper homing/mesh/load-macro durations. |
| T-05-11-03 | Spoofing / false signal | dispatcher messaging | mitigate | A slow VALID gcode no longer masquerades as a transport failure (typed `ConnectionError.Timeout` → benign "still running"); a true failure is not masked as "still running" (NetworkUnavailable → "could not be sent"). |
| T-05-11-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan (pure Kotlin edits to existing files). |
