# Phase 18.2 Plan 03: jiib Launcher Icon Wiring Summary

Wired the jiib sail mark (from 18.2-01's `ic_jiib_foreground.xml`) into the full launcher-icon set
across all API levels and densities — the API-26+ adaptive icon (foreground + monochrome) and the
minSdk-23 pre-26 vector fallback — while retaining the navy `#141A24` background (D-01).

## What Was Built

- **v26 adaptive icons** (`mipmap-anydpi-v26/ic_launcher.xml` + `ic_launcher_round.xml`) — both
  `<foreground>` and `<monochrome>` now reference `@drawable/ic_jiib_foreground` (D-01 foreground
  swap, D-02 monochrome = the jiib mark for Material You themed-icon tinting on API 33+). The
  `<background android:drawable="@color/ic_launcher_background" />` is unchanged. Comments refreshed
  Benchy → jiib.
- **`ic_launcher_background.xml`** — value confirmed and held at `#141A24` (D-01 navy retained; the
  brand-background recolor is the DEFERRED idea, not touched). Comment refreshed Benchy → jiib.
- **Pre-26 fallback** (`mipmap-anydpi/ic_launcher.xml` + `ic_launcher_round.xml`) — kept the navy
  box `<path … fillColor="#141A24">` and replaced the Benchy `scaleX/Y=0.045` stroked group with
  the jiib `scaleX/Y=0.16` translate `(11.0, 22.4)` group + the six `#FFFFFFFF` filled paths
  reused verbatim from `ic_jiib_foreground.xml` (3 sail paths + 3 circles-as-two-arc pathData). The
  result is a flat navy box with the white jiib sail mark; no adaptive layering (minSdk 23 predates
  adaptive icons). Color is fixed white — the launcher mark is outside the theme token system (D-03).

## Verification

- **Task 1 grep gate:** both v26 XMLs reference `@drawable/ic_jiib_foreground`, neither references
  `@drawable/ic_launcher_foreground`, both retain `@color/ic_launcher_background`, and

- **Task 2 grep gate:** both fallback XMLs carry `fillColor="#141A24"` (navy box) + `fillColor="#FFFFFFFF"`
  (white mark) + a `<group>`, and no `benchy` remnant (case-insensitive) → **OK**.

  → **BUILD SUCCESSFUL in 12s** (exit 0). `mergeDebugResources` + `processDebugResources` executed
  and accepted all four mipmap XMLs (aapt did not error).
- On-device launcher render (flox = API 30, static adaptive path — NOT the API-33 monochrome path)
