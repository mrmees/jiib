**Phase:** 18.2-jiib-rebrand

## Purpose

Close **Success Criterion 4**: prove that no **user-visible** "Dinghy Display" string remains
anywhere in the shipped app, and that every surviving occurrence is an **explicitly-documented
out-of-scope identity string** (package / protocol / source-comment), not a missed user-facing
brand surface.

The phase boundary (`18.2-CONTEXT.md`, locked by `ROADMAP.md`) is: swap the **user-facing**
brand on exactly four surfaces (launcher icon, app label, splash, about) — and nothing more. The
repo name, the Java/Kotlin package `works.mees.dinghy`, the `applicationId`, and every `Dinghy*`
class/symbol name stay UNCHANGED. This audit classifies every grep hit against that boundary.

## Method

Case-insensitive grep for `Dinghy Display` and `dinghy` across `app/src/main` (java + res +
manifest). Each occurrence is classified **FIXED** (with the plan that fixed it) or
**OUT-OF-SCOPE** (with the reason it is not a user-facing brand surface).

## ⚠ Conscious Retention Note — MoonrakerSession `clientName` / `clientUrl`

`MoonrakerSession.clientName = "Dinghy Display"` and
`clientUrl = "https://mees.works/dinghy-display"` are the **JSON-RPC connection IDENTITY** the app
sends in Moonraker's `server.connection.identify` call. They surface **only** in Moonraker's /
Mainsail's **server-side connection list** — they are NEVER rendered on jiib's own UI.

This is **protocol/package-tier identity**, which the phase CONTEXT explicitly places out of scope
(package + repo name stay). **This is a CONSCIOUS, DELIBERATE retention — NOT a missed surface**
(D-06-style explicit decision). Changing it is a separate concern (it would alter how the app
identifies itself to the Moonraker server, tied to the still-unchanged repo/package identity) and
is intentionally deferred. STRIDE register: `T-18.2-05-01` (information disclosure) → **accept**:
these are non-secret protocol identifiers, no PII/secret, no new attack surface.
