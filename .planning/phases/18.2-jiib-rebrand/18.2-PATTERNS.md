## Pattern Assignments

### `res/drawable/ic_jiib_foreground.xml` (asset, fixed-white launcher foreground)

**Analog:** `app/src/main/res/drawable/ic_launcher_foreground.xml` (the Benchy foreground — exact template)

**Structure to mirror** (lines 1-5, then the `<group>`/`<path>` body):
```xml
<!-- Adaptive-icon foreground: Benchy scaled+centered into the 108x108 safe zone. -->
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="108dp" android:height="108dp"
    android:viewportWidth="108" android:viewportHeight="108">
    <group android:scaleX="0.045" android:scaleY="0.045" android:translateX="18.0" android:translateY="33.75">
        <path android:pathData="M 1235 431.5 ..."
            android:strokeColor="#FFFFFFFF" android:strokeWidth="15.000000"
            android:strokeLineCap="round" android:strokeLineJoin="round" />
        ...
    </group>
</vector>
```

**What to copy / what changes:**
- Keep `viewportWidth/Height="108"` and `android:width/height="108dp"` (the adaptive-icon 108×108 canvas).
- Keep the `<group>` scale+translate-into-safe-zone idiom. The current Benchy uses a tiny `scaleX/Y=0.045`
  because the source artwork was 1200-unit space; recompute the scale/translate for `jiib_icon.svg`'s own
  viewBox so the sail mark lands centered in the inner ~72dp safe circle.
- **Color is FIXED WHITE (`#FFFFFFFF`), NOT a token** — the launcher mark is outside the theme system (D-03).
  The Benchy foreground is a *stroked* outline (`android:strokeColor="#FFFFFFFF"`); the jiib mark is a
  *filled* sail (per D-07 flatten-to-one-fill), so jiib paths use `android:fillColor="#FFFFFFFF"` instead of
  `strokeColor` (convert the SVG `<circle>` elements to path data per D-07/D-08).

### `res/drawable/jiib_wordmark.xml` and `jiib_lockup.xml` (asset, TINTABLE in-app marks)

**Analog:** `app/src/main/res/drawable/nozzle` — the precedent for a custom VectorDrawable that gets a
runtime token tint in Compose (see ExtrudeScreen excerpt below). Convert `img/jiib_name.svg` →
`jiib_wordmark.xml` and `img/jiib_name_icon_stack.svg` → `jiib_lockup.xml`.

**Conversion rules (D-07/D-08):**
- Flatten every path/`<circle>` to a **single `android:fillColor`** so a Compose `tint`/`colorFilter` recolors
  the whole drawable in one stroke. The source off-whites (`#F9F9F9`/`#F8F8F8`/`#F7F7F7`) collapse to one fill.
- The fill color baked into the XML is irrelevant for the tinted in-app render (it's overridden) — use
  `#FFFFFFFF` for clarity/preview sanity.
- Preserve the source SVG aspect ratio in `viewportWidth/Height` so the Compose-side sizing (below) keeps the
  lockup/wordmark un-stretched.

### How to render a tinted VectorDrawable in Compose (the load-bearing in-app pattern for splash + about)

**Canonical in-repo example — `ExtrudeScreen.kt` lines 235-240** (a custom `R.drawable.nozzle` vector tinted
with a token-derived color via `Icon(painter = painterResource(...), tint = ...)`):
```kotlin
Icon(
    painter = painterResource(R.drawable.nozzle),
    contentDescription = null,
    tint = tempColor,                       // <-- token-derived Color; use t.accent for the brand marks
    modifier = Modifier.size(fsSp(48f, t.fs).dp),
)
```

**Primitive that formalizes it — `designsystem/icons/DinghyIconView.kt` lines 63-68** (the `IconRef.Drawable`
branch — same `Icon(painterResource, tint)` shape, with `tint` defaulting to `LocalTokens.current.text`):
```kotlin
is IconRef.Drawable -> Icon(
    painter = painterResource(ref.resId),
    contentDescription = contentDescription,
    modifier = modifier.size(sizeDp),
    tint = tint,                            // default = LocalTokens.current.text (line 42)
)
```

**Apply to this phase:** render the splash lockup and about wordmark with
`Icon(painter = painterResource(R.drawable.jiib_lockup), contentDescription = ..., tint = t.accent, modifier = …)`.
- `Material3.Icon` applies `tint` as a `ColorFilter.tint` over the whole drawable — this is exactly why D-07
  requires flattening the SVG to one fill (a tint recolors uniformly).
- Imports needed (already present in ExtrudeScreen, NOT yet in Splash/About):
  `androidx.compose.material3.Icon`, `androidx.compose.ui.res.painterResource`, `androidx.compose.foundation.layout.size`,
  and `works.mees.dinghy.R`.
- **a11y:** give the brand `Icon` a real `contentDescription` via `stringResource` (e.g. `cd_jiib_logo = "jiib"`),
  OR `null` if treated as decorative beside adjacent text. Match the DinghyIconView contract.

## Shared Patterns

### Theme tokens (every in-app surface)
**Source:** `theme/compose/LocalTokens.kt` consumed as `val t = LocalTokens.current`
**Apply to:** SplashScreen (already line 69), AboutScreen (already line 70) — the in-app marks tint `t.accent`,
the about note uses `t.text3`. THEME-01: in-app brand color MUST be a token, never a literal (contrast the
launcher mark which is intentionally a fixed-white THEME-system exception, D-03).

### Font scale (any text the planner adds)
**Source:** `theme/fsSp.kt` — `fsSp(baseSp, t.fs).sp`
**Apply to:** the About jib note (`fsSp(15f, t.fs).sp`, matching the description). NEVER a raw `.sp` literal.
See memory [[dinghy-font-sizes-too-small]]: 15sp metadata floor, 20-22sp titles.

### Ratio-only sizing (LAYOUT.md)
**Source:** LAYOUT.md non-negotiable — no hardcoded px.
**Apply to:** the splash lockup and about wordmark `Modifier.size(...)` / `fillMaxWidth(fraction)`. Size by
ratio or an `fsSp`-derived dimension, not a magic dp constant.

### Accent↔bg contrast floor (D-06 watch-item — DO NOT silently drop)
**Source:** no existing contrast-guard helper found in repo (see No Analog Found).
**Apply to:** the `t.accent` tint on splash + about marks. Planner must EITHER implement a min-contrast
fallback (e.g. `if (contrast(t.accent, t.bg) < floor) t.text else t.accent`) OR document it as a deferred
known-limitation. CONTEXT D-06 + the discretion bullet make this a required decision, not optional.

### Preview-first convention (PREVIEW_AND_TOKENS.md)
**Source:** `app/src/main/java/works/mees/dinghy/preview/` (e.g. `DinghyPreviews.kt`, `PreviewTheming.kt`).
**Apply to:** any changed screen ships/updates a `@Preview` matrix (6 theme combos + `fs=L`, no live Moonraker).
SplashScreen and AboutScreen are changed surfaces → their previews should render the new marks across themes,
which is ALSO how the D-06 accent-contrast risk gets eyeballed before device.
