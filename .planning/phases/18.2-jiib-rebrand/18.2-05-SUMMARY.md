## What Was Built

### Task 1 — Debug GalleryScreen de-brand + the SC-4 audit (`252e749`)
`gallery/GalleryScreen.kt`: the debug component-gallery `SectionHeader("Dinghy Display — Component
Gallery (debug)")` literal is changed to `"jiib — Component Gallery (debug)"`. It is a debug-only
surface, but fixing it keeps the SC-4 grep clean and the audit honest (zero `"Dinghy Display"`
remains in GalleryScreen.kt).

`.planning/phases/18.2-jiib-rebrand/18.2-DEBRAND-AUDIT.md` (created): an exhaustive table of EVERY
`Dinghy Display` and `dinghy` occurrence across `app/src/main` (java + res + manifest), each
classified **FIXED** (with the plan that fixed it) or **OUT-OF-SCOPE** (with the reason it is not a
user-facing brand surface). Dispositions:
- **FIXED:** SplashScreen + AboutScreen (18.2-04, user-visible brand lockup/wordmark); AndroidManifest
  `android:label` ×2 + MoonrakerService FGS notification title (18.2-02); GalleryScreen debug header
  (this plan).
- **OUT-OF-SCOPE — CONSCIOUS RETENTION:** `MoonrakerSession.clientName = "Dinghy Display"` and
  `clientUrl = "https://mees.works/dinghy-display"` — the JSON-RPC `server.connection.identify`
  identity that surfaces ONLY in Moonraker's / Mainsail's server-side connection list, never on jiib's
  own UI. This is protocol/package-tier identity, which the phase CONTEXT explicitly leaves out of
  scope (package + repo name stay). Documented as a deliberate decision (D-06-style), not a silent
  miss; STRIDE `T-18.2-05-01` → accept (non-secret protocol identifier, no PII/secret, no new surface).
- **OUT-OF-SCOPE — comments/symbols:** `ScreenScaffold.kt` KDoc comment; locked `Dinghy*`
  package / class / theme symbols + `applicationId` (CONTEXT hard boundary).

The audit concludes: **zero USER-VISIBLE "Dinghy Display" strings remain** — every survivor is the
consciously-retained protocol identity, a non-shipping comment, or a locked package/symbol (SC-4).
