# Phase 18.2 Plan 02: jiib Label & Strings Summary

Swapped the user-facing app label and persistent foreground-service notification title from
"Dinghy Display" to "jiib" via a single `app_name` string resource, and seeded the About-screen
copy strings (`about_tagline`, `about_jib_note`, `cd_jiib_logo`) that the in-app brand surfaces
(18.2-04) will consume.

## What Was Built

### Task 1 — Brand/copy string resources (`5b0f6c2`)
Added a clearly-commented `about / brand` block to `strings.xml`:
- `app_name` → `jiib` (D-09, all-lowercase) — the single source of truth consumed by both the
  manifest label and the notification title.
- `about_tagline` → "A direct Moonraker touchscreen for Klipper." (D-10, now a resource).
- `about_jib_note` → the D-11 locked copy, **CDATA-wrapped** so the embedded double-quote and the
  `jib's` apostrophe need no per-character escaping (an unescaped `'` is an AAPT2 build error, not
  just an XML concern). The ellipsis is the literal `…` character, not `...`.
- `cd_jiib_logo` → "jiib" (contentDescription for the brand Icon on splash/about, used by 18.2-04).

XML well-formedness confirmed (`xml.etree`), and the resource merge passed AAPT2 in the debug build
with no malformed-string error.

### Task 2 — Label routing + notification rebrand (`8187f9a`)
- `AndroidManifest.xml`: both `android:label="Dinghy Display"` occurrences (`<application>` + the
  `.MainActivity` `<activity>`) → `android:label="@string/app_name"`. `android:icon`, `roundIcon`,
  `theme`, `name`, package, and `applicationId` are all unchanged (icon swap is 18.2-03's job).
- `MoonrakerService.kt`: the hardcoded `.setContentTitle("Dinghy Display")` →
  `.setContentTitle(getString(R.string.app_name))`, with a new `import works.mees.dinghy.R`. The
  `setContentText(text)` connection/status line (the only dynamic field, never the API key) is
  untouched.

Result: launcher/recents label and the FGS notification both read "jiib" via the single resource;
zero "Dinghy Display" literal remains in either file.
