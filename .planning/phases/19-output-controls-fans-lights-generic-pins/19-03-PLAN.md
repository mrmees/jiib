<objective>
Add the single-source clamp authority and command builders for every whitelisted output type to
`PrinterCommands` (built from the BARE section name — HIGH-1), register those builders as typed
`CommandSpec`s in `CommandRegistry.all` so detail pages dispatch through the catalog like Fine-Tune
(HIGH-2), and add the one genuinely-new pure helper (`hsvToRgb`) the LED page needs. Turn the
Wave-0 `PrinterCommandsOutputsTest` RED scaffolds green with live-verified gcode strings, and extend
the existing `CommandRegistryGcodeTest` drift guard to cover the new output specs.

Purpose: Phase-17's hardest bug (17-07) was an unclamped optimistic target wedging the busy lock —
the lesson is single-source clamp authority in `PrinterCommands` so the markPending target and the
dispatched command share one clamp output. All Phase-19 values (fan %, servo °, pin/PWM, heater °C,
LED channels) clamp here, before format. The UI shows 0–100% / degrees; the wire takes 0–1 / degrees.
Two correctness gates from the cross-AI review: (1) Klipper commands take the BARE section name
(`FAN=FILTER_fan`), but the live object/state key is the full name (`fan_generic FILTER_fan`) — the
builders MUST be fed the bare name; (2) the established architecture routes every gcode through a
registered `CommandSpec` (the analog `ExtrusionScreen` dispatches `CommandRegistry.setFan` /
`flowFactor` / `setPressureAdvance`, NOT raw strings) — output commands MUST be registered the same way.
Output: clamp consts + bare-name builders + typed registry specs + `hsvToRgb`, all host-tested against
the live-verified strings, with registry drift coverage.
</objective>
