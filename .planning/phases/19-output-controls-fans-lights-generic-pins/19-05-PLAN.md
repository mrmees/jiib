Build the Outputs list surface: the `OutputsHolder` (descriptors + display-scaled live values + per-detail
busy state, with per-family markPending/reached() and a clearly-typed row VM) and the `OutputsScreen` flat
alpha list (icon + prettyName + live value, drawer-suppressed, Back-only gutter), plus its preview matrix.
Turn the Wave-0 `OutputsHolderTest` scaffolds green.

Purpose: SC-1 (see every output), SC-3 (absent value hides only the value, row stays tappable). The list
mirrors `CalibrationHubScreen` (a hub of tappable rows → detail pages) but is a flat `LazyColumn` of rows.
Display scaling (0..1 → %) lives in the holder, not the reducer (FineTune precedent). Two review gates close
here: (1) the per-family `reached()` semantics — fan speed / pin value / heater target / LED color / pwm
value CAN be confirmed from live status, but servo angle CANNOT (servo reports PWM `value`, not angle), so
servo is timeout-only / skip-confirm; (2) the row VM names distinguish `displayValue` / `swatchColor` /
`isSettable` / `busy` so the screen and detail consume unambiguous fields. PREVIEW_AND_TOKENS is mandatory
day-one: a @Preview matrix + stringResource strings + DinghyIcon tokens from the start.
Output: holder + list screen + previews, host-tested.
</objective>
