<objective>
GAP-B (MAJOR, functional): the LED page ignores channel capability — a white/brightness-only LED
(the owner's E5 `led chamber_light`, which has only `white_pin`) is shown the RGB hue wheel and the
page dispatches `SET_LED ... WHITE=0`, so on white-only hardware the RGB write is a no-op and there
is no way to drive the white channel. Capture per-LED channel capability from `configfile.settings`
and branch the LED page: RGB-capable → hue wheel + brightness (the GAP-A-fixed layout from 19-09);
white/brightness-only → a brightness slider with step adjustment ONLY (no hue wheel), dispatching the
WHITE channel.

Purpose: SC-2 (set LEDs via keyboard-free controls confirmed by state flip) and SC-3 (no control
sends a command the printer can't accept) — make LED control actually functional on a white-only LED.

Output: `ledHasRgb`/`ledHasWhite` on `OutputDescriptor`, gate derivation from settings, a
capability-branched `OutputLedContent`, white-only brightness dispatch via the WHITE channel, seeded
from the live white component, with new gate/command tests off the real E5 fixtures and updated previews.
</objective>
