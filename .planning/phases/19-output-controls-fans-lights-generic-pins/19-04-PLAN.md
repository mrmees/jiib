<objective>
Build the discovery + live-state spine: a pure `parseOutputs` gate (configfile.settings ∩ whitelist ∩
objects.list, case-recovered, prettified, alpha-sorted), the `OutputDescriptor` model (full `objectKey`
for state + bare `commandName` for G-code — HIGH-1), output live objects added to the subscribe set in
`deriveSubscribeSet` (derived from objects.list, BEFORE the configfile read), a 5th consumer on the
EXISTING one-shot configfile query that CLEARS descriptors on failure/reconnect, central-subscribe
reduction of live output values into a per-objectKey map, and the `outputsPresent` flow that gates the
drawer tile (D-10). Turn the Wave-0 `OutputsGateTest` scaffolds green against the real fixtures.

Purpose: SC-1 ("see every controllable output, and nothing it doesn't") and SC-3 ("absent/read-only
degrade gracefully") are both data-layer truths. The discovery algorithm is settled (research):
settings gives metadata (pwm bool always present, servo angle range) but LOWERCASES names, so commands
must use the case-preserved name from objects.list — the `hasMacroIgnoreCase` lesson. No second
configfile query (Pitfall 3). Two correctness gates from the cross-AI review: (1) the descriptor must
expose BOTH the full `objectKey` (= state-map/busy key) and the bare `commandName` (= what G-code takes)
so HIGH-1 holds downstream; (2) the subscribe set is built in `deriveSubscribeSet` from `objects.list`
which runs BEFORE the configfile read — output live objects must be added THERE, not in ad-hoc session
code; and descriptors must be CLEARED on configfile read-failure / reconnect so a printer switch never
leaves stale hardware controls visible.
Output: the outputs package data layer + deriveSubscribeSet wiring + reducer + the D-10 gate flow,
host-tested on live fixtures.
</objective>
